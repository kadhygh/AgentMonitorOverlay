# 整体待办与调度（阶段 7）

调度 agent 的目标：看整体待办和各个工程是否空闲，**提出**"开哪个会话"，由人批准后 Studio 才开工。依据：愿景文档第 9 节、`design/interaction-notes.md` 画布一节、ROADMAP 阶段 7。

## 工程空闲

一个工作区**忙碌**，当且仅当它里面有未归档的会话满足以下任意一条：

- 运行中；
- 待批准、待审阅（在等人）；
- 在终端里（"终端已接入"或"已交给终端"）：人可能正在终端里操作，Studio 这边看起来是空闲的。

否则就是**空闲**。代码：`packages/protocol/src/scheduler.ts`。

画布上绑定了工作区的分组显示"空闲"或"忙碌（N 个会话）"。跨工作区任务的会话按各自所在的工作区计算。

以后可以按习惯再调，比如"最近 10 分钟有过回复也算忙"。

## 待办转任务

- 人在侧栏点"转为任务"；
- 任务建在待办"适合的工作区"里。待办没指定工作区时，让人选一个；
- 任务放进绑定了这个工作区的分组。有多个这样的分组时放第一个，没有就放未分组；
- 任务带一个空会话，模型由人选，不发第一句话，所以不会调用模型；
- 待办记下 `taskId`，标为完成，侧栏显示"已转为任务"，点一下打开任务。

## 调度提案

调度 agent 只能提出提案，不能自己建任务或会话。提案包含：

| 字段 | 说明 |
|---|---|
| 待办 | 要做的那条整体待办 |
| 工作区 | 在哪个工程里做（默认是待办的工作区） |
| 模型 | 用哪个模型配置 |
| 提示词 | 新会话的第一句话，可以基于某个启动预设 |
| 理由 | 为什么现在做这条、为什么选这个工程（一两句话） |

生命周期：

```
待处理 ──批准──▶ 已批准（Studio：待办转任务 + 用提示词开第一个会话）
   │
   ├──拒绝──▶ 已拒绝
   └──待办被删除或完成──▶ 已过期
```

- 批准前，人可以修改提示词和模型，和阶段 6 的预设草稿一样；
- 同一条待办同时只能有一个待处理的提案，再提会被拒绝；
- 批准时待办已经不在或已处理，提案变为已过期；
- 每轮最多 3 条；
- 待处理的提案计入顶栏的"需要你"。Focus 里只显示条数和"在工作台处理"：提案要看提示词，Focus 不适合。

## 调度 agent

- 是一个普通的 Studio 会话，放在固定的跨工作区任务"调度"里，人能看到它的全过程；
- "让调度看一次"会在这个任务里开一个新会话。第一句话由 Studio 生成，内容包括：
  - 当前未完成的待办；
  - 各工作区是否空闲；
  - 可用的模型；
  - 各工作区扩展包里的启动预设；
  - 规则：只提案、每轮最多 3 条、忙碌的工程不提；
- 它能用全部只读工具，加上 `schedule_propose`。`schedule_propose` 只对"调度"任务里的会话开放；
- 不能用写自身以外的写入工具（画布写入照常需要审批），也不能派发。

## 和"派发"的区别

"派发"（S5-10，未开放）指 agent 自己建会话，或者把任务直接投进别的会话。调度提案不建任何东西，必须由人批准，Studio 才会建任务和会话。所以开放调度提案，不等于开放派发。

## 定时运行（等你决定，S7-09）

在你回复之前，只能手动点"让调度看一次"，代码里没有定时器。回复后按你定的频率、时间段和模型实现。
