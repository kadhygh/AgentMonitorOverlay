# 组织结构 v2：项目、任务、专题、会话（2026-10-13 用户已确认）

阶段 10 的第一步：先把对象之间的关系定死，再改界面。这份文件只写结构和约束，不写界面细节。
用户确认：这一层叫"专题"（每个专题用一张画布展示）；取消跨工作区任务；归档专题时任务一起归档。

## 1. 四种对象

| 对象 | 是什么 | 用户看到的名字 |
|---|---|---|
| 项目 Workspace | 本机的一个工程文件夹。同一个 git 的多个副本（例如 3 个 mining）是 3 个项目 | 项目 |
| 任务 Task | 一件要推进的事，带一棵会话树，在看板上按列移动 | 任务 |
| 专题 Topic | 任务上面的一层：把若干任务（可以跨项目）放在一起统筹，有自己的会话；界面上用一张画布展示 | 专题 |
| 会话 Session | 一次与 agent 的对话（Codex 线程或 Claude 会话），包括 fork 和子 agent | 会话 |

"公共"不是一种对象，而是一个**隐藏的内置项目**：没选项目的任务和会话都在它的文件夹里跑，界面上不出现"公共"这个名字。

```
专题（0..n，各有一张画布）
 ├─ 专题会话（统筹用，0..n，各自的会话树）
 └─ 任务（0..n）
      └─ 会话树（主会话 / fork / 子 agent）

不在任何专题里的任务照样存在，看板上正常显示。
```

## 2. 约束（以后加功能都不能破坏这些）

**会话**

- S1 每个会话**恰好属于一个归属者**：一个任务，或一个专题。不能两者都属于，也不能都不属于。
- S2 fork 和子 agent 继承父会话的归属者。父子关系只在同一归属者内部存在；跨归属者的关系只能是"留言 / 交接"这类链接，不是父子。
- S3 会话创建后归属者不变（以后要做"移交会话"时再单独设计，作为显式操作）。
- S4 会话的工作目录：任务会话 = 任务的项目；专题会话 = 专题内任一项目，或公共（创建时选，默认公共）。

**任务**

- T1 每个任务**恰好属于一个项目**。没选项目就是公共。会话开始前可以改项目，之后不能改。
- T2 每个任务**最多在一个专题里**。移出专题不影响任务本身。
- T3 看板列（待办 / 进行中 / 审阅 / 完成）只属于任务，只由人移动。专题没有列。
- T4 取消现在的"跨工作区任务"：跨项目的事一律用专题表达（一个专题 + 每个项目各一个任务，统筹放在专题会话里）。

**专题**

- C1 专题的项目集合 = 它的任务所在项目 ∪ 手动加入的项目。任务加入专题时，任务的项目自动并入。
- C2 专题里的分组、便签、依赖线、位置都属于这个专题的画布；依赖线只能连同一专题内的任务。
- C3 归档专题：它自己的会话和里面的任务**一起归档**。归档前提示会波及哪些任务；还要继续的任务，先用"转移"移到别的专题或移出专题。
- C4 转移：任务可以在专题之间转移，或移出专题；画布上的位置、所在分组、跟原专题任务之间的依赖线随之清除。

**公共**

- P1 公共是一个内置项目，默认文件夹在数据目录下 `common/`，设置里可以改路径。界面不把它列进项目列表。
- P2 公共任务可以放进专题（例如一个纯讨论的任务）。

## 3. 权限按归属者划分（MCP）

| 调用者 | 读 | 写 |
|---|---|---|
| 任务会话 | 自己的任务、自己所在专题的大纲 | 自己任务的进度 / 交接 / 清单；给别的会话或任务留言 |
| 专题会话 | 专题内所有任务及其会话树摘要、专题大纲 | 专题布局（建组、连线、归组，仍需人批准）；给专题内任务或会话留言 |

- 留言的收件人可以是：会话、任务、专题。
- 消息仍然不会自动进入对方的对话，由人转发（用户 2026-10-13 确认：先跑通，自动以后再说）。
- 以后的"主控会话自动指挥子会话"天然放在专题会话上，权限边界就是"本专题内"。

## 4. 数据模型改动

| 表 / 类型 | 改动 |
|---|---|
| `workspaces` | 加 `builtin`（`common` 或空），公共项目用它标记 |
| `topics`（新） | `id, title, workspace_ids, created_at, updated_at, archived_at`；画布布局（分组、节点、连线、版本号）从全局一份改为每个专题一份（`canvas_docs` 加 `topic_id`） |
| `tasks` | 去掉 `scope_kind`；`workspace_id` 必填（公共项目的 id）；加 `topic_id`（可空）；加 `archived_at`（现在只有会话能归档，任务还不能） |
| `sessions` | `task_id` 改为 `owner_kind`（`task` / `topic`）+ `owner_id`；`workspace_id` 保留 |
| `mail` | 收件人加 `topic` |
| API | `/api/topics` 增删改查、归档、任务转移；`/api/topics/:id/canvas` 取代 `/api/canvas` |

## 5. 迁移现有数据

- 现有全局画布 → 一个名为"专题 1"的专题，原来在画布上的任务的 `topic_id` 指向它。
- 现有跨工作区任务：会话都在同一个项目里 → 变成该项目的任务；会话分布在多个项目 → 新建一个同名专题，这些会话变成专题会话，任务本身删除。
- 设置里的公共文件夹 → 标记为内置公共项目；没设过就在数据目录下建 `common/`。
- 开发数据目前只有 1 个项目、2 个任务，迁移风险很小；仍然在迁移前备份 `studio.db`。
