# AMO Studio 改动说明

改动先写进「## 下一版」；发布时（`npm run release -- studio` 或 `auto`）它会改成 `## 版本号（日期）`，这一节就是平台上显示的改动说明。

## 下一版

- 会话用「等你决定」问你（卡片上写「非阻断 · 留言返回」的那种，GPT、DeepSeek 常用），你回答得晚、它这一轮已经结束了，回答不再石沉大海：以前回答只放进留言箱，没人去读，会话一点反应都没有。现在这一轮还在跑时，回答照旧作为留言，模型可以自己去读；这一轮已经结束，或者结束时它还没读，回答会作为一条消息发进会话，写明是对哪个问题的回答，模型接着处理。
- Codex 自己停掉一轮（比如在终端里停的）时，那一轮里还没回答的问题记成「提问已取消」，不再错写成「已在别处回答」。

## 0.9.42（2026-11-05）

- 长对话里发消息，那一刻对话不再一下子变短一大截：刚移出「最后三轮」的那一轮以前会按 300px 占位，现在按它的真实高度。更早的轮次也按真实高度占位，跳到书签、跳到回复时一开始就接近正确位置。
- 发消息后对话区如果还是空白（问题 #17 又出现过一次），Studio 会把屏幕上那一轮当场画出来，并在日志 `logs/resize-trace.log` 里记一行 `#main blank after send`（滚动位置、哪几轮在视野里），方便查。

## 0.9.41（2026-11-05）

- 新建任务时选「放进待办」，写的第一句话不再丢：以前只留下截短的标题，正文没了。现在它跟着任务存着：看板卡片上写「还没有会话 · 第一句话已写好」，打开任务页能看到全文；新建第一个会话时它自动放进输入框，看过再发。主控拆任务、先放进待办的任务也一样。
- Studio 退出时把每一步（窗口全关、will-quit、进程退出）记进日志 `logs/resize-trace.log`，马上写盘；退出卡住 10 秒就自己结束进程。平台重启 Studio 时出现过旧窗口进程关不掉的情况，下次能看出卡在哪一步。

## 0.9.40（2026-11-05）

- 新建任务页右上角加了「接续已有会话…」：把在终端或 Claude 桌面版里开的 Claude 会话接到 Studio，作为一个新任务接着做。弹窗按项目列出 Studio 里还没有的会话，右边显示最后聊到哪；选好后任务名、项目自动填上，模型用 Claude 订阅，第一句话可以不写。接过来的是一份副本，原会话不动，那边还开着也没关系；之前的对话会显示在会话里，模型也记得。原会话压缩过上下文的，只接最后一次压缩之后的部分。原会话的目录不在任何项目里时，可以一键把它添加为项目。只支持 Claude（本机 Claude Code 登录），Codex 以后再做。

## 0.9.39（2026-11-05）

- 「设置 → 测试功能」新加「开发界面目录」：开发 Studio 界面时，填一个构建好的界面目录（比如某个 worktree 的 `studio\packages\ui\dist`），窗口就从那里载入界面；那边重新构建后点「重新载入」就能看到，不用发版，也不用重启，后台和正在跑的会话不受影响。开着时窗口顶上有一条提示，写着界面来自哪个目录，可以「重新载入」或「恢复安装版」。重启 Studio 后自动回到安装版的界面；那个目录里的界面坏到窗口打不开时，右键托盘图标点「恢复安装版界面」。
- 「测试功能」里全景的说明改成现在的入口：左边栏「全部任务」下面。

## 0.9.38（2026-11-05）

- 消息发出去 3 秒还没回应时，输入框下方显示「正在发送…」；30 秒还没回应，文字会放回输入框，并提示先看一眼对话里有没有这条再发。以前输入框一按回车就清空，请求卡住时什么都看不出来，消息就这么没了。
- 发消息失败或处理超过 5 秒时，Host 会在 host.log 里记一行（哪个会话、多久、什么原因）。会话停止没停下、处理模型消息出错这类提示以前写不进 host.log，现在也会记下来。
- 文件大小统一成一位小数，最大到 GB（如「12.5 KB」「1.5 MB」「2.0 GB」）：附件、找文件、文件预览、远程打开文件的进度都一样。以前 KB 取整、10 MB 以上也取整，大文件一律按 MB 显示。
- 内部整理：界面和 Host 通信的几份请求代码合成一份；Host 回的不是正常结果时（比如中间被代理拦了），会显示状态码，而不是一句看不懂的 JSON 解析错误。界面记在本机的偏好（主题、栏宽、折叠、草稿等）读写也合成一份，存的值和以前一样，更新后照旧保留。

## 0.9.37（2026-11-05）

- 测试功能「全景」换了新画法：每个专题是地图上的一块区域，可以在「地形岛」和「地铁」两种样子之间切换（页面右上角，记在这台电脑上）；每个任务是区域里的一条路，分支会话是岔出去的支路，同一项目的任务排在一起。专题名、任务名贴在地面上，放大也清楚；打开时先放一段开场动画，区域算好后浮现；滚轮缩放更平滑。
- 全景的入口从专题的「看板 / 画布」旁挪到左边栏「全部任务」附近，一次画出所有专题（加上没归专题的任务），左边栏保留。要先在「设置 → 测试功能」里打开「全景」才会出现。

## 0.9.36（2026-11-04）

- 「工作步骤展示」选「详细」时，做完的一轮不再收成「已完成，用时 …」一行，中间的回复、思考和各段工作的标题照样摊开；点那一行还能收起。「标准」照旧收起，「完全展开」照旧连每段工作都展开。
- 中转回复、值守接着做、主控传话、转发的留言、session_send 发来的消息、子会话的回报，现在先出现在对话里，下面写「等这一轮结束后送进去」，等会话这一轮做完再自动送进去，不再插进它正在做的这一轮。Studio 重启了也会接着送。送不进去时（比如渠道的 Key 没了）这条会写「没送到」并说明原因，点「重新发送」再试；以前这种情况消息会悄悄丢掉，中转回复尤其如此。想马上让它读到，点这条下面的「立即发送」。
- DeepSeek（DSH）会话生成中发的消息，和 Claude、Codex 一样显示「等待送达」，可以点「立即发送」或按 Ctrl+Enter 让它马上读到；点停止后等着的消息接着发出。这一轮出错、DSH 进程退出或 Studio 重启时，等着的消息写「没送到」，可以「重新发送」；以前这些情况下排队的消息直接没了。
- 点了停止 15 秒后 DSH 或 Codex 还没停下，Studio 不再一直等：DSH 会关掉它的进程，Codex 会把这一轮记成已停止，会话不会一直显示「正在工作」。Claude 以前就是这样。
- 你点了停止的会话，别的会话、中转、值守再发来的消息先不送进去，会话里有一行说明；等你发下一条消息时一起送，或者点它旁边的「立即发送」。以前会话一空下来就马上送进去，刚停下的会话又自己跑起来了。
- 配合 AMO 平台更快地知道 Studio 开着还是关了：Studio 记下自己的进程号时也记下程序路径。
- 「工作步骤展示」选「详细」或「完全展开」时，模型的思考默认整段展开，不用再一条条点开；点一下标题还能收起。模型有时会把对你中途插话的回应写在思考里，以前折成一行，很容易漏看。「简洁」「标准」照旧折叠。
- 工作过程里换了配色，和 Claude Code 命令行一样分得开：思考是灰色斜体，命令和搜索内容是等宽的青绿色。
- Host 关闭的那一刻 Codex 还有消息送到时，Host 不再因为记不下这条消息出一个未捕获的错误（只写进 host.log）。
- 右键菜单和「⋯」菜单关闭的方式统一了：按 Esc、点菜单外面、滚动鼠标滚轮、切到别的窗口都会关上（以前有的菜单滚轮关不掉，有的切窗口还开着）。在窗口右边或下边打开的菜单会往左、往上展开，不会超出窗口。菜单开着时按 Esc 只关菜单，不会连下面的对话框一起关掉。
- 对话框打开时焦点在对话框里，按 Esc 或点对话框外面只关最上面那一个；点过的按钮消失以后（焦点不在任何地方）按 Esc 也能关；关上后焦点回到打开前的位置。
- 在「设置 → 数据管理」里彻底删除会话、任务或项目时，Studio 为它们记的零碎设置（角色卡、批注编号、汇报到哪一轮、MCP 身份等）也一起删掉；以前这些会一直留在数据库里。
- DeepSeek（DSH）进程的日志不再无限增长：单个超过 2 MB 时，下次启动换一个新文件（只留上一份）；一个月没写过的日志和空日志，Studio 启动后自动删掉。DSH 自己的会话记录不动。

## 0.9.35（2026-11-04）

- Studio 里的 Claude 会话现在会加载你本机 Claude Code 配置好的 MCP（`~/.claude.json` 里的，`claude mcp add` 加的就在这里，还有项目里的 `.mcp.json`），和在终端里开 Claude Code 一样。以前 Studio 启动 Claude 时只给它自带的 amo，你配好的 Figma 之类在 Studio 里用不上。中转的 `amo-relay` 和 Studio 自带的中转功能重复，默认不启用。
- 设置里新加一页「MCP」：可以关掉「加载本机已配置的 MCP」；可以粘贴 MCP 文档里给的 JSON，在 Studio 里加 MCP（Claude、DeepSeek、Codex 都能用，密钥存在 Windows 凭据管理器里，AI 看不到）；每个 MCP 默认开不开也在这里设。
- 「编辑项目」里可以给这个项目单独开关某个 MCP，项目自己的 `.mcp.json` 里 Claude Code 还没批准过的，也在这里打开。
- 会话输入框下面多了「MCP」按钮，可以只给这个会话开关某个 MCP，同一任务里新开的会话会沿用。正在运行的会话也能改：Claude 会话里 Studio 加的 MCP 下一次调用工具就能用，本机配置的那几个和 DeepSeek 会话从下一条消息起生效（回复进行中的，等这一轮结束）。Codex 只用 Studio 里加的、全局开着的，等 Codex 下次启动（比如重启 Studio）才生效。
- 在会话里跟 AI 说「帮我接入 xxx MCP」，它会把配置发给你批准，批准后加进 Studio，并在它自己的会话里直接用上（DeepSeek 会话做不了这一步，请在设置里加）。

## 0.9.34（2026-11-04）

- 会话生成中发出新消息时，刚才正在看的那条回复不会再变成空白。以前为了长对话不卡，只有最后两块内容一直画出来，更早的离开屏幕就先不画；但生成中底部那行「正在工作」也被算进了这两块，所以一发消息，屏幕上正看着的回复就被当成「更早的」，偶尔会一直空白到新回复出来。现在最后三轮对话总是画出来，不算「正在工作」那行。（问题 #17）

## 0.9.33（2026-11-04）

- Focus 的「完成待审核」「出错」只看会话的回复什么时候结束。以前会话的任何改动都算数：给已经结束的会话改名、换模型或权限、取消自动继续、交给终端或接回，它都会重新出现在 Focus 里，机器人也跟着提醒。这一版会升级数据库（第 24 版），升级后旧版本的 Studio 打不开同一份数据。
- 别的电脑把任务授权给这台电脑后，这台电脑的 Focus 不会再把任务里授权前就已经结束的会话全部列成「完成待审核」。授权之后才结束的回复照常提醒。
- 看过的会话累计超过 500 个以后，最早看过的那批不会再重新出现在 Focus 里变成「完成待审核」。

## 0.9.32（2026-11-04）

- 恢复一个已归档的任务（或专题、项目、单个会话）后，Focus 不会再把它里面早已结束的会话一条条列成「完成待审核」。以前恢复时这些会话的更新时间被改成了恢复的时刻，Focus 就当成刚回复完、还没看过，一下子刷出一屏。现在恢复算作你已经看过；之后再有新回复照常提醒。
- 点了「停止」或「立即发送」（包括生成中按 Ctrl+Enter）之后，界面会马上显示正在停：停止按钮变灰，输入框下面写「正在停止…」或「正在打断，停下后马上发出…」；等着的那条消息下面写「正在打断当前这一步，停下后马上发出…」，原来的「立即发送」按钮收起来。模型要先收住手上的命令或回复，可能要几秒；以前这段时间界面上什么都不变，消息还写着「等待送达」，看起来像没发出去。
- Claude 会话生成中按 Ctrl+Enter（立即发送），如果它正在跑一个命令，现在会马上打断这个命令、读你的消息。以前只要命令已经跑了一两秒，就要等它自己跑完才会发出（一个 40 秒的命令要等 30 多秒）；点消息下面的「立即发送」按钮和点「停止」一直是马上停的，现在 Ctrl+Enter 和那个按钮走同一条路。（问题 #16）
- DSH 会话开着目标（goal）时，你那一轮结束后 DSH 会自己接着做下一轮。以前这些自己接着做的内容不算任何一轮，都接在你那一轮后面，你那一轮的最后回复就被折进了「已完成」里；会话还显示「空闲」，没有停止按钮，Focus 也看不到它在干活；接着做超过 20 分钟，Studio 还会把 DSH 关掉。现在 DSH 自己接着做的每一轮都单独算一轮，每轮的最后回复都留在外面；做的时候会话显示「运行中」，可以点停止；最后一轮回复后 1 分钟没有新动静就算做完。以前已经记下来的会话打开后也会这样分好。（问题 #13）
- Claude 在后台跑的子智能体做完后，交回的报告现在显示成它的最后回复，不再折在「已完成」里；报告很长也完整保留。以前报告记成了一条工具调用，只留前 8000 个字，还跟过程一起折了起来。以前记下来的会话也会显示出来，只是超出 8000 字的部分已经没有了，末尾会注明。（问题 #13）

## 0.9.31（2026-11-03）

- 设置 → 模型 → Claude 和 GPT 的页面上会显示「请求地址」：Studio 拉起的会话实际把请求发到哪里。Claude 读本机 Claude Code 的 `settings.json` 里的 `env.ANTHROPIC_BASE_URL`，GPT 读本机 Codex 的 `config.toml` 里的 `model_provider` 和对应的 `base_url`。用 ccswitch 这类工具切换过的话，这里能看出来，还会写明是从哪个文件的哪一项读出来的；没有另设时显示官方默认地址。配置里写了模型的，也会一起列出（会话里另选了模型的，以选的为准）。改过配置后点「重新读取」。只显示用户级的设置；某个项目在自己的 `.claude/settings.json` 里另设了地址的，那个项目里以项目的为准。
- 在设置里隐藏了某个模型，新建任务、新会话、待办转任务这几处如果正选着它，会马上换成默认模型。以前要重新打开页面或重启 Studio 才会换。
- 会话顶栏多了「追踪」按钮：点一下就把这个任务置顶在 Focus 最上面，和在 Focus 里点置顶一样；置顶着的时候按钮变成「追踪中」（带底色），再点一下取消。在 Focus 里取消置顶，这里的按钮也跟着变。原来顶栏上的「VS Code 打开文件夹」「在资源管理器中显示」「在终端打开」挪进了右边的「⋯」菜单。

## 0.9.30（2026-11-03）

- DeepSeek 可以用 DeepSeek Harness 桌面版里登录的账号了，不用 API Key：设置 → 模型 → DeepSeek 多了「登录方式」，选「DSH 桌面版的账号」就用桌面版登录的那个 DeepSeek 账号（用量和余额算在它上面，在桌面版里退出或换账号，这里跟着变；桌面版还没登录时会写明，登录后点「重新检测」）；选「API Key」就用填在这里的 Key。Key 现在可以直接在这里填、换、删（存在 Windows 凭据管理器里），没装过旧 AMO 的电脑也能设置了。没选过的话：这台电脑存着 Key 就照旧用 Key，没有就用桌面版的账号。用账号时型号列表只列账号的型号。第三方 DeepSeek 渠道不变，还是用它自己的 Key。
- Claude 可以登录多个账号了：设置 → 模型 → Claude 里点「+ 添加账号」，浏览器打开 Claude 的登录页，登录要加的账号就行（浏览器没自动打开时，那里有「打开登录页」；登录页给了一串代码的话，粘贴到那里）。每个账号一个独立的配置目录（Claude Code 官方的多账号做法），放在 `%USERPROFILE%\.claude-accounts` 下，终端里的 claude 不受影响。添加的账号和本机默认账号共用对话记录、Claude 的记忆、skills、插件，CLAUDE.md 和 settings.json 以默认账号的为准，所以切换账号后，原来的会话可以接着聊。Claude 订阅的会话都用「正在使用」的那个账号。左下角的额度按账号分开：正在用的照旧显示，其他账号收在「其他 Claude 账号」里，点开能看各自剩多少，每个后面有「切换」；设置里也能切换、重新登录、改名、删除。有 Claude 会话正在进行（在回复、等你批准或回答、有后台命令）时不能切换，等它结束或停止后再切。只有一个账号时，一切和以前一样。
- 去掉了「DeepSeek（Codex）」这个内置渠道，DeepSeek 只走 DSH。用过它的旧会话还能打开查看，但不能接着发消息了；常用预设里用它的那几条不再列出。

## 0.9.29（2026-11-03）

- 值守读问题页时不碰「待审核」「打回」的问题（别人提的、还没让维护者确认制作的），也不会把问题改成这两种状态。
- 程序包瘦身：程序文件夹里的文件从 11230 个减到 4396 个，第一次安装和每次装新版要建的文件少了一大半。去掉的是重复的一份内部模块、类型声明、source map，以及第三方包里的说明文档、测试和示例；各包的许可证照留。用起来没有变化。

## 0.9.28（2026-11-02）
