# AMO 中转服务 改动说明

团队服务器上跑的中转服务（含问题页、下载页、平台的发布点）和中转客户端的界面内容。每次部署一节，标题写 `## 版本号（日期）`；部署用 `npm run release -- relay-service`，版本号也写进服务（`/api/health` 的 `version`）。

## 下一版

- 会话右边加了「文件」边栏，替掉原来消息上方那一行附件：双方在这个会话里发的文件都在这里，最新的在上面，每个写明谁发的、什么时候、多大，同名文件有多个版本时写「v2 / 共 2 版」，有批注时写几条；点开在查看器里看，鼠标移上去可以直接下载。「＋ 附加文件」在边栏底部，也可以把文件拖进边栏。边栏可以收起（会记住），收起后标题右边有「文件 N」按钮再打开；窗口较窄时默认收起。
- 「复制给 AI」「在 Studio 里打开」从标题栏右边挪到左边，跟在会话状态后面。

## 0.7.12（2026-11-05）

- 会话里的「复制给 AI」「复制整个会话」「复制新回复」带上批注了：以前只带回复时勾选附上的批注，自己写的、回复之后才写的、还没回复时写的都没复制进去。现在会话附件上的批注都在，每条写成和 Reviewer 复制一样的样子：`文件名:行号`、`>` 后面是引用的原文、下面是批注内容和写的人（找不到原文所在的行时只写文件名）。「复制新回复」只带你上次发言之后写的批注。
- 文件查看器里的「复制批注」也带上行号。
- 看附件不再挡住会话：查看器改成浮在右边的面板，没有遮罩，后面的会话照样能看、能点；按住标题栏可以拖动，拖左边或右下角改大小，「铺满」（或双击标题栏）占满窗口。写批注用的是 Reviewer 那个小窗：能拖到旁边、能改大小，Ctrl+Enter 保存，Esc 只取消这条批注、不关查看器。
- 新增「已接手，不用回复」：收到的会话看过了、不需要回复时点它（在回复框旁边），会话就此结束，事情由你来做。可以写一句附言；发起人是 AI 时，可以勾选「把附言转给 AI」，不勾 AI 就不会收到任何消息（大多数时候对方已经把事情说清楚了，不用再打扰那个对话）。发起人那边显示「X 已接手 · 不用回复」，需要时任何一方都能重新打开。命令行和 MCP 读到的会话也写明「已接手（不用回复）」。
- 新增「说明」：左下角「说明」和会话状态旁的「?」打开，讲会话是什么、每个状态和按钮是什么意思、复制给 AI 复制什么、和 AMO Studio 一起用时怎么跳。
- 会话是本机 AMO Studio 里的 AI 发的、Studio 开着时，会话头上有「在 Studio 里打开」，点一下 Studio 跳到发起这个会话的对话（要新版的中转桌面程序和 Studio）。
- 刚登录那一下收到的会话不再丢：以前列表加载完、实时连接还没连上之间新来的会话，要等下次重新加载才显示。

## 0.7.11（2026-11-05）

- 问题页：粘贴了截图、最后没发出去的，一周后从服务器上删掉（以前一直留着）；发出去的截图不受影响。
- 上传文件和截图时不再卡住服务：最大 20 MB 的内容改成后台写盘。

## 0.7.10（2026-11-03）

- 服务器能给出每个工具每个版本的完整压缩包（`/platform/zip/<工具>/<版本>`，要登录），从已发布的文件现做，不另存一份；支持断点续传。平台「用完整包更新」用它。
- 下载页的「下载 AMO 平台」现在给的是最新发布的平台（测试和正式通道里较新的那个），按钮上写着版本号；以后每次发布平台，下载页自动跟着更新，不用再手动放压缩包（以前那份是 10 月 29 日手动放的）。

## 0.7.9（2026-11-03）

- 平台读的工具清单变小了：完整清单去掉缩进并压缩后再发（Studio 的从 2.3 MB 变成 0.5 MB），另有一份只含版本说明的摘要（几百字节），新版平台平时只读它。旧版平台照旧能用，也一样收到压缩后的清单。

- 问题页分了「维护者」：在管理页（`/admin`）的账号列表里点「设为维护者」。维护者在问题页上看得到所有人的问题，提的问题和以前一样直接进入处理。不是维护者的人只看得到自己提的问题（截图也是），提的问题先是「待审核」，维护者在「要你看」里看到，点「确认制作」后值守才开始处理；也可以写一句原因点「打回」，提交的人补充一句就重新提交审核。确认过的问题以后「还不对」再打开，不用再审一次。发布打包、前往讨论和改状态只有维护者能做。**部署后一开始谁都不是维护者**：先在管理页把自己设成维护者，不然值守读不到别人的问题、也不能代 AI 回复。

- 服务器给 Claude Code 和 Codex 做镜像：每小时查一次官方的最新版，有新版就在后台下好（断了接着下）。Claude Code 下压缩包，按官方清单核对；Codex 下 npm 上的 Windows 平台包，按 npm 给的 sha512 核对。核对通过后，局域网里的 AMO 平台可以从这里安装、更新它们。
- 管理页（/admin）多了「Claude Code 镜像」「Codex 镜像」两张卡片，各自能设：开关、多久查一次、要哪些平台（默认只要 win32-x64）、保留几版（默认 3 版）。卡片上还有当前状态、下载进度、出错原因和「现在检查」按钮。
- 文件放在数据目录的 `mirror/` 下。

## 0.7.8（2026-11-03）

- 网站首页多了「下载 Android 版」：服务器上发布过 Android 版时，首页写着版本号和大小，手机打开服务器地址点一下就能下载安装，不用先登录（装好后在 App 里用团队服务器的账号登录）。固定地址 `/downloads/android/latest.apk` 总是最新版。

## 0.7.7（2026-11-01）

- 便签的「待办」存在这里（`/api/todo`、`/api/todo/ops`）：每个账号每台设备一张表，加一张同账号共通的表；同账号的设备都能看、能改。删除的待办留 30 天标记，好让离线的设备知道；管理页改名时待办跟着走。

## 0.7.6（2026-10-31）

- AMO Studio 安卓版从这里更新：服务器上放最新的安装包（`npm run relay:mac -- android-publish`），登录的人能读到它的版本和改动说明（`/api/platform/android`）并下载安装包（`/platform/android/<文件名>`）。

## 0.7.5（2026-10-31）

- 问题页「打包记录」：0.7.3 时记下的那次打包没有每一步的时间，那几格显示「—」，不再显示「NaN 秒」。

## 0.7.4（2026-10-31）

- 问题页的打包进度：每一步（类型检查、单测、提交版本、打包、发布）各有一条进度条，按前几次同一步用时的中位数估计，写着「已用 / 约多久」，顶上写预计还要多久；没有历史的步骤显示一条滚动的条。下面「打包记录」能展开看最近 30 次打包，每次一行：每一步用了多久、总时长、成功还是失败，最上面一行是中位数，像 Jenkins 的 stage view。没报结束就又开始了新一次的（电脑关了之类），记成失败。
- 「等你回答」改名「需要确认」，「建议单开讨论」改成「去会话讨论」：问题详情里加了「前往讨论」按钮，点了之后值守不再处理这个问题，页面上显示处理过它的会话 id，复制后在 Studio 的搜索框里粘贴就能打开；想让值守接着做就点「交回值守」。每个问题都显示 AI 最后用的会话 id，带复制按钮。「要你看」不再列「去会话讨论」的问题。

## 0.7.3（2026-10-31）

- 问题页顶上能看到打包进度：正在打哪个包、第几步（测试 → 提交版本 → 打包 → 发布）、用了多久；打完了显示结果，失败了显示停在哪一步、为什么。半小时没有新进展会提示「可能中断了」。进度是 `npm run release` 用打包那台电脑的平台账号报上来的。
- 问题页布局改了：左边是问题列表，「报问题」平时收起，点了才展开；点一个问题在右边打开，「收起」关掉，再点一次列表里的它也会收起。来往多的问题只显示第一条和最后 3 条，中间的折叠成「展开前面 N 条来往」。窄窗口里列表和问题分开显示，看问题时有「← 回列表」。Esc 也能收起。

## 0.7.2（2026-10-31）

- 管理页 `/admin`：「服务器状态」卡片——整机和中转的 CPU、内存，在线人数和设备数，最近 24 小时的曲线；文件夹大小、磁盘、占内存最多的程序。10-31 上午部署过一次（没提交），被 0.7.1 覆盖掉了，这一版恢复。
- 下载页：「报问题」收进最下面折叠的「维护工具」里，平时只看到下载 AMO 平台。

## 0.7.1（2026-10-31）
