# AMO 中转服务 改动说明

团队服务器上跑的中转服务（含问题页、下载页、平台的发布点）和中转客户端的界面内容。每次部署一节，标题写 `## 版本号（日期）`；部署用 `npm run release -- relay-service`，版本号也写进服务（`/api/health` 的 `version`）。

## 下一版

## 0.7.7（2026-11-01）

- 便签的「待办」存在这里（`/api/todo`、`/api/todo/ops`）：每个账号每台设备一张表，加一张同账号共通的表；同账号的设备都能看、能改。删除的待办留 30 天标记，好让离线的设备知道；管理页改名时待办跟着走。

## 0.7.6（2026-10-31）

- AMO Studio 安卓版从这里更新：服务器上放最新的安装包（`npm run relay:mac -- android-publish`），登录的人能读到它的版本和改动说明（`/api/platform/android`）并下载安装包（`/platform/android/<文件名>`）。

## 0.7.5（2026-10-31）

- 问题页「打包记录」：0.7.3 时记下的那次打包没有每一步的时间，那几格显示「—」，不再显示「NaN 秒」。

## 0.7.4（2026-10-31）

- 问题页的打包进度：每一步（类型检查、单测、提交版本、打包、发布）各有一条进度条，按前几次同一步用时的中位数估计，写着「已用 / 约多久」，顶上写预计还要多久；没有历史的步骤显示一条滚动的条。下面「打包记录」能展开看最近 30 次打包，每次一行：每一步用了多久、总时长、成功还是失败，最上面一行是中位数，像 Jenkins 的 stage view。没报结束就又开始了新一次的（电脑关了之类），记成失败。
- 「等你回答」改名「需要确认」，「建议单开讨论」改成「去会话讨论」：问题详情里加了「前往讨论」按钮，点了之后值守不再处理这个问题，页面上显示处理过它的会话 id，复制后在 Studio 的搜索框里粘贴就能打开；想让值守接着做就点「交回值守」。每个问题都显示 AI 最后用的会话 id，带复制按钮。「要你看」不再列「去会话讨论」的问题。

## 0.7.3（2026-10-31）

- 问题页顶上能看到打包进度：正在打哪个包、第几步（测试 → 提交版本 → 打包 → 发布）、用了多久；打完了显示结果，失败了显示停在哪一步、为什么。半小时没有新进展会提示「可能中断了」。进度是 `npm run release` 用打包那台电脑的平台账号报上来的。
- 问题页布局改了：左边是问题列表，「报问题」平时收起，点了才展开；点一个问题在右边打开，「收起」关掉，再点一次列表里的它也会收起。来往多的问题只显示第一条和最后 3 条，中间的折叠成「展开前面 N 条来往」。窄窗口里列表和问题分开显示，看问题时有「← 回列表」。Esc 也能收起。

## 0.7.2（2026-10-31）

- 管理页 `/admin`：「服务器状态」卡片——整机和中转的 CPU、内存，在线人数和设备数，最近 24 小时的曲线；文件夹大小、磁盘、占内存最多的程序。10-31 上午部署过一次（没提交），被 0.7.1 覆盖掉了，这一版恢复。
- 下载页：「报问题」收进最下面折叠的「维护工具」里，平时只看到下载 AMO 平台。

## 0.7.1（2026-10-31）

- 问题页：新状态「建议单开讨论」（AI 觉得太大、不是顺手能修的）；新页签「要你看」：等你回答、卡住了、建议单开讨论，而且还没回的，页签上带数字。

## 0.7.0（2026-10-31）

- 从这一版开始记版本和改动说明。之前的改动见 git 记录（最近一次部署：问题页 `/issues`，提交 e483ca7）。
