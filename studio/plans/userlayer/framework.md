# 全景的框架（2026-11-04 起，讨论中）

全景（`panorama.md`）解决「怎么看」；这份写「事情从哪来、谁推进、人在哪里出手、数据怎么放」。用户 11-04 的讨论定下来的，没定的标「待定」。

## 定位（用户 11-04）

1. 最大限度地了解任务状态，把控整个项目；
2. 让人更好地做决策；
3. 解决工作中注意力切换的痛点。

和各家厂商往「项目 loop」进化的方向一致，但用户的工作（游戏开发要人验收手感；跨领域的琐碎工程维护，比如课件、健身计划）有一条不能让：**代码可以不审，方案一定要审**，项目的把控力不能丢。

## 分层

```
人 ── 审方案 / 拍板 / 看全局
│
展示层   可替换的渲染器（地图、书桌……）+ 固定的展示件词汇；只读数据层，按专题的展示配置画
│
agent 层 Router（全局一个）→ Lead（每个专题一个）→ Worker（每个 session）；都经结构化接口写数据层
│
数据层   全局 / 专题（topic）/ 任务（task）/ 会话（session）四个作用域 + 专题自己的规范、扩展字段和数据源脚本
```

## 名字（对齐 super-agent，任务和会话沿用 AMO 的叫法）

| 我们 | super-agent | 是什么 |
|---|---|---|
| Router | Router（代码里叫 orchestrator） | 全局调度：一件事该进哪个专题，没有合适的就问人；不拆任务、不做技术判断 |
| Lead | （没有，super-agent 只有两层） | 专题主控：拆任务、出方案、维护专题数据和展示件、处理任务之间的耦合；有事件才被叫起，不常驻 |
| Worker | Executor / worker | 推进：每个 session 照常干活，每轮交结构化的结果 |
| Task / Session | Ticket / Assignment | 沿用 AMO：一个 Task 是地图上一条 lane，一个 Session 是一轮或一条子 lane |
| Trigger | Trigger | 叫醒 agent 的事件：人说的话、一轮回复结束、handback、定时检查、数据源脚本的结果 |
| Mandate | Mandate | 一个 Task 被允许做什么：任务说明 + 审过的方案 |
| handback | handback | Worker 遇到超出 Mandate 的事交还给 Lead |
| human_action | human_action | 要人做的事，只认结构化字段，不从自由文字推断；在全景上就是「等你」 |

不设展示 agent：底层代码够稳定，全景由代码画。

## Worker 和 Lead 怎么配合

- Worker 一律把结构化的结果记进数据层：要点、方案、决定、拆分建议、handback。
- **在 Mandate 之内**（换实现办法、调细节）：只记成条目挂在节点上，Lead 不醒；人和 Worker 照常往下聊（订阅直通：人对某个节点的回答直接给这条 lane 的 session）。
- **超出 Mandate**（改目标、拆方向、影响别的 Task、偏离审过的方案）：Worker 交 handback → Lead 醒，决定在这条 lane 开分支、新开 Task，还是给别的 lane 标「需复查」。
- Lead 平时只看专题规范、各 lane 的一句话摘要和数据层条目（决定、方案、关联），不读对话全文；要细节按 id 去翻（super-agent 的「卡片 + 按需读原文」）。
- 跨专题的耦合由 Router 在全局层记一条关联，先只支持记录和显示。

## 模型和提示词（用户 11-04 定）

| 角色 | 默认模型 |
|---|---|
| Router | Sonnet 5.5 |
| Lead | Opus 5.5 |
| Worker | Opus 5.5 |
| 整理（抽要点、补记决定的兜底等） | Dxx-DS |

- 在**全景自己的设置弹窗**里设：每个角色的模型，以及每个角色的提示词（在内置提示词之外追加或替换）。不放进 Studio 的总设置。
- Router 和整理工作先用观察模式：只记「本来会怎么做」，人看几次觉得对了再放开。

## 专题模板（用户 11-04）

- **专题由人建**；建的时候选一个模板。模板 = 一组默认的专题规范（工作规范、状态字段、展示配置、审核规则）+ 建议的数据源脚本 + Lead 提示词的补充。先内置几种常见的（比如游戏开发、工程维护、学习/计划类），具体哪几种做的时候再定。
- 目的：除了少数专项专题，人不用维护这层框架，只关心任务内容；特殊专题再在模板上改。

## 第一版：模拟现在的推进方式，跑通流程（用户 11-04）

人在专题里给某个项目建 Task，和 Worker 一问一答推进，完成后归档。变的只是查看和审核的形式，lane 和周边留下更多信息。

- **第一版可以有 Router**（用户 11-04），但专题由人建；Router 把人说的事放进已有的专题，没有合适的就问人。
- **全景里有自己的建 Task 入口**，体现「专题 → Task」的层次（建在哪个专题、哪个项目）。全景是独立的特殊模块，**从 Studio 的建任务流程里搬逻辑，不复用它的界面组件**（用户 11-04）。会话窗口是例外：抽成共用模块（见下）。

### 入口和占位（11-04）

- 入口放在**左边栏「全部任务」附近**：全景面向所有专题，不属于某一个专题，放在专题内的「看板 / 画布」选项卡旁不合适；以后有多张全景时，这里就是全景的列表。
- 打开全景时**保留左边栏**，全景占右边的主区域（原来看板、画布的位置）。

- **节点**：Worker 每回复一轮，lane 上长一个节点，带一个「待查看」的方块标记。
- **节点状态**：未看（空心）→ 看了一部分（半填，带进度）→ 审完。**审完后只有两种结果**（用户 11-04）：**待回复**（人回复后自然继续推进，长下一个节点）或**完成**（人标记完成，lane 接上终点）。
- **查看**：点方块看整轮对话。会话窗口抽成一个模块，Studio 的会话页和全景共用同一份，改渲染让两边一致（用户 11-04 提议）。新加的阅读功能做在这个模块里，两边一起受益。模块属于 AMO 一侧，全景通过页面传进来的插槽使用它，绘制层不直接引用（守住 `panorama.md` 里「和 AMO 的边界」）。
- **阅读进度**：读到哪一行随手标（或自动记），被打断回来跳到上次读到的位置；读到结尾或关键点都处理过才算审完。
- **批注**：沿用逐行批注、攒起来一起发回。
- **关键内容提示，主要靠 AI**（用户 11-04：先按这个方案试）：Worker 回复时交一份结构化的要点，每条指向回复里的具体行（方案、假设、风险、要拍板的地方）；阅读时这些行高亮，旁边一个小目录可以跳。
- **决定**：人在回复里做的决定（比如「按第 2 个方案推进」），由 **Worker 在下一轮开头用工具记下**（它最清楚、几乎不多花 token，也符合「只认结构化字段」）；Worker 没记、但人的话里明显有决定时，便宜模型兜底补记，先观察模式。决定挂在节点旁，默认只有一个小标记，悬停展开，阅读时对应文字标亮（防止抢注意力）。
- **拆分**：人说「分 3 个方向推进」，或 Worker 建议拆成多个 Task，Worker 交一份结构化的拆分建议，写明是「Task 里分支」（从这个节点岔出子 lane = 分支 session）还是「拆成新 Task」（交 Lead，新开 lane，原节点连线过去）；人确认时可以改，确认后 lane 自动变结构。
- **审核档位**（方案必审 / 只看结果 / 全自动）第一版不做：每一轮都是人在审。等以后有自动推进再加。

## 数据层

- 四个作用域，每层「固定字段 + 扩展字段」：全局（专题目录、跨专题关联）、专题（目标、规范、展示配置、项目状态）、Task（lane、方案、清单）、Session（每一轮、要点、方案、决定）。固定字段所有渲染器都认识；扩展字段的格式由专题规范定义，写入时校验。
- **专题规范存在 AMO 的数据里，不进项目仓库**；项目里已有的规范文件（比如 AGENTS.md）可以引用，不复制（用户 11-04 同意）。规范分：工作规范、状态字段、展示配置、审核规则。
- 只有 Host 写数据层；AI 通过 MCP 工具写，每次写入校验格式、记一条事件；渲染器只读。
- **数据源脚本**（用户 11-04 同意）：专题可以挂几个脚本，存在 AMO 的数据里，在指定项目目录里定时或有事件时跑，打印 JSON；Host 按专题规范校验后写进数据层（项目状态字段、展示件内容）。复用值守项的运行方式，保存时由人批准（脚本带人的权限）。**脚本只产出数据，不碰画面。**

## 展示层

- 固定的**展示件词汇**：进度汇总、重点目标、状态字段表、清单、文档列表、公告板、时间线、数字指标……每种有固定的数据格式。
- 每个专题一份**展示配置**（数据）：首页放哪些展示件。Lead 通过接口写配置、填内容。
- 每个渲染器各自实现这套词汇（地图：区域头上的贴地字；书桌：一摞文件最上面那张）。换渲染器不动配置和数据。
- **渲染器和主题随版本发布，不做成可动态挂的脚本**（11-04 建议，用户同意）：渲染器是重代码（deck.gl、性能、拾取），做成插件要拆元素、定插件接口、做沙箱和版本兼容，代价大；专题的定制需求由展示配置 + 数据源脚本覆盖。折中：主题参数（颜色、字号、开哪些图层）已经是风格表里的数据，以后可以开放成可编辑的 JSON，加主题不用发版；展示件词汇随版本增长。等真有「外部要写一个渲染器」的需要再谈插件。

## 第一版的顺序（11-04）

0. 把预览里的新渲染器（地形岛 / 地铁、贴地字、开场动画、平滑缩放）接进 Studio 的全景页，用真实数据看效果；入口挪到左边栏「全部任务」附近，保留左边栏。
1. 会话窗口抽成模块，接进全景：点节点的方块看整轮对话。
2. 节点状态（未看 / 看了一部分 / 审完 → 待回复或完成）和阅读进度。
3. Worker 交要点和决定的工具，阅读时关键行高亮。
4. 拆分建议，确认后 lane 自动变结构。
5. 全景的设置弹窗（角色的模型和提示词）、Router、全景里建 Task、专题模板。
