# AMO 中转 · 阶段 2：团队任务和决策会话（方案）

> 2026-10-27，根据用户描述的团队开发流程整理。状态：用户已定下「需要你定的」几条（见文末「用户的决定」），正在出界面原型 `plans/relay-ui-prototype.html`，确认后从 2a 开始。上一阶段见 `plans/relay.md`。图解版：`plans/relay-tasks.html`（不进 git）。

## 一句话

- 现在的「请求」升级成**会话**：会话多一个「现在等谁处理」，处理的人有三个动作：返回给发起人、接手任务、标记完成。
- 会话上面加一层**团队任务**，任务始终在某个人手里，靠流转往下推进。
- 每个人只需要看两样东西：**我手里的任务**、**待我处理的会话**。
- 文件（Markdown/HTML）和批注挂在任务或会话上，批注可以一键带进回复，AI 也能用 MCP 拿到。

## 场景：开发一把加特林

1. 策划新建团队任务「加特林」，写 designdoc，传到任务里。
2. 策划在任务页点「复制任务提示词」，贴给自己的 AI 做初审。提示词里有团队流程、任务 id 和 MCP 用法。
3. 初审通过后，AI 用 MCP 给程序发一个会话，附上 designdoc 和要确认的问题，比如「推进方式」三选一。
4. 程序在「待处理」里看到这个会话，可以批注 designdoc，然后三选一：
   - 回复并返回给策划；
   - 接手任务：弹窗里选新状态、写原因；
   - 标记完成。
5. 策划在「待处理」里看到返回的会话，点「复制给 AI」，或者让 AI 用 sessionId 自己取，然后继续推进。做完后把任务流转给程序终审。
6. 程序终审通过，把任务标成已完成。

## 概念

| 概念 | 是什么 | 和现在的关系 |
|---|---|---|
| 团队任务 | 标题、说明（Markdown）、创建人、**持有人**（在谁手里）、状态、文件、会话、记录 | 新增 |
| 会话 | 一个人（或他的 AI）发给另一个人、需要对方处理的一件事。可以挂在任务下，也可以不挂。带「现在等谁」（`waitingOn`） | 由现在的「请求」改名升级，逐条回答和结论都保留，旧数据自动迁移 |
| 聊天 | 普通聊天 + 话题，用来闲聊 | 不变 |
| 文件 | 任务或会话的附件，按版本保存，Markdown/HTML 能直接打开看 | 新增 |
| 批注 | 选中文件里的一段文字写意见 | 新增，复用 Studio 的定位方法 |

## 会话：现在等谁

| 状态 | 等谁 | 等的人能做什么 | 列表里 |
|---|---|---|---|
| 待处理 | 收到的人 | 回复并返回 / 接手任务… / 标记完成 | 收到的人：「待我处理」，高亮；发起人：「等对方」 |
| 已返回 | 发起人 | 继续追问（回到对方手里） / 标记完成 / 复制给 AI | 发起人：「待我处理」；对方：「等对方」 |
| 已完成 | — | 任何一方都能重新打开 | 两边都在默认折叠的「已完成」里 |

- 「回复并返回」：回复表单（逐条回答、补充说明、结论）照旧，只是发出去的同时把会话交还给发起人。只写一句批注就返回也可以。
- 「接手任务…」：只有挂在任务下的会话才有这个按钮。弹窗里写新持有人（默认是自己）、新状态、原因，可以勾选「同时结束这个会话」（默认勾上）。
- 迁移：现在 open 的请求 → 待处理；answered 的 → 已返回（等发起人确认）。

## 任务：持有人、状态、流转

- 默认状态：设计中 / 评审中 / 开发中 / 待验收 / 已完成 / 已搁置。这份列表可以在服务上改。
- 流转 = 换持有人 + 选新状态 + 写原因，在弹窗里完成。流转会写进任务记录；新持有人的「待处理」里会出现一条「任务流转给你」，点开就算看过了。
- 建议小团队里谁都能流转，全部留记录，原持有人会收到提醒。会话里的「接手任务」就是把任务流转给自己。
- **决策**：会话收到回复时，逐条回答和结论自动汇总到任务记录里的「决策」。AI 调一次 `relay_task_get`，就能拿到说明、持有人、状态、决策列表，以及每个会话的摘要和 id。
- **推进方式**（策划在主分支开发 / 策划拉独立分支、程序合并 / 程序接手）：建议不做成固定字段，而是写进团队流程，作为一个标准问题，由 AI 在会话里三选一地问，回答自动记为一条决策。（待定）

## 文件和批注

- **上传**：在客户端里把文件拖进任务或会话；AI 用 MCP 的 `relay_file_put` 传本机文件（例如 `designdoc.md`）。同一个地方再传同名文件就是新版本，旧版本保留。文件存在服务数据目录的 `files/` 下，单个文件不超过 20 MB。
- **展示**：
  - Markdown 用现在的渲染器。
  - HTML 放在沙箱 iframe 里，默认**不运行脚本**，这样才能安全地选中文字批注。需要看交互时可以切到「运行脚本」，这个模式下不能批注。
- **批注**：选中文字，写一条意见。定位方式是「引文 + 前后各 24 个字」，做法参考 Studio 的 `packages/ui/src/lib/selection.ts`，界面参考 `packages/ui/src/review/AnnotationBubble.tsx` 和 `AnnotationPanel.tsx`。文件出新版本后，还能找到原文的批注自动跟到新版本上，找不到的标「原文已改」。
- **一键带走**：
  - 「复制批注」生成一段 Markdown：引文、意见、文件名和版本。
  - 回复表单里有「附上我的批注」，直接把批注带进回复。
  - `relay_session_get` 返回的内容里也带批注。

## 界面重新规划

现在的界面是一栏列表加对话。加上任务之后东西变多，改成三栏：左边是窄导航，中间是列表，右边是详情。

- **导航**：待处理（带数字）/ 任务 / 聊天 / 成员 / 设置（团队流程、状态列表）。
- **待处理**：一个按时间排的队列，里面有三类：收到的会话、返回给我的会话、流转给我的任务。每一项显示所属任务、来自谁、等了多久，处理完就从队列里消失。
- **任务列表**：默认显示「我手里的」，可以切到「我创建的 / 全部」，按状态分组。看板视图以后再做。
- **任务详情**：
  - 头部：标题、状态、持有人、创建人，以及「流转…」「复制任务提示词」两个按钮；
  - 标签页：概要 / 会话 / 文件 / 记录。
- **会话详情**：沿用现在请求页的样子，增加所属任务的链接、附件条，底部是三个动作。
- **文件查看**：在主区域打开，右边是批注栏；从会话里点附件打开，关掉后回到会话。
- **聊天**：现在的普通聊天加话题，不变。

  - 复制用法：加上团队流程。
- **不改**：账号、热更新、服务器状态、聊天和话题。桌面外壳也不用改：拖文件进窗口、上传、iframe 查看都是页面自己就能做的，不用加 `SHELL_VERSION`，大家不用重新下载客户端。
- **不做**：
  - 权限分级：小团队里所有人都能看到所有任务。
  - Git 集成：分支和合并还是你们在 Git 里自己做，中转只记录做了什么决定。

## 风险

- **数据迁移**：现有请求要转成会话。处理办法：迁移前备份数据库，迁移逻辑写单测，并用当前线上库的一份副本实测。
- **HTML 里的脚本**：designdoc 里如果有脚本，可能伸手到客户端。处理办法：默认不运行脚本；运行脚本时 iframe 不给同源权限，拿不到登录 key。
- **一次改动太大**：布局、任务、文件、批注同时上的话，很难测试。处理办法：按 2a 到 2d 拆开做，每一步都能单独用起来。
- **团队流程写得太死**：处理办法：流程是一段可以编辑的说明，不写进代码；推进方式也作为一个问题来问，而不是固定字段。

**补充需求**
- 一个任务下可以有多个会话；人在客户端里也能在任务下新建「任务会话」，能建多个。
- 会话常常是 AI 通过 MCP 发出的：人回复并返回后，应该由 AI 收取并继续。这一段要尽量自动走；卡住时，人能看出来并接手。

## AI 接力：返回给 AI 的会话怎么自动走

- 会话记下发起方是人还是 AI（`via`），以及发起人这一侧现在由谁处理（`handler`：ai / person）。AI 发起的会话，默认 `handler = ai`。
- **回复返回时**：
  - 如果发起人的 AI 正在等（`relay_session_wait` 等这个会话，或者 `relay_queue` 等队列），它马上拿到回复，服务记下「AI 已取回」和时间；
  - AI 处理完后用 MCP 收尾：`relay_session_reply` 继续追问（会话回到对方手里），或者标记完成；也可以 `relay_session_handoff` 交给人，并附一句原因。
- **没等着的 AI**：AI 的新对话开始时，MCP 说明要求先调 `relay_queue`，看有没有返回给主人、并且由 AI 处理的会话，有就接着做。
- **人能看到的状态**（发起人的「待处理」里）：
  - 回复已到，AI 还没取回（超过 10 分钟会高亮）；
  - AI 已取回，正在处理；
  - AI 取回后 30 分钟没有动作，可能卡住了（高亮）。
  - 两个时间阈值可以在设置里改。
- **人随时能接手**：
  - 「复制取回指令」：一行提示词，贴给任何 agent 就会去取；
  - 「复制给 AI」：复制整段回复和批注；
  - 「我来处理」：`handler` 变成 person，之后就是普通的继续追问 / 标记完成。AI 之后再对这个会话调 MCP 时，会被告知「已由某某接手」。
- 收到会话的人（例如程序）这一侧暂时只按人处理；让程序的 AI 也帮着处理，以后再说。

## 界面风格和回复规则（2026-10-27，用户看过第一版原型后定的）

- **整体照 AMO Studio 的设计语言做**，以后并进 Studio 时更容易适应：
  - 主题变量直接用 Studio 的 `packages/ui/src/styles/base.css`，浅色是「纸感编辑部」（象牙底、墨蓝强调），深色是 Studio 的深色。两套都支持，可以选「跟随系统 / 浅色 / 深色」。
  - 组件的做法照 Studio：顶栏（`.topbar` + `.view-tabs`）、左栏（`.scope-nav` / `.nav-label` / `.nav-row`）、**任务用看板卡片**（`.board` / `.column` / `.card`）、**会话用列表**（`.srow`）、弹窗（`.modal`）、按钮（`.btn-primary` / `.btn-ghost`）、标题用衬线字体。
  - 2a 开始时，`relay-ui` 先换成这套变量和组件，再加新功能。构建时直接引用 Studio 的 `base.css`，不复制一份，免得两边改着改着不一样。
- **批注在弹窗里做**：打开附件是一个大弹窗，左边是文档，右边是批注栏。选中文字后在批注栏里写；底部有「复制批注」「完成，回到会话」。回复表单里有「附上我的批注」和「打开批注」。
- **需要回复的会话，收到的人不能标记完成**：
  - AI 发来的会话一律需要回复；人发起的会话可以选择要不要回复，默认需要。
  - 收到的人只有「回复并返回」和「接手任务…」两个选项。接手时会同时回复会话，告诉发起方自己已经接手，会话回到发起方手里。
  - 只有发起方（人或者他的 AI）能标记完成。发起方还没等到回复时，可以「撤回并标记完成」。
  - 不需要回复的会话，收到的人才有「标记完成」。
