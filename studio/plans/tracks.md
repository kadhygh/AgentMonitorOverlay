# 脉络（tracks）：一个会话、几个会话推进多件事时，不丢线（2026-11-09）

> 状态：进行中。第 0 步（测试功能「开发中」标签、「脉络」开关、这份方案）在分支 `studio/tracks`（worktree `G:/PROJECT/AgentMonitorOverlay-tracks`）。下一步：面板原型。

## 起因（用户 11-09）

- 子会话和主会话之间的往来（回报、`session_send`）现在都以用户气泡铺在对话里，影响人的判断。
- 对话常分出几个方向：聊到后面分成 3 支，要分别迭代；人的精力在第 1、2 支，第 3 支就忘了，只能不时去问对应的对话「做到哪、还有什么没做」。
- 拉起子会话、或经中转发给别人，本身是一个小循环。
- 主会话和子会话频繁互动时人不该关心中间过程；派发之后应该让人直接在子会话里操作，省掉「子 → 主 → 人」的转手。
- 这几种本是想在全景里表达的。全景卡住了：框架太大、痛点不够明确。这次反过来，**从小向大**：先从会话级做起。

## 已定（用户 11-09）

- **名字「脉络」**，对标全景；会话顶上切换「对话 / 脉络」，点「脉络」右边整个换掉。代码 id `tracks`。里面那本账叫「台账」。
- 设置 → 测试功能：全景和脉络都标「开发中」。
- **台账是 Host 存的数据，不是会话**：放在会话里会跟着压缩丢、常驻维护越来越费 token（同 10-30 不做常驻看板员）。平级会话的用处是**接力**：一个会话做到一半太大，开新会话把台账交过去。
- **从会话级开始**，不预先判断任务大小：开了功能，新会话从一开始就带台账，空的不花什么。
- 新建会话 / 任务的界面要有对应选项；顺带把任务里「新建会话」改得像新建任务：一页填完首句、模型、附件、选项，一次创建并发出（现在是先选模型创建、再写首句）。
- 用**开发界面目录**（设置 → 测试功能，`config.devUiDir`）在 worktree 里迭代界面；Host 一侧的改动要重启 Host 才生效，攒一批，由人在没有会话运行时点重启，必要时发测试版。

## 核心流程

1. **面板**：脉络视图长什么样，先做原型（用验证里那份真实台账做 2～3 种可点的 HTML），人上手比较后再定。
2. **单会话、中等任务**（多数任务，尤其策划推过来的）：有可能压缩一两次。靠外置的台账维持多件事稳定推进。
3. **多会话、中等 / 复杂任务**：一般知道任务后就能判断复杂度，一轮对话后直接开拆。主会话了解整个任务内部和它相关的内容，维持任务架构清晰，并让人看得懂（例：上面那个合并任务）。

## 做法（草案，随步骤补）

- 台账：线（thread）→ 条目（编号、一句话内容、类型、状态、等谁、来源）。
- 模型接口：`ledger_update`、`ledger_read`（MCP）。规则写进工具说明：内容写清，不能只写编号；有两件以上开着的事、或话题分叉了才开始记。
- 回给模型：平时不注入；压缩之后、人问进度时，把开着的事的目录放进下一条消息（`roleUpdate` 通道，`core/role.ts`）。
- 给人看：脉络视图（按线分组，「◐ N 条等你」）。
- 以后（流程 3）：条目挂会话 id / 中转 threadId；子会话回报只带台账变化和全文入口；人直接接管子会话；接力。
