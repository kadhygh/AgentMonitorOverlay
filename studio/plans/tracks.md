# 脉络（tracks）：一个会话、几个会话推进多件事时，不丢线（2026-11-09）

> 状态：进行中。第 0 步和面板原型（v1–v7、alt）做完；11-15 用户定直接走 v7（楼），第一版「脉络会话」接进 Studio（见下面「脉络会话（楼）」），在测试功能「脉络」开关后面。下一步：用户拿真会话用一阵，再看少什么。

## 起因（用户 11-09）

- 子会话和主会话之间的往来（回报、`session_send`）现在都以用户气泡铺在对话里，影响人的判断。
- 对话常分出几个方向：聊到后面分成 3 支，要分别迭代；人的精力在第 1、2 支，第 3 支就忘了，只能不时去问对应的对话「做到哪、还有什么没做」。
- 拉起子会话、或经中转发给别人，本身是一个小循环。
- 主会话和子会话频繁互动时人不该关心中间过程；派发之后应该让人直接在子会话里操作，省掉「子 → 主 → 人」的转手。
- 这几种本是想在全景里表达的。全景卡住了：框架太大、痛点不够明确。这次反过来，**从小向大**：先从会话级做起。

## 验证（11-09，`studio/out/branch-eval/findings.md`，不进 git）

拿 project_mining「代码合并和任务推进」主会话（人 40 条、收件箱 36 条、压缩 3 次、开 13 个子会话、人问进度 4 次）做的：

- 第一次压缩时开着的 16 件事：Claude 的压缩摘要完整保住 10、半截 2、丢 4；按台账格式记（规则「内容写清，不能只写编号」）Sonnet 14 / 2 / 0，Opus 15 / 1 / 0。
- 压缩后模型的汇总和摘要一模一样：摘要里没有的它就不知道。丢掉的「画面表现未核实（死者身上落雷）」后来成了 BR-007。只留编号的 D11 在压缩后被套上了 D12 的内容。
- 只取开着的事渲染成目录约 5,900 字，压缩摘要 11,000 字。
- 主会话转述子会话状态出错过一次（U24）；36 条回报共 84,185 字进了主会话的上下文。
- 10-30 以来人开的 78 个主会话：人发 10 条以内的 63 个，压缩过的 5 个；11 条以上的 15 个，压缩过 13 个，「问进度」只出现在这里。115 个子会话里人亲自进去发过消息的 57 个。

局限：一个会话、一个切点、单人标注；台账是事后一次整理，不是边干边记。

## 已定（用户 11-09）

- **名字「脉络」**，对标全景；会话顶上切换「对话 / 脉络」，点「脉络」右边整个换掉。代码 id `tracks`。里面那本账叫「台账」。
- 设置 → 测试功能：全景和脉络都标「开发中」。
- **台账是 Host 存的数据，不是会话**：放在会话里会跟着压缩丢、常驻维护越来越费 token（同 10-30 不做常驻看板员）。平级会话的用处是**接力**：一个会话做到一半太大，开新会话把台账交过去。
- **从会话级开始**，不预先判断任务大小：开了功能，新会话从一开始就带台账，空的不花什么。
- 新建会话 / 任务的界面要有对应选项；顺带把任务里「新建会话」改得像新建任务：一页填完首句、模型、附件、选项，一次创建并发出（现在是先选模型创建、再写首句）。
- 用**开发界面目录**（设置 → 测试功能，`config.devUiDir`）在 worktree 里迭代界面；Host 一侧的改动要重启 Host 才生效，攒一批，由人在没有会话运行时点重启，必要时发测试版。

## 脉络会话（楼）（用户 11-15 定，接进 Studio 的第一版）

用户 11-15：「我个人还是倾向于 v7…脑补是没意义的，一定要真的用上才能确认工具的实用性」；谈「AI 写的进度页」时发现它就是 v7（「这不就是之前说的 v7」）；最后定：「现在本来也是测试性、开发，我们就直接走 v7 的流程，正好我用这个会话来迭代体验，然后再来看看少什么。…测试功能开启后，task 里如果我勾选上了楼板类型的会话，这个会话点开直接就能看到相关的楼板表现，以及可以继续走对话。允许前面每轮楼板上有信息缺失。」

- **楼是从会话记录现算的，不存**：Host 每次被问到就把这个会话的行整理成楼（`features/tracks/tower.ts` 的 `buildTower`，数据形状在 `protocol/src/tower.ts`）。一轮一层（一条消息开一轮，前一轮没做事时接着算同一轮）；它开的子会话（`session_start`）是开出它那一层上的区域，只带最近 4 轮；回报、中转回复是收到它那一层上的小卡；楼顶是还没完的事（等人审批 / 回答、子会话在跑或等人、中转没回）；最近一次压缩是一条横线。所以旧会话、没勾选的会话也能看。
- **AI 只补它才知道的**：每轮的标题和一句结果、人强调的事和谈定的结论（「要点」），用 MCP 工具 `track_note` 写，存在 kv `tracks:<会话 id>`（`core/tracks.ts`）。没写的层，标题用那一轮开头的话顶着（用户：允许信息缺失）。这里的「要点」就是交流框架里说的「已定的事」的第一版。
- **告诉 AI 的时机**：勾上「脉络会话」后，随人的下一条消息带一行说明（和「AMO 更新」同一个通道）；每次压缩后再带一次（它忘了）。不常驻注入。
- **界面**：会话的对话上方一行「对话 | 脉络」和「脉络会话」勾选框。脉络视图盖在对话上，输入框留在下面照常用。楼本身是单独一页 `tower.html`（three.js，从原型 v7 的绘制代码改来），放在 iframe 里：不进工作台的包，样式互不影响；数据由外面的页面发进去，「在对话里看这一轮 / 打开子会话」发回来。数据变了整页重载（镜头位置留着）。
- **和原型不一样的地方**：子会话区域自动摆（按开出的先后排，放不下一起缩小）；楼层名画大了（真会话里每层多半只有一张被上层挡住的卡，首屏靠楼层名读过程）；楼顶没事时只留前面一条；首屏只框最上面 10 层，往下用电梯；颜色跟 Studio 的主题走。原型里的会话浮窗去掉了，换成跳回真的对话。
- **远程任务**（用户 11-15 发版当天：「我是远端操控好像看不到」）：远程副本的会话也有这一行。楼不在这台电脑上算（副本没有 AI 写的标题、要点和中转的线），而是向任务所在的电脑要（`rt.tracks`，带 `on` 就是勾选）；这台电脑只在自己的「脉络会话」名单里记一笔，让它一打开就是楼。那边的 Studio 版本旧（任务快照里没说它答 `rt.tracks`）时，这一行改成一句「要更新到哪一版」。做法上 tracks 自己把这条命令登记到 remote（`RemoteFeature.answerSession`），不让 remote 反过来调 tracks：否则 tracks → 中转 → 会话 → 远程 → tracks 成环。
- **用了一小段之后改的**（用户 11-16）：「脉络开启之后，如果我拖拽 sessionlist 的宽度，会卡住。然后视角坐标的设置改到右下角。楼层导航改到右上角，而且一上来就展示了全部楼层，我觉得效果不太好。点击某个卡片时，不要用侧边栏展示应该改成会话弹窗。弹窗开启时，下面的输入栏先隐藏，且输入栏的内容也展示到弹窗里。弹窗应该能拖动，能 pin。弹窗也能加批注。」随后：「选中楼层后，楼层之上，直接隐藏吧，现在半透明也有点怪怪的。」
  - **会话弹窗**：楼的页面只说选中了哪张卡片（`tower.pick`：哪个会话、哪一行、卡片自己的标题；点空白或 Esc 说 `tower.unpick`），外面的任务页把同一个 Thread（对话和输入框）挪进楼上面的浮窗，所以草稿、附件、批注都是原来那一套，不是另画一份。点子会话的卡片时，任务页选中的会话换成子会话，楼还按原来那个会话画（弹窗状态里的 `towerFor`）。固定了的弹窗只有 × 能关；人关掉时外面告诉楼的页面（`tower.popup`）取消选中。楼的页面因为数据变了重载之后，会把重载前选中的卡片重新标出来。
  - **导航和坐标**：导航在场景右上角，只列楼顶和连着的 6 层；视角坐标在右下角；选中楼层后上面的楼层藏起来。右边栏只留总览。
  - **拖宽度卡住**的原因：鼠标移到 iframe（楼）上面以后，移动和松手的事件进了那一页，外面的页面收不到。拖动时把指针抓在拖柄上，并且让 iframe 这期间不接鼠标（`lib/dragWidth.tsx`、`shell.css`）。
- **用户对它的判断**（11-16）：「经过短暂的时候我现在感觉脉络可能没那么方便。但是顶楼其实还有必要。不过暂时不用删除，我再用一段时间。」所以楼先留着、不再往上加东西；接下来做的是对话里的审阅进度（`plans/review-progress.md`）和白板（`plans/board.md`）。
- **没做的**：子会话自己经中转问人的卡（只在楼顶显示「在等谁回」）；`decision_request` 等的决定不在楼顶；分段（几轮合成一段）；手机版没有；会话列表里没有「脉络会话」的记号。

## 核心流程

1. **面板**：脉络视图长什么样，先做原型（用验证里那份真实台账做 2～3 种可点的 HTML），人上手比较后再定。
2. **单会话、中等任务**（多数任务，尤其策划推过来的）：有可能压缩一两次。靠外置的台账维持多件事稳定推进。
3. **多会话、中等 / 复杂任务**：一般知道任务后就能判断复杂度，一轮对话后直接开拆。主会话了解整个任务内部和它相关的内容，维持任务架构清晰，并让人看得懂（例：上面那个合并任务）。

## 做法（草案，随步骤补）

- 台账：线（thread）→ 条目（编号、一句话内容、类型、状态、等谁、来源）。
- 模型接口：`ledger_update`、`ledger_read`（MCP）。规则写进工具说明：内容写清，不能只写编号；有两件以上开着的事、或话题分叉了才开始记。
- 回给模型：平时不注入；压缩之后、人问进度时，把开着的事的目录放进下一条消息（`roleUpdate` 通道，`core/role.ts`）。
- 给人看：脉络视图（按线分组，「◐ N 条等你」）。
- 以后（流程 3）：条目挂会话 id / 中转 threadId；子会话回报只带台账变化和全文入口；人直接接管子会话；接力。
