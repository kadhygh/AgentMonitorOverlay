## 用户补充的 6 条

1. **Review 拆成查看器（Viewer）**：除了 git diff，还能读 md 文件、按指定行打开脚本做常规查看，并标出是哪几行。对话里点文件链接默认就打开这个查看窗口。默认只有一个窗口，点「固定」之后它保留，下次点链接另开一个。链接右键还能「用 git diff 看」和「VS Code 打开」。
2. Review 窗口竖向调整大小时疯狂闪烁。
3. 分支历史：单独一个按钮，弹出像找文件那样的列表，可以快速搜索提交说明、hash、作者；选中一个提交，另开一个 Review 窗口看这个提交的改动。
4. 滚动条旁边加一竖条，像 minimap 一样显示改动在文件里的位置。
5. 文件列表能拖动宽度了，但还是太窄，允许拖得更宽。
6. GPT 加一个 Fast 按钮。

### 用户的决定（2026-10-14）

- 查看器是**独立窗口**（像 Review），可以拖到别的屏幕、同时开多个。
- **只有点「固定」按钮**才固定；没固定的那个窗口会被下一次点击复用。
- 右侧栏的快速查看**保留在右键菜单里**：单击打开查看器，右键 = 查看器打开 / 右栏快速查看 / 用 git diff 看 / VS Code 打开 / 在资源管理器中显示 / 复制路径 / 标记。

### 按默认推进的做法（可推翻）

- **查看器和 Review 是同一种窗口**，只是模式不同：「文件」（代码按语言变色、行号、标出指定的行或行范围并滚到那里；Markdown 默认渲染，可切源码；图片）和「改动」（现在的 Git Review）。窗口地址 `#viewer?…`，旧的 `#review?…` 照旧能用。标题栏：模式切换、文件路径、固定、VS Code、资源管理器、标记。
- **窗口规则**：
  - 没固定的预览窗口全局只有一个，点链接时复用它，换成新文件。
  - 固定之后，它就不再被复用。
  - Review（改动模式）仍是每个项目一个窗口。
  - 提交历史打开的提交是另外的窗口，每个提交一个。
- 「用 git diff 看」= 打开这个项目的 Review 窗口并选中这个文件；文件没有改动时提示「这个文件没有未提交的改动」。
- **提交历史**：Review 标题栏「历史」按钮，弹出和 Ctrl+P 找文件一样的列表：当前分支最近 500 个提交，显示短 hash、说明首行、作者、时间。输入框同时匹配说明、hash 和作者。回车或点击，另开一个窗口看这个提交相对它父提交的改动（合并提交对第一个父提交），只读，不能批注。
- **总览条**：diff 区滚动条左边一条约 12px 宽的竖条，按行位置画出新增（绿）、删除（红）、修改（黄），框出当前可见区域，点击跳过去。单栏、左右对照、只看改动、完整文件都有。
- **列表宽度**：上限从 600px 改为窗口宽度的 70%。
- **Fast**：只给声明了 fast 档的型号显示，读 Codex `model/list` 返回的 `serviceTiers`。输入框下方加一个开关，默认关，按会话记住；打开后每一轮带 `serviceTier: "fast"`。开关的提示里写上 Codex 对这个档的说明（`ModelServiceTier.description`），比如是否更耗额度。DeepSeek 等第三方路由不显示。
