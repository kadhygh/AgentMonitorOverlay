### 用户定的

- **板上的事项卡就是事项的画法**，不另存一份状态；按参与方分道，再加一道「已定 / 已验」；群聊顶部列开着的事和等谁确认。

## 概念

三样东西，两条线：**消息是推的，板是拉的。**

| | 是什么 | 谁会被叫醒 |
|---|---|---|
| **事项** | 一来一回的小循环：委派子会话、经中转问人、要人审批、向人提问、别人来信、agent 之间商量一件事。有主场（一个会话）、参与者、等谁、结论 | — |
| **消息** | 事项里的一条：谁发的、发给谁、属于哪件事项、哪一类（提问 / 回复 / 回报 / 结论 / 通知）。人和 agent、agent 和 agent、本机和别的设备，格式一样，只是走的路不同（本机收件箱 / 中转） | 收的那一方 |
| **板** | 一个范围里共享的状态：这个范围里的事项（开着的、定了的）和事件（谁定了什么、改了什么）。范围从小到大：会话树 → 任务 → 专题 → 项目。Host 存的数据，不是会话 | 没有人。要谁干活，就明确发一条消息给谁 |

参与者只有两种，地址只用一套：人（团队账号）、agent（会话 id，可以在别的设备上）。

### 规则

1. **消息跟着事项走。** 属于某件事项的消息自动进它的主场会话。
2. **来信没有事项时，自己开一个会话接。** 别人（或别人的 AI）主动发来、不属于任何事项的，Host 开一个「接待」会话，来信成为它的第一件事项；它自己看是哪件事、该问谁、要不要回。它不往别的会话的上下文里塞东西：要找相关的会话，就照规则 3 发消息问。
3. **agent 之间可以直接发消息**，不必经人转。按距离分档：同一棵会话树里自动送；同一个专题、不同任务（都在用户自己这边）**默认自动，任务上可以改成先问**（用户 11-15 定：先做自动，或者做成可配置）；别的设备、别人的 agent 走中转。
   - 现在是怎样的（11-15 核对代码）：跨任务只有主控能传话（`task_message`，`host/src/features/relays/`），默认要人在主窗口或 Focus 里确认，任务的 ⋯ 菜单里有「主控传话不用确认」（`relayAuto`，默认关）；`mailbox_send` 是留言，不会自己进对话，要人转。所以这次是把默认值从「先问」翻成「自动」，并且不再只限主控。
   - 不同专题之间、没有专题的任务之间：仍然先问（用户 11-15：按建议来）。
4. **板的改动不叫醒任何人。** agent 要用时自己读（MCP），压缩上下文之后 Host 把它所在范围里开着的事读回给它。这样不需要常驻的看板员。
5. **会话在等人时，来的消息不开新一轮。** 有没答的审批或提问、或输入框里有字时，来的消息只更新事项卡；人发下一句时一起带给模型，或者人点「现在让 AI 看」。
6. **给人看时按事项折叠。** 对话里一件事项一张卡，在原地更新，不再是一条条气泡；点开是这一来一回的全文。

### 仍然要人的地方（守旧决定）

- 发给真人之前先问（除非开了 设置 → 功能 → 中转 的自动发送 `teamAutoSend`）。
- 动别的任务的内容，照 `task_message` 的规矩。
- 接待会话拿不准归到哪、或要做决定时，停下来等人。
- 只在局域网、只连自己的设备；远程默认关闭。

### 为了以后能自动对话，现在就要留的护栏

- 每件事项有主人（提出它的那一方），只有主人和人能关掉它。
- agent 之间一件事项的往来有轮数上限；到了就停下标「等人」，不让两个 agent 来回烧额度。用户 11-15：合理，可以设 30～50 轮，理论上极少有任务会到。（具体数没定；人在这件事项里说过话就重新数。）
- 等结果时结束本轮，不 sleep、不轮询（`agent-collab-direction.md` DSH 表第 1 条）。
- 来信是别人写的内容：接待会话默认只读权限。
- 人随时能看每件事项的全文、能插手。

### 别人写的内容进了会话（现在就有的风险）

用户 11-15 问：现在 AI 用中转发给别人、别人回了之后 AI 接到自动跑，算不算这个风险。算，是同一类：回复以「【中转回复】…」进发起会话的收件箱（`teamrelay/service.ts` `tell`），这一轮结束后自己送进去，会话接着用它自己的权限跑；回复里要是写了「顺手把 X 也改了」，模型可能照做。比来信轻的地方：人是自己挑的、事是自己起的头、回复标明了是谁说的，而且只在局域网、登录过的同事之间。

框架里统一成一条：**消息带着「谁写的」进模型，别人写的内容只当信息，不当指令**（写进送给模型的那段说明里）；会话因为别人的消息自己开跑的那一轮，要动手改东西时照会话本来的审批走，不因为是自动开的就放宽。接待会话再加一层：默认只读。用户 11-15：规则可以加。

**信任的人（用户 11-15 定）**：用户大部分情况是信任对方的，所以按人管：**默认都信任，不信任的才处理**（用户原话：现在先默认都信任，不信任才处理）。也就是现在的行为不变：同事的回复直接送进会话接着跑；用户把某个人标成「不信任」以后，他的回复先给用户看，用户点了才送。做法（用户 11-15：按建议来）：

- 信任管的是「要不要先过我的眼」，不改上面那条规则：信任的人写的内容进模型时仍然标着是谁写的、只当信息。
- 来信也按它走：信任的人发来的直接开接待会话；标了不信任的先停在「我的来信」，用户点了才开。
- 标记要顺手：会话里某人的回复卡片上有「以后先给我看」；设置里有一页能看、能撤。

### 多方确认（用户 11-15：先做一对一，改一对多也比较容易）

中转会话现在是一对一的（`relay/src/protocol.ts`，`to` 是一个人）。建议分步来：

- **概念和数据现在就留**：事项的参与者是一个列表，每个人有自己的状态（等 / 回了 / 通过 / 要改），事项上写「怎样算完」（都回了 / 有一个回了）。以后加比现在留贵得多。
- **第一刀只做一对一**：和现在的 `team_ask` 一样。
- **第二步做「同一件事分别问几个人」**：一件事项下面挂几条一对一的中转会话，不用改中转；事项卡上一行一个人。两个人答得不一样时不自动裁决，回到主场交给提出的人。
- **几个人在同一条里互相看得见地讨论**（群聊式）先不做：那是另一种东西，轮到谁说、谁说了算都要另定。

## 和现有东西的关系

| 现有的 | 在框架里是什么 |
|---|---|
| 会话收件箱的行（进对话后是 `type: "user"` 的条目，只多一个投递状态） | 消息：加上事项 id、类型、来源 |
| `team_ask` 的中转会话（回复已经自动回到发起的会话） | 一种事项 |
| `session_start(report)`、`session_send` | 一种事项；放开到同一棵树里互发 |
| 审批、提问 | 一种事项（等的是人） |
| `mailbox_send`（现在要人转） | 消息，按规则 3 的档决定自动还是先问 |
| 脉络的台账（`plans/tracks.md`） | 板在会话这一级；条目就是事项，加上模型记的结论 |
| 画布、看板 | 给人看板的另外两种样子；以后管家读板，不读原始对话 |

### 怎么转进来（我的建议）

概念定了之后，现有的东西一样一样转，不一次全换：

- 每转一样，先「换底不换样」：MCP 工具的名字和用法不变（`team_ask`、`session_start`…），只是 Host 在底下多建一件事项；确认没坏，再换界面上的样子（事项卡）。
- 顺序按离概念的远近：`team_ask` 的中转会话（已经有会话 id、状态、自动回主场，最近）→ 审批、提问 → 子会话的回报和 `session_send` → 留言和传话（`mailbox_send`、`task_message`）→ 来信。
- 不转的：画布、看板、值守本身不是交流，留在原处；它们以后读板。

## 交流模板（框架稳定之后；做法没定）

模板 = **一类事项怎么走**。拿「策划做完功能，让程序审核」说：

| 模板里写的 | 这个例子 |
|---|---|
| 什么时候用 | 策划的会话把一个功能做完、验证过 |
| 发给谁 | 按角色找（程序），不写死人名 |
| 开场要带什么 | 改了什么、怎么验证的、要对方确认的几点（每点带选项） |
| 对方怎么回 | 通过 / 要改（一条条列）/ 要讨论 |
| 之后怎么走 | 要改 → 回主场会话改 → 在同一件事项里再发；通过 → 记结论，关掉事项 |
| 护栏 | 最多几轮、发之前要不要问人 |

和提示词的区别：提示词只能告诉 AI「照这个格式发」；模板挂在事项上，Host 认得它走到哪一步，所以能显示「审核第 2 轮 · 等程序」、改完再发时不另开一件、到了轮数上限自己停。所以它要排在事项做出来之后。在那之前，用提示词模板（`plans/done/prompt-templates.md`）写一条「发给程序审核」先顶着，顺便试出模板里到底该有哪几栏。

它和 `agent-collab-direction.md` 里谈过的「协作模板」（角色：模型、强度、权限、分工规则）是一件事的两半：那边定的是**谁来干**，这里定的是**一类事怎么走**。建议合成一种模板，不做两套；那边没答的 4 个问题到时一起定。

## 第一版做了什么（11-15，用户：「推进第一版，推进到差不多能用的就发测试版」）

第一版是「建议的第一刀」里第 1、2 步的一部分，不改数据怎么存，只在现有的会话收件箱上加东西：

1. **消息带上来源**。收件箱送进会话的行多一个 `origin`（`protocol/src/entities.ts` 的 `MessageOrigin`：哪一类、谁发的、哪个会话或哪几个中转会话、子会话的回报是做完 / 被停下 / 出错）。六处都带：子会话回报、`session_send`、中转回复、主控传话、转来的留言、值守。旧消息没有这个字段，按给模型看的那一行【…】认（`protocol/src/origin.ts`），所以已经在进行的对话也一样显示。
2. **对话里不再当成人的气泡**。这些消息显示成一条折叠的行：谁发的、两三行摘要、字数，点开看全文（`ui/src/chat/OriginMessage.tsx`）。
3. **事项清单（自动的部分）**。设置 → 测试功能 →「脉络」打开后，任务页侧栏最上面一栏「还开着的事 / 已结束的事」：经中转问了谁、等了多久，哪个子会话在跑，哪个审批 / 提问 / 决定在等人，压着几条消息；点一条跳到对话里对应的行或那个会话。它是界面从已有的记录里算的（`ui/src/tracks/matters.ts`），Host 还没有「事项」这张表，也不花模型的 token。
4. **规则 5 的后一半：打字时不插队**。输入框有按键时界面告诉 Host（最多一分钟一次），Host 的收件箱压住这个会话的来信 5 分钟；人发出消息时排在它后面一起送，输入框清空或 5 分钟没动就照常送（`sessions/inbox.ts` 的 `typed`）。前一半（有没答的审批 / 提问时不开新一轮）收件箱本来就是这样。**0.9.69 发出当天用户说「这个可以先去掉，等我体验一段时间」**：改成测试功能里的开关「打字时不插队」（`typing-hold`），默认关；关着时界面不告诉 Host，Host 也不压。同一天用户又说「测试功能，给脉络单独加一个弹窗或者选项卡，可以点开时候具体进行设置调整。我们开发中的有些东西可以先放在里面」：脉络在 设置 → 测试功能 里有了自己的一页（它那一行的「详细设置」），列出已经有的（事项清单）和开发中可以单独开的选项，「打字时不插队」是第一个；选项只在脉络开着时生效（`EXPERIMENTAL_FEATURES` 的 `parent`，`experimentalEnabled`）。以后这条线上做到一半的东西都先放这一页，默认关。
5. `session_start` 的说明里加了「只剩等结果时结束这一轮，不要 sleep 或轮询」。

没做、排在后面的：Host 里真正的事项表和事项 id（现在是算出来的，重启不丢但也不能挂结论）、「已定的事」（AI 记结论、压缩后读回）、来信开接待会话、不信任标记、同专题跨任务自动互发、轮数上限、交流模板、v7 的楼。

## 建议的第一刀（没定）

1. Host 自己建事项、更新状态（`team_ask`、`session_start`、审批、提问发生时），不花模型的 token；收件箱的行带上事项 id、类型、来源。
2. 对话里折叠成事项卡；规则 5（等人时不开新一轮）。
3. 板在会话这一级：「还开着的事 / 已定的事」，结论由 AI 一句话一条地记，压缩后读回。
4. 来信开接待会话。
5. v7 雏形读这份数据（楼层 = 轮，竖线 = 事项，楼顶 = 等人的事项）。

板升到任务 / 专题、agent 跨任务自动对话、管家，等前面用过几轮再定。

## 原来没定的几件（11-15 都定了）

用户 11-15 先说「其他的我觉得你说得都没问题」，后来又说「其他都按建议来就行了」，下面这几条都按当时的建议定了。

1. 哪些来信开接待会话：只有「要确认的事」（带问题的中转会话、别人的 AI 发来的）才开；人和人的普通聊天不开。（按建议）
2. 接待会话用便宜的模型，放在一个固定的「来信」任务里，认出归属后可以挪到对应任务。（按建议）
3. 同一个专题、不同任务之间：默认自动，可配置；不同专题之间仍然先问（见规则 3）。
4. 规则 5 里「输入框里有字」：算在等人，但只在最近 5 分钟动过输入框时算；草稿放着不动超过 5 分钟就照常送。（按建议）
5. 多方确认：先做一对一。
6. 信任：默认都信任，标了不信任的才先给人看（见上）。
