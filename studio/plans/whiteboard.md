## 用户说的（11-16，原话摘）

- 「我觉得可能更需要的是一个 board，给 ai 来做数据临时存储。ai 通过快速调整 html 的方式，直接展示这个 board 里的相关内容。他相当于是个工作白板，现在是 session 级，后面应该有 task 级。这里我们先用 2d 版试试水。」
- 「这里可以先不给人开放功能，人只是看这个白板加批注，这个批注可以加在白板上的任意位置，或者选中任意白板上的节点。」
- 一轮复杂任务是这样走的：「1，先和 ai 聊，和他确认任务内容。2，讨论推进计划，这个时候因为是复杂任务，有可能会有子 agent 调查，也可能会有 ai 给的一些建议，然后人在每条建议上给回复。」
- 「人和白板更像是一个中间数据层，这样就不是靠对话里来回翻来让人看整个内容的推进了。所以应该是一个人和 ai 一起推进的 session 推进逻辑白板。（人看白板来快速了解，ai 直接看数据结构一次就能看清。）未来遇到 ai 上下文压缩，也能通过看这些加深记忆。」

## 从这些话里定下来的

- 白板是 **AI 写的**，人不编辑，只看和批注。
- 一份数据两种读法：**人看画出来的白板，AI 读数据结构**。
- 批注有两种落点：**白板上的任意位置**，或者**选中的某个节点**。人在每条建议上的回复就是批注。
- 先做**会话级**、**2D**；任务级以后做。
- 压缩之后 AI 靠它找回前面的事。

## 第一版做成什么样

### 数据（`protocol/src/whiteboard.ts`）

Host 里每个会话一块白板（kv `whiteboard:<会话 id>`，跟着会话删；AI 自己给的页面单独一行 `whiteboard-view:<会话 id>`）：

- **节点**：`id`（AI 自己起的短名，或 n1、n2…）、`kind`（目标 / 计划 / 建议 / 问题 / 发现 / 决定 / 待办 / 备注）、`title`、`body`（几行 Markdown）、`status`（开着 / 在做 / 做完 / 不做了 / 等你）、`group`（放在哪一栏，AI 自己起名）、`after`（接在哪些节点后面，画成线）、`from`（谁给的，比如哪个子会话）、`rev`（它最后一次被改时白板的版本）。
- **批注**：`id`（c1、c2…）、落点（在节点上：`nodeId`；在节点旁边：`nodeId` 加从它左上角算的 `x`、`y`；在页面上的位置：`x`、`y`）、那里的字（`quote`，让 AI 知道指的是什么）、人写的话、状态（没发 / 已发给 AI / AI 回应了 / 关掉了）、AI 的回应。节点被拿掉后，它上面的批注留着，记下原来那个节点的标题。
- **版本号** `rev`：节点或页面每改一次加一。人看到哪一版记在 `seenRev`：节点的 `rev` 比它大，就是人还没看过的变化。

### AI 这边（MCP 工具，`features/whiteboard/mcp.ts`）

- `whiteboard_read`：全部节点和还没关掉的批注。
- `whiteboard_update`：`set` 加或改节点（带已有的 id 就只改给了的字段），`remove` 拿掉，`replies` 回应批注。一次调用改一批。
- `whiteboard_view`：画白板的那一页 HTML。不带参数读现在这一页；`html` 给整页，`edits` 改其中几处（用户说的「快速调整 html」），`reset` 回到 Studio 自带的。页面从 `window.BOARD` 读数据、定义 `renderBoard`，节点的元素带 `data-node`（约定写在 `features/whiteboard/template.ts`）。

什么时候告诉 AI（`core/whiteboard.ts` 的 `whiteboardHint`，随人的下一条消息带过去，和「脉络」同一个通道）：开白板之后一次（白板是什么、怎么用）；每次压缩之后一次（先 `whiteboard_read`）；人新写的批注（逐条：编号、在哪、写了什么）。

### 人这边（`ui/src/whiteboard`）

- 对话上方那一行多一项「白板」（「对话 | 白板 | 脉络」）。白板占对话的位置，输入框留在下面照常聊。
- 第一次点进去是「这个会话还没开白板」和「开白板」按钮；开了以后 AI 才被告知（我定的：按会话开，免得小任务也多花 token）。
- 页面在沙箱 iframe 里（只许脚本、不许联网、碰不到工作台的页面）：Studio 自带的画法按栏排卡片、`after` 画成线、状态用 ✓ ◐ ○ ! × 加字；AI 给了自己的页面就用它的，出错时能先换回自带的看。
- 批注：点一个节点 → 右边写；在任意位置点右键 → 写在那个位置（点在节点里的一小段字上，会记下那段字）。批注栏只在有批注或正在写时出现。批注攒着（我定的：不是写一条打断 AI 一次），点「把这 N 条发给 AI」（发一条只说「看一下白板上的批注」的消息）或者人自己发下一条消息时一起带过去。AI 的回应显示在批注下面；处理完了人点「关掉」。
- 没看过的变化：节点上标「有变化」，白板顶上说有几个，「白板」那一项上带点。点「都看过了」或者离开白板就算看过。

### 没做的

人直接改节点；任务级的白板；子会话的白板合进主会话（现在只能靠主会话的 AI 把子会话的结论写成节点）；白板和楼顶（没完的事）合并；远程任务的副本上看白板（那一项不显示）；手机版；节点很多时的折叠、搜索；页面位置上的批注在 AI 换了画法之后会对不上原来的地方（它记的是页面上的坐标）。

## 还要用户用过再定的

1. 按会话点「开白板」才开始，还是测试功能开着就每个会话都告诉 AI。现在：按会话开。
2. 批注攒着一起发，还是写一条立刻让 AI 看到。现在：攒着。
3. 白板占对话的位置，还是单独一个能拖走的窗口（一边看白板一边看对话）。现在：占对话的位置。
4. AI 会不会真的按提示把内容写上白板、改节点而不是只在回复里说，要多花多少 token：没验证，要用真模型试（e2e 里是模拟模型照着指令调工具）。
5. 开白板之前就在跑的会话，AI 可能要等下次启动才有这几个工具（提示里让它遇到时直接告诉人）：没验证。
