# 待办（todo list）

2026-11-01 和用户谈定的方向；同天第一版做完（第 1–3 步，388e6d4 提交，中转服务 0.7.7 已部署；进度见 `HANDOFF.md` 11-01 那条）。

## 要什么

- 类似便签的随手待办，**登录才能用**，数据在团队服务器上。
- 每台设备有自己的一张表，另有一张同账号所有设备共通的表。

## 定下来的

1. **所有表都存服务器，不是只有共通表。** 本地只是缓存 + 离线改动队列。理由：
   - 登录本来就是前提；共通表要做离线缓存、重连同步、冲突处理，设备表复用同一套几乎不花力气，只放本地反而是两条数据路径。
   - 「这台设备的待办」常要在别的设备上看、加（手机上记一条「明天在公司电脑上做」）。
   - 换电脑、重装不丢。
   - 服务器只在局域网（外面只有部分设备走 Tailscale），离线可用无论如何都得做，所以「只放本地 = 离线能用」不构成优势。
2. **设备表同账号的其他设备都能看、能改**（用户 11-01：按推荐）。和远程那边「同账号设备共享授权」一个思路。
3. **待办是便签程序里的另一个窗口**，便签窗口一点不动（用户 11-01，推翻了先前「便签里加一页切换」的草案）。
4. **待办可以绑定 Studio 的任务 / 会话**（11-02，问题 #10）：在 Studio 里任务或会话的 ⋯ →「绑定到待办…」绑，不在便签里绑；绑定只存在本机（便签的 `todo-cache.json`，按条目 id），不上服务器；Studio 开着就能绑、能跳（不限 Studio 启动的便签），只点条目后面的标签才跳。Studio 和便签之间是 Studio 连上便签的 `/api/events?client=studio`，点标签时便签在这条连接上发 `studio.open`（`app/src/notes-link.ts`）。

### 为什么是「便签程序的另一个窗口」

- 不强行融在一起：便签窗口不改，已经在用的不受影响；两个窗口能同时开，各记各的位置和大小。
- 不拆成第二个程序：托盘图标、设置窗口、版本号、平台安装和发布车道都还是便签那一份（另做一个工具 = 多一个托盘图标、多一个进程、多一条版本号和 CHANGELOG）。
- 不破坏架构约束第 1 条：便签照样不登录也能用，只是待办窗口没登录时显示「在 AMO 平台里登录」（第 7 条：登录只在平台，读 `%APPDATA%\AMO\account.json`）。
- 代价：便签程序多了网络和 `@amo-studio/account` 依赖，多一个窗口的位置 / 大小。可接受。

## 数据模型

一种数据，按「表」区分：

```
todo_lists   account, list ('shared' | 'device:<设备编号>'), device_name, updated_at
todo_items   id, account, list, text, done, order_key, created_at, updated_at, deleted_at, rev
```

- 设备编号用 `%APPDATA%\AMO\device.json` 里已有的那个（`@amo-studio/account` 的 `ensureDevice`，远程也用它），设备名跟着它。
- 删除留标记（`deleted_at`），不然离线的设备会把删掉的同步回来；标记过一段时间（比如 30 天）清掉。
- `rev`：账号级递增版本号，客户端拿 `since=<rev>` 增量拉。
- 冲突：按条、按字段后写的赢（`updated_at`，服务器时间为准）。待办很少两台同时改同一条，不做合并。
- 排序用 `order_key`（字符串分数排序），拖动只改一条。

## 服务器（中转服务里）

中转已经有账号、设备编号和 sqlite，加在 `packages/relay`：

- `GET /api/todo?since=<rev>`：本账号所有表的改动（含删除标记）和当前 `rev`。
- `POST /api/todo/ops`：一批改动 `{ device, deviceName, ops: [{ op: 'put' | 'delete', item }] }`，返回新 `rev`；按条幂等（重复提交同一条不出错）。
- 变更推送：复用设备通道（`devices.ts` 的 WebSocket）发一个 `todo-changed { rev }`，客户端收到再拉；没连上就定时拉（比如 60 s）兜底。
- 只看自己账号的；不跨账号共享（以后要做团队共用表再谈）。
- 部署走 `npm run release -- relay-service`。

## 便签程序这边

- 新开一个「待办」窗口（`packages/notes/src/main.ts` 里和便签窗口并列），自己的位置、大小；和便签窗口互不影响，能同时开。**先不做快捷键**（用户 11-01）：从托盘右键「显示待办」打开。
- 表切换：**本机**（默认）、**共通**、其他设备（按设备名列出）。新建的条目默认进当前看的表。
- 本地缓存放便签的家目录（`%APPDATA%\AMO Notes\todo-cache.json`，不放工作目录：它是服务器的副本，不是用户的文件）；离线改动排队，连上后提交。
- 换了账号登录：缓存按账号分开，不混。
- 「使用待办」关着时：不建待办窗口、不连服务器。

## 界面（草案，11-01；示意页 `todo.html`）

和便签窗口同一套样子（无边框、一色纸面、上下两条短线、Esc 收起），是另一个窗口：

- **标题栏**：待办的标记 +「待办」，右边是表：`本机`、`共通`、`其他 ▾`（下拉列同账号其他设备，带未完成数）；`Alt+1` 本机、`Alt+2` 共通、`Alt+3` 起是其他设备（和便签窗口里 `Alt+数字` 切页一个手感）。
- **正文**：最上面一行是输入行「＋ 添加待办，回车」（不画框，写在纸上）；下面是未完成的，每条一个方框 + 文字，悬停时右边出 `⋯`（移到 本机 / 共通 / 某设备、复制、删除），拖动排序；最下面「已完成 N ▸」默认折叠，完成的划线变淡。共通表里每条悬停时显示是哪台设备加的。
- **看别的设备的表**：正文顶部一条提示「这是「公司台式机」的待办，加的会出现在那台设备上」+「回到本机」。
- **底栏**：左边「N 项未完成 · 同步状态」，右边「清除已完成」。底栏不放「复制」按钮（用户 11-01：等需要时再看）；单条的复制在 `⋯` 菜单里。
- **同步状态**：`✓ 已同步` / `◐ 同步中` / `! 连不上服务器 · N 条改动待提交`（离线照样能加、能勾，连上再提交）。
- **没登录**：窗口正文居中「待办用团队账号，数据存在服务器上」+ 按钮「在 AMO 平台里登录」（平台装了就打开它，没装就提示先装平台）。
- **键盘**：`Enter` 添加；`↑↓` 移动；`Space` 勾选；`F2` 或双击改字；`Del` 删除（底栏出「已删除 · 撤销」几秒）；`Alt+↑↓` 调顺序；`Esc` 收起。
- **托盘菜单**：`显示便签` / `显示待办` / `设置…` / `退出便签`。待办先没有快捷键，只从这里打开。
- **设置**（托盘右键「设置…」，便签已有的设置窗口；用户 11-01）：
  - **能看版本号**：设置窗口标题行写「便签设置 · 版本 0.9.x（开发版 / 平台安装）」，不用滚动就能看到；便签标题栏右键「关于便签」照旧。
  - **「待办」一节，放在「快捷键」下面**：「使用待办」开关，**默认开**。关掉以后：托盘菜单没有「显示待办」，不连服务器；服务器上的数据不删，再打开时照旧同步回来。开着时下面还有：当前账号（只读，没登录时写「未登录 · 在 AMO 平台里登录」）、已完成保留几天。
- **先不做**：截止时间、提醒、子任务、标签 / 优先级。
