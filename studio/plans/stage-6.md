# 阶段 6 · 项目扩展接口

分支：`studio/stage-6`（从 `studio/main` 创建）。目标、验收和关卡见 `ROADMAP.md`：针对具体 project 接入专门的规范、流程和工具。

依据：ROADMAP 阶段 6；`docs/next-gen-vision-architecture-2026-10.md` 第 6 节（只读 MCP 包含扩展包规范）、第 7 节（扩展包的四类内容，"先预留接口，不预设具体内容"）；阶段 5 的实际结果（写自身的 MCP 工具、任务页右栏的面板结构）。

## 已确定的做法

| 项目 | 做法 | 说明 |
|---|---|---|
| 位置 | 工作区里的 `.amo/packs/<name>/pack.json`，一个目录一个扩展包 | 随工程一起进版本库 |
| manifest 格式 | JSON，不引入 YAML 依赖；带 `schemaVersion: 1` | 默认决定，可推翻 |
| 四类内容 | `docs`（规范引用）、`templates`（流程模板）、`presets`（启动预设）、`tools`（专用工具，**只预留字段，不执行**） | 与愿景第 7 节对应 |
| 路径安全 | manifest 里的路径都相对扩展包目录或工作区，拒绝绝对路径、`..` 越界和符号链接逃逸；单个文档最大 512 KB | 扩展包来自工程文件，可能是别人提交的，按不可信内容处理 |
| 不执行任何代码 | 阶段 6 只读文件：不运行脚本、不启动扩展包里的 MCP 服务 | 专用工具以后单独评审 |
| 加载 | 按需读取（打开扩展包页面、MCP 调用时），按文件修改时间缓存；页面上有"重新加载"；不做文件监听 | 一个扩展包写错不影响其他扩展包，错误显示在它自己的条目上 |
| 启动预设 | 点预设只会**预填**新会话表单（模型、提示词、上下文文件清单），由人确认后才发出 | 预设的提示词来自工程文件，不能不经人看就发给模型 |
| 上下文文件 | 提示词里列出文件路径，让 agent 自己去读；不把文件内容整段塞进提示词 | 省额度，也避免超长 |
| 流程模板 | 从模板新建任务时，任务带上步骤清单（新表，迁移 v4）；人在任务页勾选；agent 可以通过 MCP 勾选自己任务的清单项（写自身，不弹审批） | 和阶段 5"写自身"一致 |
| 额度 | 开发与 e2e 用 mock；S6-07 冒烟预计 GLM 约 4 次、DeepSeek 约 2 次 | |
| 真实扩展包 | 第一个真实扩展包的内容和所在工程由你决定（S6-09，必须等你）；loop 只用 `studio/examples/packs/` 下的示例包，并且只在沙箱工作区里测试 | 红线：不在真实工程里测试 |

## 任务

### S6-00 manifest 格式与校验 · done
- 依赖：无
- 内容：protocol 里定义 `PackManifest`（`name`、`title`、`description`、`docs[]`、`templates[]`、`presets[]`、`tools[]`），写校验函数：字段类型、id 唯一、路径安全、数量与长度上限；错误信息写清楚是哪个字段。格式说明写进 `design/pack-format.md`。
- 验收：单测覆盖正确的 manifest、各类错误、路径越界（`..`、绝对路径、盘符）。符号链接要读文件系统，放在 S6-01 的 Host 加载里检查。

### S6-01 Host 加载扩展包 · done
- 依赖：S6-00
- 内容：扫描工作区的 `.amo/packs/*/pack.json`；接口 `GET /api/workspaces/:id/packs`（列表，含每个包的错误）、`GET /api/workspaces/:id/packs/:pack/docs/:doc`（读一篇文档，限大小）；按修改时间缓存。
- 验收：接口单测（正常、manifest 写错、文档缺失、超大文档、越界路径、同一工作区多个包）。

### S6-02 工作台显示扩展包 · done
- 依赖：S6-01
- 内容：
  - 左栏选中工作区时，可以打开这个工作区的"扩展包"页面：列出扩展包；文档用现有的 markdown 渲染查看；列出流程模板和启动预设；manifest 有错时显示错误；
  - 任务页右栏加"规范"面板：任务所在工作区的扩展包文档链接，点开在任务页内查看。
- 验收：e2e 与截图。

### S6-03 流程模板 · done
- 依赖：S6-01
- 内容：新任务页可以选择"按模板"：带上模板的标题前缀和步骤清单；Store 迁移 v4 加任务清单表；任务页显示清单，人可以勾选；看板卡片说明行显示"清单 2/5"。
- 验收：Store 与接口单测；e2e。

### S6-04 启动预设 · done
- 依赖：S6-01
- 内容：任务页"新会话"和看板卡片上可以选扩展包里的启动预设：预填模型、提示词（支持 `{{task.title}}`、`{{workspace.path}}`、`{{pack.dir}}` 三个变量）和上下文文件清单；人确认后才创建会话。预设指定的模型不存在时，回退到默认模型并提示。
- 验收：单测（变量替换、模型回退、上下文文件越界被拒）；e2e。

### S6-05 MCP 读取扩展包 · done
- 依赖：S6-01、S6-03
- 内容：只读工具 `pack_list`（某个工作区的扩展包：文档、模板、预设的目录）、`pack_doc`（读一篇文档）；`task_get` 带上任务的清单；写自身工具 `checklist_check`（勾选自己任务的清单项，不弹审批）。
- 验收：MCP 单测；mock 会话里调用。

### S6-06 示例扩展包与验收 · done
- 依赖：S6-02～S6-05
- 内容：`studio/examples/packs/demo/`（虚构内容：一份规范、一个流程模板、一个启动预设，`tools` 里有一条预留项）；e2e 把它复制进沙箱工作区，走通：加载 → 查看规范 → 按模板建任务 → 按预设启动会话 → agent 用 MCP 读规范并勾选清单。
- 验收：e2e 与截图 `screenshots/stage-6/`。

### S6-07 真实冒烟 · done
- 依赖：S6-06
- 内容：沙箱工作区放示例扩展包；GLM（Claude 会话）和 DeepSeek（Codex 会话）各自按预设启动，用 `pack_doc` 读规范、用 `checklist_check` 勾一项。
- 验收：结果写进 `spikes/results/s6-07-smoke.json`；计入额度。

### S6-08 阶段验收与收尾 · done
- 依赖：S6-00～S6-07
- 内容：`LOOP_RULES` 第 6 节收尾；"请你过目"附截图、示例扩展包和写扩展包的方法。

### S6-09 【必须等你】第一个真实扩展包的内容 · 等你（已写入 NEEDS_YOU）
- 内容：写入 NEEDS_YOU（必须等你）：第一个真实扩展包放在哪个工程、包含哪些规范、流程和预设（例如"武器逻辑开发"）。loop 不会自己往真实工程里写文件；等待期间继续后续阶段中不依赖它的部分。
