# 安卓版：手机上能用的一版（问题和改法）

2026-10-31。用户在真机上装了 0.1.2、配好了 B，能看到任务，但「几乎不能用」，要求完整过一遍界面和功能，手机上能用基础功能，保持 AMO 风格但专门为手机适配。这份是评审结论和改法，等用户定了再动手。

**进度（2026-11-01）**：用户定了「可以放弃完全重写，按方便实施来」。四步一次做完，出了 0.2.0：连接和协议层保留，数据层和界面重写。未按原文做的地方：Markdown 没用 CommonMark 库（离线环境没有），自己写了块级解析；会话「重命名、归档」没做（`rt.*` 没有这两个命令）。验证见 `HANDOFF.md` 2026-11-01 那条。

依据：读了 `studio/android/app/src/main/java/dev/amo/studio/` 全部代码（StudioUi、ChatUi、FileUi、StudioRepository、AmoTheme），看了 `studio/screenshots/android/` 的截图，对照了 `packages/protocol/src/entities.ts` 的会话条目类型。已有的截图都来自 mock 夹具（一两条消息），真实会话的样子没有截图；下面「卡」的判断来自代码，**没有在真机上测过**。

## 一、问题

### A. 卡、慢（最可能是「几乎不能用」的主因）

1. **每来一个字就把全部缓存重新序列化一遍，在主线程上。** `push()` 和 `fetchTask()` 最后都调 `saveCache()`：它把所有任务快照、所有会话的历史（每个会话最多 2000 条，工具输出单条可到 300 KB）拼成一个 JSON 字符串，这一步在主线程同步做，只是写文件延迟 300 ms。模型流式回复时每个 delta 都触发一次，真实会话里就是每秒几十次几 MB 的序列化。超过 8 MB 时它直接不存，缓存从此失效，也不提示。
2. **打开会话总是从第 0 条下载全部历史。** `fetchItems()` 每次都 `since = 0`，一页最多 400 条或 600 KB，一直翻到底。打开会话、发一条消息、审批一次、断线重连、回到前台，都会再整段下载一次。手机走 Tailscale 时，长会话打开要很久。
3. **连接一有动静就把所有任务重拉一遍。** 别的设备上线下线（`presence`）、回到前台（`refresh`），都会触发 `syncAll()`，按顺序对每个授权任务发一次 `rt.task`，每次最长等 30 秒。
4. **对话列表每次变化都整页重组。** 条目是 `JSONObject`，Compose 认为它不稳定；流式回复时每个字都让所有可见条目重新组合，Markdown 也重新解析。delta 每次还要把整条 JSON 转成字符串再解析一遍。

### B. 结构：手机上最常做的事要点太多次

5. **每次打开都从「已配对的电脑」开始**，要点四层（电脑 → 任务 → 会话 → 对话）才能回到刚才那个对话。只配了一台电脑也要先选电脑。
6. **看不出哪里在等你。** 手机最主要的用途是离开电脑时审批、回答模型的问题、看进度，但任务列表只有标题，会话列表只有一行状态文字，没有一个地方汇总「等你审批 / 等你回答」。
7. **任务列表没有状态和顺序。** 只显示标题（加描述），不显示有没有会话在跑、最近什么时候动过，也不排序（谁最后拉到谁在最后）。
8. **会话列表是平铺的。** 子代理（`sub`）、分支（`fork`）、归档的会话和主会话混在一起，标题是第一句话，看不出层级。
9. **「新建任务 / 新建会话」是列表顶上的大块深色按钮**，占地方，滑下去就找不到了。

### C. 对话页：真实会话读不下去

10. **工具调用一条一行，一轮几十行。** Claude 一轮常有几十次工具调用，每次都是一行「▸ 摘要 completed」，正文被淹没。状态是英文原文（completed、inProgress、failed）。桌面会把一轮里的操作收成一行，手机没有。
11. **Markdown 渲染太简陋。** 自己按行解析：代码块每一行单独一条底色、长行折行，有序列表、斜体、引用块、标题层级都没有；表格每列固定 160 dp；链接只认 `[文字](地址)`。模型的回复大多是 Markdown，读起来很吃力。
12. **很多条目类型没有专门显示。** `subagent`、`notice`、`compaction`、`command`、`error`、`background`、`suggestion` 都走「兜底」，只显示一段文字；子代理不能点进去看。
13. **输入区太高，「中断」常驻。** 输入框最少两行，下面还有一排「中断」和「发送」，约 170 dp；键盘弹起后，对话只剩一小块。「中断」不管会话在不在跑都在那里，容易误点。
14. **看不出模型在不在干活。** 对话页顶上没有会话状态，没有「正在回复…」，也没有「回到最新」按钮；往上翻看历史时，新消息来了没有提示。
15. **审批卡不好用。** 「允许」「拒绝」两个大按钮上下排，命令是原样的一大段文字，处理完显示英文状态（accepted、declined）。
16. **改了哪些文件看不到。** 工具调用改的文件只列路径，点开是文件当前内容，看不到改动。

### D. 视觉：桌面表单搬到了手机上

17. 顶栏是文字按钮「返回」+ 衬线大标题 + 文字「设置」，标题经常被截断；没有手机上习惯的返回箭头和溢出菜单。
18. 主要操作都是 48 dp 高的深色方块按钮，列表是带边框的卡片，一屏放不下几项。
19. 出错时红字插在内容顶上，把页面往下挤；连接状态也是插一行文字。
20. 用的是 Material3 默认组件加 AMO 的颜色。颜色和字体对了，但整体还是「Material 表单」的样子，不像 AMO。

## 二、怎么改

原则：**手机上只把「看进度、回消息、审批、回答、开新会话」做顺手**，其余照旧不做（批注、书签、画布、终端等）。风格沿用桌面的颜色、字体、小圆角、细边线和状态点，布局按手机重排：主要操作放在拇指够得到的底部，次要的收进底部弹出面板。

### 第 1 步：先解决卡和慢（不改界面）

- **缓存**：按会话分文件存，只存变了的那个会话，放到后台线程做，流式回复结束（或每 2 秒）才存一次。超过上限就丢最旧的会话，不再整体放弃。
- **历史增量拉取**：打开会话时先显示缓存，再从缓存里最后一条的 `seq` 往后拉（`rt.items` 本来就支持 `since`）。只在重连后重新核对审批这类「没有新 seq 也会变」的条目：只重拉最近一页。
- **任务快照**：`syncAll` 只在连上、回到前台时跑，几个任务并行，同一时间只跑一次；`presence` 只刷新在线状态，不重拉任务。
- **对话列表**：条目先转成不可变的 Kotlin 数据类，Markdown 解析结果按条目缓存，流式回复只重组正在变的那一条。

验收：用真实规模的会话（几百条、有长工具输出）在模拟器上测流式回复时的帧率和打开时间；手机上走 Tailscale 再测一次（要你的手机）。

### 第 2 步：结构（打开就是你要的）

- **首页改成「工作台」**：顶部一块「等你处理」（各任务里等审批、等回答的会话，点进去直接到那条）；下面是任务列表，按最近活动排序，每行显示状态点（在跑 / 等你 / 空闲 / 出错）、在跑的会话数、最近时间。多台电脑时用顶部的电脑切换器筛选，只有一台时不出现。
- **打开应用回到上次的对话**（可在设置里关掉）。
- **任务页**：会话按主会话列出，子代理和分支缩进挂在主会话下面，默认收起；归档的收进底部「已归档 N 个」。
- **新建**：任务列表和会话列表右下角一个浮动的「+」，点了从底部弹出面板：选模型、写第一句话，任务还要选项目和主题。

### 第 3 步：对话页（重做）

- **顶栏**：返回箭头、会话标题（一行）、下面一行小字写状态（「正在回复」「等你审批」「空闲」），右边一个「⋯」菜单：新会话、重命名、归档、打开任务的文件。
- **一轮里的工具调用和思考收成一行**：「12 个操作 · 2 个改了文件 · 1 个失败」，点开是列表，再点一条看输入输出。失败的、等审批的不收起。状态用中文加状态点。
- **Markdown**：换成完整的渲染（代码块整块、可横向滚动、等宽字体；有序列表、引用、标题层级、表格自适应列宽）。可以用 CommonMark 解析库，在后台解析后缓存。
- **专门显示的条目**：子代理（一行摘要，点了打开子会话）、提示和错误（小条，不占大块）、上下文压缩（一行）、命令输出（收起的代码块）。
- **输入区**：一行起，最多 6 行自动长高；发送按钮在输入框里面右下角。会话在跑时发送按钮变成「停止」，不跑时不出现「中断」。
- **回到最新**：往上翻时右下角出现「↓ 新消息」。
- **审批卡**：命令用等宽字体，太长就收起成三行可展开；「拒绝」「允许」两个按钮并排放在卡片底部，允许是主色。处理完写中文结果（已允许 / 已拒绝 / 在别处处理了）。等你处理的审批和问题，在对话底部输入框上方钉一条，不用翻找。
- **改了的文件**：先做到点开看这次的改动（工具条目里已经带了 `files` 的 diff），按手机宽度只做上下对照，不做左右对照。

### 第 4 步：视觉统一

- 自己写一套小组件代替 Material 默认的：顶栏、列表行（标题 + 状态点 + 一行灰字 + 右侧时间）、底部弹出面板、主按钮 / 次按钮、提示条（错误和连接状态都改成底部的小提示条，自动消失或可关）。
- 颜色、字体照桌面的 `base.css`、`chat.css`；圆角 2–4 dp；列表行之间用细线分隔，不用每行一个带框卡片；触控区不小于 48 dp，但视觉上不做那么大。
- 浅色、深色、窄屏（360 dp）、大字体（1.3 倍）、横屏各截一套图核对。

### 不在这一版

- 后台推送通知（手机在后台时收到「等你审批」）：要常驻前台服务，耗电，也要服务器配合。第 2 步的「等你处理」先解决「打开就知道」，通知等这一版用一阵子再定。
- 发图片和附件、左右对照看改动、桌面 Markdown 的扩展（Mermaid、数学公式）。
