# relay-in-sessions：会话里直接用 AMO 中转（方案草稿，2026-10-29，排在远程会话做完之后）

## 起因

用户 10-29：想让会话（Studio 里的和终端里的）能直接通过 AMO 中转发聊天消息、发审批请求（策划的 AI 卡住或方案要程序把关时发会话找人确认），对方回复后最好自动回到对话里接着做。Claude、Codex、DSH 都要支持。

## 现状（10-29 查的）

- Studio 会话自带 Studio 的 AMO MCP（看板、任务、子会话、画布、专题文档等）。其中 `relay_send` 是 **Studio 内部的「传话」**（转给同专题另一个任务的会话），和 AMO 中转无关，名字撞了，模型容易混。
- AMO 中转的「接入 AI」不配 MCP：复制一段提示词，让 AI 运行 `amo-relay.cmd prompt` 按说明用命令行。用户的 Claude Code 全局没配 MCP，Codex 也没有中转的 MCP。
- 10-28 定的卡点流程：AI 发完会话就结束这一轮，回复在中转「待我处理」里，人点「复制给 AI」贴回去。

## 打算

1. **Studio 的 `relay_send` 改名**（比如 `task_message`），说明写清是给 Studio 里另一个任务的会话传话。
2. **Studio 会话加中转的工具**：发聊天消息、发审批请求（会话）、查回复。登录用平台存的（`AGENTS.md` 约束第 7 条）；Studio 的 Host 连中转服务（远程会话第 1 步已经让 Host 连上了，复用）。
3. **回复自动回到对话（只有 Studio 里的会话能做，Claude / Codex / DSH 都行）**：Host 记下请求是哪个会话发的；对方回复后，Host 把回复作为一条消息发回那个会话（空闲就开新一轮，正在跑就排到这一轮后面），像委派会话的 `report` 那样。
4. **终端里的会话（指定文件夹，不做全局）**：Studio 设置里「在文件夹里启用 AMO MCP」，替用户执行 `claude mcp add --scope local …`（只对这个文件夹生效，不进 git）；配置里只写一个转接命令（比如 `amo-mcp.cmd`），令牌由转接命令运行时从数据目录读，不写进配置。终端会话的工具：发聊天消息、发审批请求、查回复。回复**不能**自动塞回终端会话（外面没法让 CLI 开新一轮）；可选的补充：Claude Code 的 hook 在每轮结束时检查回复（只有 Claude 有）。Codex、DSH 按文件夹配 MCP 的方式要查（Codex 的配置主要是全局的 `~/.codex/config.toml`，不确定）。
5. 要回复自动回到对话，就在 Studio 里跑；Studio 已有「在终端打开」和收回，两边能切换。
