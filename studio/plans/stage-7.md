分支：`studio/stage-7`（从 `studio/main` 创建）。目标、范围和关卡见 `ROADMAP.md`：调度 agent 定期查看绑定了工作区的分组是否空闲，认领待办并开出会话，开工前交给人批准。

依据：ROADMAP 阶段 7；`docs/next-gen-vision-architecture-2026-10.md` 第 9 节（"调度 agent 定期检查空闲的工程，认领待办并开出会话，开工前交给人批准"）；`design/interaction-notes.md` 画布一节（待办"转为任务"、任务放进绑定了对应工作区的分组；"交给调度 agent"）；阶段 3 的整体待办和分组绑定工作区，阶段 5 的请求决策与审批卡片，阶段 6 的启动预设。

## 关卡怎么处理

ROADMAP 规定阶段 7 是"必须等你：开工前确认调度权限与频率"。我的理解和做法（请你过目，可推翻）：

- **在你回复之前**，只做**不会自己调用模型**的部分，以及**由你手动触发一次**的部分；
- **定时自动运行**调度 agent 的部分（S7-06）等你回复后才做，在那之前代码里也不会有定时器；
- 写入 NEEDS_YOU（必须等你，S7-09）：能否定时运行、多久一次、用哪个模型、每次最多提几条、批准后是否立即开工。

## 已确定的做法

| 项目 | 做法 | 说明 |
|---|---|---|
| 工程空闲 | 一个工作区"空闲"= 这个工作区里没有未归档的会话处于运行中、待批准、待审阅，也没有会话在终端里。绑定了工作区的画布分组显示"空闲 / 忙碌" | 纯函数放在 protocol，规则写进 `design/scheduler.md`；以后可按你的习惯调整 |
| 待办转任务 | 人点"转为任务"：在待办的工作区建任务（没指定工作区就让人选），放进绑定了这个工作区的分组（有多个时放第一个，没有就放未分组），待办记下 `taskId` 并标为完成 | interaction-notes 已写 |
| 调度提案 | 调度 agent 只能**提出**"用哪个待办、在哪个工作区、用哪个模型和提示词开一个会话"；提案显示在工作台和 Focus，**人批准后 Studio 才建任务和会话**；拒绝就作废 | agent 自己不建会话，不等于"派发"（S5-10 仍然不开放） |
| 调度 agent | 一个普通的 Studio 会话，放在一个固定的跨工作区任务"调度"里，过程全部可见；比普通会话多一个工具 `schedule_propose`，只有这个任务里的会话能用 | 运行时用现有的 Claude（GLM）或 Codex；不新增运行时 |
| 触发方式 | 在你回复 S7-09 之前，只能由人点"让调度看一次"手动触发一轮 | 定时运行等你决定 |
| 提案上限 | 每轮最多 3 条，重复的（同一个待办已有未处理提案）拒绝 | 防止刷屏 |
| 额度 | 开发与 e2e 用 mock；S7-07 冒烟预计 GLM 约 4 次、DeepSeek 0 次 | |

### S7-03 调度提案的数据与审批 · done
