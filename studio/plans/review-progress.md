# 审阅进度：看到哪了、审过没有（2026-11-15）

> 状态：进行中（先做对话这一块）。11-15 和用户谈的；11-16 用户用过脉络之后：「我再想更新需要的功能是之前说的那个审核，阅读看到哪然后标记上。我们可以在会话里加上（脉络的单轮会话弹窗我觉得应该是都用的同一份逻辑，所以我认为自动加上了）」——对话里每一轮的 没看 / 浏览过 / 审过 先做，脉络的会话弹窗用的是同一个对话，自动带上；文档、查看包那几块照下面的顺序以后做。用户说它和交流框架（`plans/collab-framework.md`）这一轮关系不大，但后面调整代码时可以一起做。

## 第一版做了什么（11-16，测试功能「审阅进度」，只管对话）

- 一轮按它的最终回复记（回复那一行的 id）；过程里的中间回复不单独算；还在写的不算。
- 浏览过：回复末尾（页脚那一行）在对话可见区域里累计约 1.5 秒，窗口有焦点、页面可见才记；对话被脉络的楼盖住时不记。攒 1 秒一起报给 Host。
- 审过：只能人点。平时只有值得审的回复末尾有按钮：回复本身高过对话可见区域，或那一轮有审批、提问（含 `decision_request`）、文件改动、`view_open` / `review_open`。审过的显示「✓ 审过」，点一下撤回。
- 复盘：对话右上角的「复盘」。每条回复都显示状态和按钮，没审过的整轮变色，顶上一条写还有几条没审、「下一条没审的」（到底从头再来，没画出来的轮次先展开）、「到这里为止都审过」。
- 存在 Host：kv `review-progress:<会话 id>`，跟着会话删；`GET|PUT /api/sessions/:id/review-progress`；远程副本的进度留在看的这台电脑上。
- 脉络的会话弹窗是同一个 Thread，不用另做。

做的时候自己定、用户还没看过的（用过再改）：

1. 撤回「审过」退回的是「浏览过」，不是「没看」（点得到按钮说明看过）。
2. 「复盘」按钮上不写数字，还有几条只在悬停提示和复盘顶上写（平时少一样显眼的东西）。
3. 「超过一屏」量的是回复本身，不是整轮（整轮的高度随折叠变）。
4. 复盘换会话就退出，不按会话分别记。
5. 复盘的颜色铺满整轮，人的那条消息也在色块里。

没做的：长文档按节记；查看包、Git 改动的「已看」；回复里的批注卡片；人中途回复时带上进度；任务卡 / Focus / 脉络上显示进度；审过之后内容变了退回没看。

没验证的：窗口真的失了焦点时不记浏览过（e2e 里是改写 `document.hasFocus` 模拟的：Electron 里 `BrowserWindow.blur()` 之后页面的 `hasFocus()` 仍然是 true）；几百轮的长会话里的性能；远程副本上实际用一遍。

## 起因（用户 11-15）

长文档比如有 5 页，可能刚看了 1 页半就被叫走。人的审核应该是：收到 → 开始审 → 标出看到了哪里 → 都看完了标记看完。现在没有这种记录（批注、书签、查看包都不记阅读进度）。

## 用户定的（11-15）

- **续读自动记，看完由人点**：被叫走的那一刻不会记得去点标记，所以「看到哪了」自动记；「看完了」是一句 AI 会据此往下做的话，由人明确点。
- **浏览过不等于审过**：有时只是想快速浏览一遍，不认为它算审完。所以是三种状态：没看 / 浏览过 / 审过；滚过去最多算「浏览过」，「审过」只能由人点。
- **对话里每一轮有自己的按钮**：别的回复发过来，可能让某一条没看完就被顶走了，所以审没审过要记到每一轮上，不能只记一条「看到这里」的线。
- **复盘时一眼看出哪些没审**：开始审核 / 复盘时，没审过的变色，审过的点一下；这样一眼看到哪些没审过。

## 做法（用户 11-15：按建议来）

### 三种状态

| 状态 | 怎么来的 | 平时的样子 | 复盘时的样子 |
|---|---|---|---|
| 没看 | 默认 | 不显眼 | 变色（最显眼） |
| 浏览过 | 在屏幕上停过（窗口有焦点时），自动记 | 不显眼 | 变色（淡一档） |
| 审过 | 人点的 | 一个小勾 | 正常色 |

记在什么上：

- **对话**：每一轮（AI 的一次回复）一个状态，回复末尾一个「审过」按钮。
- **长文档**（查看器里的 Markdown / HTML）：按标题分节，每节一个状态；另外自动记「上次看到这里」，再打开落在那条线上。
- **查看包**：每个条目一个状态。**Git 改动**：每个文件一个「已看」勾。

### 复盘模式

平时这些标记很淡，不给对话添乱。点「复盘」（或从「等你审」的卡片进来）以后：

- 没审过的整块变色，审过的保持原样；点一下就是审过。
- 顶上写「还有 N 条没审」，带「下一条没审的」。
- 「到这里为止都审过」：在某一轮上点，前面的一次标完，不用一条条点。
- 以后 v7 的楼可以直接用它：楼层 = 轮，没审过的楼层亮着。

### 几条细的

- 按内容记，不按滚动位置记：AI 常在两次看之间改文档；按段落内容记，标记跟着走，还能标出「这一节在你审过之后改了」（改了就退回「没看」）。批注已经是跟着文件内容走的，用同一套办法。
- 存在 Host 里，不存浏览器本地：卡片、Focus、脉络上才显示得出「没开始 / 看到 2/5 / 审完」。
- 人中途回复时带上进度：消息里附一句「人审到第 2 节为止」，免得 AI 把没提到的后几节当成默认同意。
- 在交流框架里：「等你审」是一件事项，进度是它上面的字段；进度变化是板上的状态，不叫醒 AI，人点「审完」或发回复时才发消息。可以在转「审批、提问」那一步时顺手带上。

## 顺带：回复里直接看到原批注（用户 11-15 提；做法按建议来）

用户：AI 针对批注回复时，回复里最好能直接看到「批注 x」的内容，横排卡片或别的样子，方便快速看到原批注是什么。

现在有的：批注在会话里有编号，发出去的消息是固定格式（`protocol/src/api.ts` `REFS_HEAD`、`splitAnnotationRefs`），人自己那条消息里已经渲染成一块（`ui/src/task/ThreadParts.tsx` `anno-refs`）。所以 Studio 知道每个「批注 N」的原文和人写的话，缺的只是在 AI 的回复里认出「批注 N」并显示出来。

建议：

- **标题下一张横排卡片**：回复里某个标题（或段首）提到「批注 N」，就在它下面放一张矮卡片，左半是被批注的原文（最多两行），右半是人写的批注（最多两行），点开看全文、能跳回原处。
- **正文里零散提到的**「批注 N」变成一个小标签，悬停出同一张卡片（不占版面）。
- **回复顶上一行核对**：这条回复回应了哪几条、**哪几条没被提到**（Studio 拿人发出去的编号和回复里出现的编号一比就知道）。
- 送批注给模型的那段话里加一句「回复时按『批注 N』逐条对应」，让卡片认得稳；认不出时就不显示，不猜。
- 和上面的审阅进度是一回事的另一面：一条批注也有「提了 / AI 回了 / 人认可了」的状态，复盘时可以列出还没认可的批注。

## 原来没定的几件（用户 11-15：都按建议来）

1. 开始审：从「等你审」的卡片点开就算开始，不单独点。
2. 全部审过之后：只标状态，等人另外回复；不自动告诉 AI「人审完了，没有意见」。
3. 经中转发给同事审的文档：先不让发起方看到对方的进度。
4. 所有轮都有状态，但平时只有超过一屏、或带审批 / 提问 / 文档的那些回复显示「审过」按钮；复盘模式里全部显示。
5. 回复里的批注卡片放在标题下面，不放右侧（对话这一栏不宽）。
