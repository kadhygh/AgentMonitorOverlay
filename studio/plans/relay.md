# AMO 中转（Relay）· 让 AI 会话找人确认（2026-10-26）

## 为什么

策划和 AI 推进案子时，常有要程序确认的问题。现在的做法：策划提交一轮到 Git → 程序看提交、审批 → 再回给策划，很麻烦。
要一个中转工具：**AI 会话直接发一条「请求」给某个人，对方在自己的面板上看到、逐条回答，回复回到发起方。**

先作为独立程序做在 AMO 仓库里（同便签、Reviewer 的做法），跑通后再考虑并进 AMO Studio。

## 已定（用户 2026-10-26）

- 传输：**局域网中转服务**（HTTP + WebSocket），不走共享文件夹 / IM / Git。
- 范围：**同一局域网的小团队**（几到十几人）；身份 = 名字 + 团队口令，不做公网、不做账号体系。
- AI 客户端：每个人用的都不一样（Studio、Claude Code、Codex……）→ **以 MCP 为主**，一个独立的 stdio MCP 服务，任何支持 MCP 的客户端都能接。
- 回复形式（第一阶段）：**逐条回答 + 自由文字 + 结论**（同意 / 需要改 / 有疑问）。行批注放第二阶段。
- （补充）**人和人之间也能直接发内容**（普通聊天）；**聊天记录存在服务器上**，换电脑、重装托盘程序都还在。

## 数据

- **对话（thread）**：两种。`direct`：两个人之间的私聊，每对人只有一个；`request`：每条 AI 请求单独开一个对话，标题就是请求标题，之后的回复和追问都在里面。
- **消息**：`text`（普通内容）/ `request`（正文 + 问题列表）/ `reply`（逐条回答 + 补充说明 + 结论）。每条都记作者，以及是本人发的还是 AI 代发的（带客户端名，比如 Claude Code）。
- 消息按服务器全局序号排；每人每个对话记一个已读位置，未读数从这里算。
- 身份：第一次用名字加团队口令加入，服务器发一把个人钥匙存在本机设置里，之后的请求都带着它。名字不能重复。

## 组成

```
AI 客户端 ──stdio──▶ relay MCP ──HTTP──▶ 中转服务 ◀──HTTP/WS── 托盘程序（每人一个）
                    （读本机身份）        （存请求和回复）          收件箱 / 发出的 / 回复
```

1. **中转服务**（`packages/relay`，Node，`node:sqlite`）：成员、请求、回复、已读状态；WebSocket 推送「有新请求 / 有新回复」。
   默认由某个人的托盘程序在设置里打开「在本机开启中转服务」，也能无界面单独跑（放在公用机器上）。
2. **托盘程序**（AMO 中转）：单实例、托盘图标、新消息时托盘气泡提醒。窗口里两栏：**收到的**（待我回答）和 **我发出的**（等回复 / 已回复）。
   发出的请求收到回复后有「复制回复」（格式是给 AI 读的），网页版聊天的人也能用；也可以手动新建一条请求，把内容贴进去。
   设置：我的名字、服务地址、团队口令，以及是否在本机开服务。保存在 `%APPDATA%\AMO Relay`。
3. **relay MCP**（同一个包里的 stdio 入口）：读本机托盘程序的设置拿到身份和地址。
   - `relay_people`：能找的人（名字 + 角色说明，如「程序-战斗」）。
   - `relay_ask`：to、title、body（Markdown）、questions[{id, text, options?}]，返回请求 id。说明里要讲清楚：请求发出就返回，不要干等。
   - `relay_replies`：按 id 或「我发出的、新的回复」取回复，带上逐条回答、补充说明和结论。
   - `relay_wait`（可选）：最多等 N 分钟，受客户端工具超时限制，所以只当作辅助。

## 阶段

1. **最小闭环**：服务 + 托盘程序 + MCP；内容只有 Markdown 正文和问题。本机两个身份互发也能测（e2e 起一个服务、两个客户端）。
2. **接上 Reviewer**：请求里带**快照**，就是把文件内容、重点行、diff 打包进请求。程序那边打不开策划没提交的文件，所以查看包要能做成快照。程序在 Reviewer 视图里写行批注，批注作为回复的一部分发回去。
3. **回到会话**：Studio 管的会话收到回复后自动接回去；外部客户端照旧用 `relay_replies`，或者复制回复。
4. 以后：程序让自己的 AI 先起草回复、一个请求发给多个人、并进 AMO。

## 补充（用户 2026-10-26）

- **一键复制用法 prompt**：推进中随时粘给任何 agent，让它知道怎么用。文字只在 `usage.ts` 一处生成，托盘的「复制用法」、`amo-relay prompt` 和 MCP 的 instructions 都用它。
- **中转服务跑在 Mac 上**：服务只用 Node 自带的模块加 ws，打包成单个 `amo-relay.mjs`（`npm run relay:bundle`），要求 Node 22.13 或更新；Mac 上的部署和 launchd 写在 `packages/relay/README.md`。托盘程序跑在每个人自己的机器上，目前是 Windows。

## 补充（用户 2026-10-26 下午）：先在本机部署，出一个能直接跑的客户端，发链接给同事一起测

- **账号密码**：注册时填名字、密码，以及负责什么；服务带邀请口令时还要填口令。登录后每台设备拿一个 key。客户端会**记住账号和密码**：密码用系统加密保存（Windows 上是 DPAPI，Mac 上是钥匙串），登录页可以选已存的账号。
- **热更新整个客户端**：界面放在服务器上，由 `relay-ui` 构建；桌面外壳固定不变。启动顺序：
  1. 读条；
  2. 连接服务器并检查版本；
  3. 第一次打开时下载界面；有新版本时，在读条里直接装好；
  4. 进入登录页。
  运行中**自动更新**（10-26 用户问「能自动更新吗」后改的）：发布后，服务会在 5 秒内通过 /ws 推送 `client` 事件；登录页则从 `/api/health` 读到新版本。客户端在不会丢东西的时候自己更新：登录页上要求还没动过表单；登录后要求窗口没在用（在托盘里、最小化了，或者没有焦点，由外壳的 `inUse()` 判断），并且没有草稿和打开的对话框。更新就是重新载入窗口，登录状态和当前打开的对话都会保留（sessionStorage）。条件不满足时，左上角显示「有新版本 · 不用时自动更新」和「立即更新」按钮。外壳本身变了的话，会提示重新下载。
- **更新桌面程序**（10-27 用户说「单独写个更新专用的界面，这样就不用单独下载再重新解压了」后加的）：
  - `relay-release --shell` 给外壳盖上构建号（`dist/build.json`），并在 zip 旁写 `downloads/AMO-Relay-win.json`（构建号、大小、sha256）；`/api/health` 的 `shell` 字段带上它。
  - 外壳构建号和服务上的不一样时，顶栏和登录页出现「桌面程序可更新」，点开是单独一页（`ShellUpdate.tsx`）：现在 → 新版、「更新并重启」、进度（下载 / 校验 / 解压 / 换文件 / 重启）。
  - 外壳自己做（`updateShell`）：下载到 %TEMP%，校验 sha256，用系统的 `tar.exe` 解压，**只换内容有变化的文件**（正在运行的文件先改名成 `…amo-old-<时间>`，再放新文件；出错就全部还原；下次启动时删掉旧文件），然后 `app.relaunch` 带原参数重启。日志在数据目录的 `update.log`。
  - 为什么这么做：靠一个比程序活得久的脚本来换文件不可靠（父进程退出时 Windows 可能把子进程一起结束，WMI 起进程在这台机器上也不执行）；整目录 3757 个文件逐个换会在中途被结束（原因没查清，同步、异步都一样），而两次构建之间通常只有程序自己的 JS 变了，exe 和 DLL 不变。新版连 Electron 本体（`resources\` 以外的文件）也变了时不在运行中换，提示手动换一次。
  - 没有 `updateShell` 的旧外壳只显示手动换的三步。
  - 验证：用打好的包实测过（旧构建号 → 新版，换 1–2 个文件，退出码 0，带 `--server` 参数重新打开，旧文件下次启动时删掉）。
- **服务器状态**（同一天加的）：登录页显示「服务器在线 · 地址」；连不上时显示「! 服务器离线」，带离线时长、几秒后自动重试（每 5 秒一次）、「立即重试」和「换一个地址」，登录按钮不可用。登录后，名字旁边显示「在线 / 连接中 / 离线」。断开超过 1.5 秒，对话上方出现一条提示，写着断开多久、几秒后重连，并有「立即重连」按钮；这时成员的在线状态显示为未知。服务每 20 秒发一次 tick，客户端超过 45 秒没收到任何消息就判定断开，所以服务所在的电脑睡眠或断网也能发现。读条阶段连不上时，也每 5 秒自动重试。
- **布局改版**（10-27 用户说顶栏「过于紧凑」，要设置入口放左下、字体大小可调、团队流程 HTML 要有快捷入口；设计画布 https://claude.ai/artifact/LdMYwi6E1GCz72qgQCECmm 确认后做的）：
  - 顶栏只留图标、团队名、四个视图和「＋ 新会话 / 新任务」，56px 高。
  - 左栏底部（`SideFoot.tsx`）从上到下：提示条（服务器离线 → 有几件等我处理 / 没有等我的 → 有新版本、桌面程序可更新，点了直接去处理）；「团队流程」「流程速查」「复制用法」；我的头像、名字、服务器状态和齿轮「设置」。原来对话上方的断线提示条、顶栏的「更多」菜单都去掉了。
  - 设置（`Settings.tsx`）左侧分四页：通用（字体大小 13–16、主题，只影响本机，存在 localStorage）、团队流程（全队共用，点保存生效）、接入 AI、我的资料（含退出登录）。字体大小改的是 Studio 的 `--fs-*` 变量，各级字号保持原来的差距。
  - **团队流程文档放在服务器上**（用户：「默认都读服务器，然后有人定期维护更新即可」）：文件表加 `slot` 列，`slot = "flow"` 的文件不属于任务或会话，全队都能看，谁都能传新版本，版本号不看文件名连续往上记；`/api/settings` 带上 `flowDoc`（最新一版）。传了新版本，别人的「团队流程」上出现「有更新」，打开后消失（记在本机）。
  - 团队可以勾选「允许这份文档运行自己的脚本」（`flowScripts`，默认开），只对这份文档生效，其他 HTML 仍默认不运行。运行脚本时在文档里注入一小段代码，把 `navigator.clipboard.writeText` 和 `execCommand("copy")` 转给客户端去复制，因为沙箱里的页面拿不到剪贴板。
  - 「写给 AI 的流程」的文字版仍然保留，复制用法和任务提示词里用的是它。
- 下载页 `/`：发给同事的链接。上面有 Windows 客户端的 zip，也可以直接在浏览器里用（`/app/`）。
