# AMO 中转（Relay）· 让 AI 会话找人确认（2026-10-26）

## 为什么

策划和 AI 推进案子时，常有要程序确认的问题。现在的做法：策划提交一轮到 Git → 程序看提交、审批 → 再回给策划，很麻烦。
要一个中转工具：**AI 会话直接发一条「请求」给某个人，对方在自己的面板上看到、逐条回答，回复回到发起方。**

先作为独立程序做在 AMO 仓库里（同便签、Reviewer 的做法），跑通后再考虑并进 AMO Studio。

## 已定（用户 2026-10-26）

- 传输：**局域网中转服务**（HTTP + WebSocket），不走共享文件夹 / IM / Git。
- 范围：**同一局域网的小团队**（几到十几人）；身份 = 名字 + 团队口令，不做公网、不做账号体系。
- AI 客户端：每个人用的都不一样（Studio、Claude Code、Codex……）→ **以 MCP 为主**，一个独立的 stdio MCP 服务，任何支持 MCP 的客户端都能接。
- 回复形式（第一阶段）：**逐条回答 + 自由文字 + 结论**（同意 / 需要改 / 有疑问）。行批注放第二阶段。
- （补充）**人和人之间也能直接发内容**（普通聊天）；**聊天记录存在服务器上**，换电脑、重装托盘程序都还在。

## 数据

- **对话（thread）**：两种。`direct`：两个人之间的私聊，每对人只有一个；`request`：每条 AI 请求单独开一个对话，标题就是请求标题，之后的回复和追问都在里面。
- **消息**：`text`（普通内容）/ `request`（正文 + 问题列表）/ `reply`（逐条回答 + 补充说明 + 结论）。每条都记作者，以及是本人发的还是 AI 代发的（带客户端名，比如 Claude Code）。
- 消息按服务器全局序号排；每人每个对话记一个已读位置，未读数从这里算。
- 身份：第一次用名字加团队口令加入，服务器发一把个人钥匙存在本机设置里，之后的请求都带着它。名字不能重复。

## 组成

```
AI 客户端 ──stdio──▶ relay MCP ──HTTP──▶ 中转服务 ◀──HTTP/WS── 托盘程序（每人一个）
                    （读本机身份）        （存请求和回复）          收件箱 / 发出的 / 回复
```

1. **中转服务**（`packages/relay`，Node，`node:sqlite`）：成员、请求、回复、已读状态；WebSocket 推送「有新请求 / 有新回复」。
   默认由某个人的托盘程序在设置里打开「在本机开启中转服务」，也能无界面单独跑（放在公用机器上）。
2. **托盘程序**（AMO 中转）：单实例、托盘图标、新消息时托盘气泡提醒。窗口里两栏：**收到的**（待我回答）和 **我发出的**（等回复 / 已回复）。
   发出的请求收到回复后有「复制回复」（格式是给 AI 读的），网页版聊天的人也能用；也可以手动新建一条请求，把内容贴进去。
   设置：我的名字、服务地址、团队口令，以及是否在本机开服务。保存在 `%APPDATA%\AMO Relay`。
3. **relay MCP**（同一个包里的 stdio 入口）：读本机托盘程序的设置拿到身份和地址。
   - `relay_people`：能找的人（名字 + 角色说明，如「程序-战斗」）。
   - `relay_ask`：to、title、body（Markdown）、questions[{id, text, options?}]，返回请求 id。说明里要讲清楚：请求发出就返回，不要干等。
   - `relay_replies`：按 id 或「我发出的、新的回复」取回复，带上逐条回答、补充说明和结论。
   - `relay_wait`（可选）：最多等 N 分钟，受客户端工具超时限制，所以只当作辅助。

## 阶段

1. **最小闭环**：服务 + 托盘程序 + MCP；内容只有 Markdown 正文和问题。本机两个身份互发也能测（e2e 起一个服务、两个客户端）。
2. **接上 Reviewer**：请求里带**快照**，就是把文件内容、重点行、diff 打包进请求。程序那边打不开策划没提交的文件，所以查看包要能做成快照。程序在 Reviewer 视图里写行批注，批注作为回复的一部分发回去。
3. **回到会话**：Studio 管的会话收到回复后自动接回去；外部客户端照旧用 `relay_replies`，或者复制回复。
4. 以后：程序让自己的 AI 先起草回复、一个请求发给多个人、并进 AMO。

## 补充（用户 2026-10-26）

- **一键复制用法 prompt**：推进中随时粘给任何 agent，让它知道怎么用。文字只在 `usage.ts` 一处生成，托盘的「复制用法」、`amo-relay prompt` 和 MCP 的 instructions 都用它。
- **中转服务跑在 Mac 上**：服务只用 Node 自带的模块加 ws，打包成单个 `amo-relay.mjs`（`npm run relay:bundle`），要求 Node 22.13 或更新；Mac 上的部署和 launchd 写在 `packages/relay/README.md`。托盘程序跑在每个人自己的机器上，目前是 Windows。
