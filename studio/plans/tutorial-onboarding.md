# 教程和新手引导（方案，2026-10-29，待用户看）

起因（用户 10-29）：测试下来的反馈是「不知道 Studio 怎么用，不明白各种功能是做什么」。要做一轮教程：按使用场景、对照别的 harness 的常规操作、讲本软件的特点；形式是 HTML + 演示，演示倾向在网页里绘制（而不是 GIF）；再加新手引导，比如第一次打开平台时主动引导设置工作文件夹。

## 一、评估：为什么看不懂

对着代码和 README 过了一遍，问题不在某个功能，而在**第一次接触时没有人带路**：

| 现状 | 问题 |
|---|---|
| 平台第一次打开：登录 → 「工具」页。Studio 数据目录在「目录」页，只有点「打开 Studio」被拦下时才提示去设（`PlatformApp.tsx` 的 `dirNotice`） | 先撞墙再找路；便签的工作文件夹、Studio 的默认文件夹完全不提 |
| 平台「环境」页（Claude Code / Codex / git）要自己点进去 | 装好 Studio 打开后才发现模型「不可用」 |
| Studio 从平台打开时跳过首次设置（设了 `AMO_STUDIO_DATA_DIR`），直接进空看板，每列只写「空」 | 新人不知道第一步是「登记项目」还是「新任务」 |
| 概念多且互相嵌套：项目、专题、任务、会话、分支、子会话 / 委派、公共文件夹、渠道、额度、预设 | 没有一处讲它们的关系；README 的「日常怎么用」表格是给已经懂的人查的，还有过时内容（「工作区」「Focus 开/关」「长期令牌」） |
| 窗口多：主窗口、Focus、便签、书签、画布小窗、查看器、Git Review、远程对话框 | 不知道哪个窗口是干什么的、从哪打开 |
| 产品里没有任何「帮助 / 教程」入口 | 有问题只能问人 |
| 用过 Claude Code / Codex 的人有现成习惯（终端里一问一答、`/` 命令、审批、`--resume`） | 没告诉他们「你熟悉的那个操作在这里是哪个按钮」，也没讲 Studio 多出来的东西（看板、Focus、批注发回、画布）值在哪 |

结论：教程和引导各管一半——**引导**负责「第一次能走通一件事」，**教程**负责「知道还能干什么、什么时候用」。两者互相指：引导每步旁边有「详细看教程」，教程每章末尾告诉你在软件里从哪进去。

## 二、新手引导（产品内）

### 1. 平台：第一次打开的向导

登录之后、第一次进主界面之前，出一个分步向导（可以「以后再说」跳过，之后在 设置 里能重新打开）。只用平台已有的能力，不为它改工具（约束第 1 条）：

1. **装哪些工具**：Studio（默认勾，带便签和 Reviewer）、中转（默认勾）、独立 Reviewer / 便签（默认不勾，说明「Studio 里已经带了」）。点下一步开始装，装的同时往下走。
2. **文件夹**（用户点名的这一步），一页列三个，每个一句话说清存什么、给默认值和「选择…」：
   - Studio 数据目录（必选；会话、项目、设置；升级不碰；已有 `studio\.data` 的人选它就能接着用）；
   - 便签工作文件夹（默认 `%APPDATA%\AMO Notes` 下；写进便签自己的设置，见下面「待定」）；
   - Studio 新项目的默认位置（「登记项目」选文件夹时从这里开始；写进 Studio 设置，见下面「待定」）。
3. **环境检查**：把「环境」页的检查搬进来一份：Claude Code、Codex、git，缺的给「去下载 / 一键安装」，Claude 没登录的提示「在终端运行 claude 登录一次」。缺了也能继续。
4. **完成**：「打开 Studio」+「先看 5 分钟教程」两个按钮。

向导的状态记在 `platform.json`（`onboarded: true` 和完成到哪一步），中途关掉下次从那一步继续。

### 2. Studio：第一次进来

不做整屏遮罩的强制导览，做三样轻的：

- **空状态即引导**：没有项目时，看板中间是「开始的三步」卡片：① 登记一个项目（按钮）② 新建第一个任务（按钮，项目登记后亮）③ 在对话里批准第一条命令（说明）。每步完成打勾，三步都完成后卡片消失，换回普通看板。画布、查看包、书签、远程这些页面的空状态也各写一句「这是干什么的 + 怎么开始 + 教程哪一章」。
- **第一次碰到时的一句话提示**：第一次出现审批卡片、第一次打开 Focus、第一次进画布、第一次进 Git Review，在旁边弹一个可关的小气泡（只出一次，记在 Host settings，换电脑不重复也不丢）。
- **教程入口**：顶栏右边一个「?」（或放进设置旁），打开教程；各页面的「这是什么」链到对应章节锚点。

### 3. 便签、中转、Reviewer

只加教程入口（托盘菜单「使用教程」/ 设置里一行）和各自的空状态说明，不做向导。

## 三、环境：平台帮人装和维护 Claude Code / Codex（10-29 补）

用户 10-29：有的人没装 Claude Code / Codex CLI；参考 cc-switch 的安装和维护逻辑，平台辅助安装，最好看得到进度条，首次向导的环境检查才有用。**当天早上的事**：策划的 CLI 版本太旧，用不了新模型。

### 现状（平台「环境」页，`platform/src/environment.ts`）

- 能查：Claude Code（PATH、`~\.local\bin`、npm 全局）、Codex（PATH）、DSH 桌面版、git；显示 npm 上的最新版本。
- 能更新：npm 装的 `npm install -g <包>@latest`，官方安装器装的 Claude `claude update`；Codex 被 Studio 后台占着时不更新。只在点了才做（10-29 用户定的，当时就参照了 cc-switch）。
- 缺的：**没装时不能装**（只有「去下载」和一条要自己粘贴的命令）；**落后了不主动说**（只有比 Studio 的 SDK 旧时 Claude 才标黄，Codex 不比较；要自己点进「环境」页才看得到）；没有进度，更新时只有转圈；不知道一台机器上装了几份、命令行用的是哪一份；不查 Node 版本够不够。

### 从 cc-switch 拿什么（看的是 GitHub `farion1231/cc-switch` 的 `ddcb111`，2026-10-29；主要在 `src-tauri/src/commands/misc.rs`、`tool_node_requirement.rs`）

| cc-switch 的做法 | 我们怎么用 |
|---|---|
| Windows 安装命令：Claude `npm i -g @anthropic-ai/claude-code@latest --ignore-scripts=false --include=optional --allow-scripts=@anthropic-ai/claude-code`；Codex `npm i -g @openai/codex@latest`；Codex 官方安装器 `irm https://chatgpt.com/codex/install.ps1 \| iex`（它用来更新独立安装的那份，带 `CODEX_INSTALL_DIR` / `CODEX_HOME` / `CODEX_NON_INTERACTIVE=1` 原地升级） | 照用这几条命令和参数（Claude 那几个参数是让 npm 允许它装本机二进制的可选依赖，少了装完跑不起来） |
| 先列出这个工具在本机的**所有安装**，标出命令行实际用的那份（PATH 上第一个，解析软链接后比较）；有多份时界面写「检测到多处安装，命令行用标『默认』的那处，升级可能写到了别处」，升级前让人确认升级哪一处 | 照做。今早那种「明明更新过还是旧的」很可能就是这个，向导和环境页都要显示 |
| 更新**锚定到默认那份**：npm 装的用它旁边那个 npm，官方安装器装的用 `claude update` / `codex update`，失败再退回 npm；认不出怎么装的（别的安装器、手动拷的 exe）不更新，说「怎么装的就怎么更新」 | 照做，把我们现在的 `updatePlan` 扩成这样 |
| 升级前查 Node：取新版本的 `engines.node`，和那份安装要用的 node（安装旁边的 node.exe，否则 PATH 上的）比，不满足就不给升级按钮、先说「要先升 Node」 | 照做 |
| 一个工具一把锁、所有安装串行（npm 全局目录是共用的） | 照做 |
| 静默执行：写临时 .bat，第一行 `@chcp 65001>nul`（用户名有中文时 npm 路径会乱码），`CREATE_NO_WINDOW`；PATH 用「进程的 + 注册表里用户和系统的」合并后的（刚装完的程序改了 PATH，已经在跑的进程看不到）；失败时取输出最后 8 行 | 照做；PATH 合并这条装完后找程序也要用 |
| 升级后再问一次版本，没变就说「上游升级器报告成功但版本没变」；装好但问不出版本单独标「已安装但无法运行」 | 照做 |
| **不拿**：用 `powershell -ExecutionPolicy Bypass -EncodedCommand` 跑官方安装器 | 火绒报过这种写法（10-28，`322cb20`），改用脚本走 stdin、不带这两个参数，和现在 Host 里的做法一样 |
| **不拿**：WSL、另外十几种 CLI、卸载 | 用不到 |

cc-switch 自己**没有进度条**（阻塞执行完弹一个提示），进度要我们自己做。

### 我们要多做的

1. **没装时一键装**：
   - Claude Code：和 cc-switch 一致（用户 10-29 定），Windows 上用 npm 装（上面那条带参数的命令）。没有 Node 时 cc-switch 装不了；我们退回官方原生安装器（不需要 Node，装在 `~\.local\bin`，之后 `claude update` 能更新），这一条是我们加的。
   - Codex：有 Node 用 npm；没有 Node 用官方独立安装器。要先验证：Studio 找 Codex 只看 PATH（`locate` 的 `codexOnPath`），独立安装器装的位置（`%LOCALAPPDATA%\Programs\OpenAI\Codex\bin`）是不是在 PATH 上、Studio 的 app-server 用它行不行。
   - 不帮人装 Node 和 git，只给官方下载页（它们是系统级安装，要管理员权限、会弹 UAC）。
2. **进度条**，分四段：检查 → 下载 → 安装 → 验证（装完问一次版本）：
   - 平台自己下载的东西（如果原生安装器那条路改成平台自己下二进制、核 sha256，再跑 `claude install`）按字节走，是真进度；
   - npm 装：拿 npm 仓库的 `dist.unpackedSize`（主包 + 本机平台的可选依赖）当总量，看目标文件夹已经写了多少，标「约」；拿不到时这一段用来回滑的条，旁边滚动显示安装输出的最后一行和已用时间；
   - 官方安装器（PowerShell 脚本）：只能分段 + 显示输出，不估百分比。
   - 第一步先摸清：两个官方安装脚本各自下什么、多大、有没有校验；Claude 的 npm 包现在是不是靠可选依赖装原生二进制。这些都**未验证**，结论记进这份方案再定走哪条路。
3. **主动提醒**（今早那件事）：
   - 平台启动时、之后每 6 小时在后台查一次（只查，不装）；落后时「环境」页标签和托盘亮点，Studio 卡片下写一行「Claude Code 有新版 x（你的是 y）」。
   - 两档：比最新版旧 = 「有新版」（提醒）；比 Studio 需要的旧 = 「要更新」（醒目，首次向导里不更新就不让点「完成」之外的下一步）。「Studio 需要的」：Claude 是 Studio 带的 SDK 对应的 Claude Code 版本（现在已有）；Codex 是 Studio 生成协议类型时用的那一版（要在打包时写进 Studio 包里，平台读）。
   - 今早的情况（用户 10-29 补）：策划登录的是 GPT 账号，Studio 里型号只能选 gpt-5.6，应该默认显示 6.1。Codex 的型号列表是 Codex 自己给的（app-server），CLI 旧就只列旧型号，所以根子是 Codex 版本旧。Studio 的型号选择里加一行小字「型号列表来自 Codex x.y（最新 z）；更新 Codex 才能看到新型号」，落后时显示；Claude 的型号选择同理。
   - Studio 里：会话因为「模型不存在 / 不支持」之类的错误开不起来时，错误下面加一句「可能是 Claude Code / Codex 版本太旧（你的是 y），在 AMO 平台的『环境』里更新」。只是一句提示，不依赖平台（约束第 1 条）。
4. **有会话在用时**：Codex 已经是「Studio 后台占着不更新」；Claude 也查一下有没有 Studio 的 Claude 会话在跑（npm 装的会因为文件被占用失败），有就说明先等会话结束或完全退出 Studio，不替人关（约束第 6 条）。

## 四、展示：AMO 好在哪（10-29 补）

用户 10-29：除了教程，要专门做一套展示，讲 AMO 的亮点，尽量贴实际工作场景。教程回答「怎么用」，展示回答「为什么用它」；两者共用演示引擎，展示里每一幕末尾链到教程对应章节。

### 亮点

用户列的五条：

1. **多个模型在一个地方对话**（Codex / Claude / DeepSeek），还能用内置功能在会话、任务之间流转（委派、交接、留言、提案）。
2. **topic → task → session 三层**：会话外面包着任务，任务外面包着专题。比只按 project 分更适合重度开发：一个专题跨几个项目，一个任务下面有几个会话和分支。
3. **画布**：方便人读全局。
4. **Reviewer + 批注**：快、顺手，AI 还能直接把人带到关键的那几行。
5. **局域网里多设备互动**（远程）。**风险大**，所以只在局域网里用。工程描述和教程里都要强调：只推荐给自己在局域网里的几台设备之间用。

我补的（代码里已经有的）：

6. **Focus：并行时只在需要你时叫你**。几个会话同时跑，Focus 小窗只列要批准、要回答、做完待看的；能直接在 Focus 里批准或回答，不用切回主窗口。
7. **AI 也懂 AMO**：受管会话自带 AMO MCP，能看看板和任务，写自己的进度和交接，向人提问（`decision_request`），叫人看某个文件的某几行（`review_open`），提议开新任务（人确认后才开）。所以「流转」不只靠人复制粘贴。
8. **不锁定**：随时「在终端打开」交回原版 CLI（Codex 和终端共用同一个会话；Claude 交给终端期间工作台只读，关掉终端就收回）。Studio 不改 `~/.claude`、`~/.codex` 的设置；密钥在 Windows 凭据管理器里，不传给 agent 跑的命令。
9. **审批和提问统一**：三家 CLI 的审批卡片、问题弹窗是同一套样子，还会标出是「阻断（等你回答）」还是「不阻断（答案作为留言返回）」。
10. **中转：AI 卡住了去找对的人**。策划的 AI 有拿不准的事可以直接发给程序，程序回一轮或几轮后 AI 接着做，人不用在中间传话。人和人之间也能直接聊。
11. **团队一处装和更新**：平台从团队服务器装工具，有测试和正式两个通道，能回滚；环境页管 CLI 版本（第三节）。
12. 小的：便签全局快捷键随手记，书签按专题收藏段落，额度和统计页同时看几个订阅的用量。

### 形式

- **10-30 用户看过第 1 步的教程后改**：教程很详尽，留作文档；展示要像产品落地页，短动画 + 往下滚出现新演示，几屏讲完关键点，看起来要酷。所以每屏只有一个大标题、一行副标题和一段自动循环的动画，不放段落和表格，没有播放控件，底部「怎么用 →」链到教程。下面的场景是动画的素材，文字不上页面。
- **10-30 用户看过循环版后再改（结构）**：优先讲已经成熟、在用的功能；工具要标明是工具。六屏：① 多 AI ② 专题 › 任务 › 会话和多项目之间的流转 ③ 画布上的任务节点 + 主控 AI 推进一个专题 ④ 工具 · Reviewer ⑤ 工具 · 中转 ⑥ 工具 · 便签。我提的、用户同意的：前三屏讲 Studio，后三屏前加分隔「也能单独用的工具」，每屏标「工具 · AMO …」，副标题点明不装 Studio 也能用；Focus 不单独占屏，并进第 1 屏；远程从展示页拿掉，只留在教程（风险说明照旧）；②要演「流转」（一句话交给另一个任务里的 Codex，结果流回），不是静态三层图；③主控提议拆任务 → 人确认 → 画布长出节点和依赖、随进度变色；④查看包标关键行 + 批注复制回对话，带一下 HTML 位置批注；⑤策划的 AI 发问、程序回复、回到策划的会话；⑥快捷键弹出便签、记一句、Studio 里引用。动画都只播一遍，播完给「重播」。
- **10-30 再改成四屏（替代上面的六屏）**：① 开场（AMO 的基础：多 AI、Focus 里直接批准、镜头扫一眼额度）② 专题 › 任务 › 会话 + 画布（画布讲对专题的组织：一眼看清推进的结构）③ 工具：Reviewer + 便签（都和审阅有关；Reviewer 是最近程序评价最高的）④ 测试中：中转 + 远程链接任务，**展示页上也强调远程的安全**（替代之前「远程那屏不放风险小字」）。文案在 `docs/tutorial/showcase.md`（我梳理、待用户看）。

### 演示怎么画

在网页里画，不用 GIF。理由：GIF 要录屏、文件大、界面一改就得重录、不能暂停到某一步看清楚；画出来的可以逐步播放、暂停、跳到某步，深浅色跟着页面走，文件小。

做法：一个小的演示引擎（几百行，内联在页面里），每个演示是一段脚本：

- **场景**：用 HTML/CSS 画一块**简化的**界面（只画这一步相关的区域，比如新任务页的输入框和模型选择），配色用 Studio 的 token，看着像但不追求像素一致；
- **步骤**：`光标移到 X → 点击 → 打字「…」→ 出现 Y → 高亮 Z`，每步配一行字幕；
- **控制**：播放 / 暂停 / 上一步 / 下一步 / 重播，进入视口才自动播，`prefers-reduced-motion` 时不自动播只给分步。

考虑过直接用 `ui` 包的真组件 + 假 Host 来演示：最像、界面改了自动跟上，但每个演示要拼假数据、多窗口难做、单文件会很大，第一版不做。界面改动后的走样用一个便宜的检查兜：教程里引用的按钮文字（「+ 新任务」「授权给…」等）列成清单，单测检查它们在 `ui/src` 里还存在，找不到就报，提醒去改教程。

### 放在哪、怎么维护

- 源文件：`studio/docs/tutorial/`，每章一个 `.md`（正文）+ `scenes/*.js`（演示脚本）；`npm run tutorial:build` 生成单文件 `tutorial.html`（样式、脚本都内联，不引外部资源，双击能开）。HTML 不是事实源，页脚写源文件路径。
- 发布：随工具打包（`ui/public/tutorial.html`，Studio 在查看器里打开它，查看器已经能跑页面里的脚本），离线能看、和装的版本一致；平台、便签、中转从各自入口打开同一份（Studio 没装时平台用自己包里的一份）。是否另外放一份到团队服务器的下载页，见「待定」。
- 截图和真界面对照：e2e 已有的截图（`studio/screenshots/`）不进教程，只在写演示时作参照。
