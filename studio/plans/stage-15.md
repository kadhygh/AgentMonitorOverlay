# 阶段 15：让 agent 懂 AMO、主控拆任务、传话（2026-10-15）

起因：用户 2026-10-15 提出「现在可以让 agent 了解 AMO 的架构和接口用法了」。先只讨论设计，不写代码；设计定下来之后再做。

## 用户的场景

一个「迁移」专题，要在 3 个项目里分别推进任务；这 3 个项目是同一个 git 工程。用户把目标交待给**主控**，主控拉起 3 个平级的任务，每个在一个项目里，在专题画布上把它们的关系连起来。用户再分别进这 3 个任务敲定细节，而不是什么都通过主控。最后 task1 确认没问题合 master，task2 再合 master，依次进行。

## 现状（2026-10-15）

- agent 通过 MCP 能做的：读看板、专题、画布、项目；在自己的任务上记进度、交接；留言（用户决定什么时候转进对话）；向用户提问；勾清单；在画布上建组、连依赖、放任务（每次要用户批准）；调度提案。
- 不能新建任务，也不能让别的会话开始干活：这是 NEEDS_YOU S5-10「是否开放派发」，一直没定。本阶段就是在定它（见下）。
- 已有的 MCP 说明文字（`mcp/tools.ts` 的 `AMO_MCP_INSTRUCTIONS`）是一段通用介绍。

## 用户的决定（2026-10-15）

1. **AMO 知识**走 MCP 的服务说明，加一个随时可查的 `amo_guide` 工具，加每个会话的**角色卡**（主控 / 执行 / 子 agent）。**不改 CLI 的系统提示词**（之前用户撤掉过 Studio 自己的系统提示词）。
2. **专题文档**：只放和推进这个专题的任务严格相关的文档，存在 Studio 里。很专门的文档放在项目里，用已有的「文件标记」标出来；专题文档可以引用这些标记。
3. **主控只写提案**：要建哪些任务（标题、项目、第一句话、模型、先后关系）；用户确认后 Studio 才创建任务，并放上画布、连好依赖线。
4. **建好后跑不跑**：两种都支持（立刻开跑 / 放进待办），在确认时按当时的任务决定。
5. **分支和合并 Studio 不管**：用户说开才开、说合才合，由 agent 按用户的话执行 git。Studio 只负责让用户方便地 Review。
6. **主控由用户指定**，不靠推断：开任务时可以标「主控」，之后也能改。一个项目里可以有一个或多个主控；在专题里的主控负责这个专题。
7. **Review 现在够用**，本阶段不做 Review 相关的事，用户再用一段时间。
8. **传话**：主控调用传话接口 → 用户看到弹窗 → 确认后自动送进目标任务的会话。目标任务也可以设成「主控传话不用确认」（长任务里自动送话很正常）。

## 预研：两个 CLI 会不会把 MCP 服务说明交给模型（s15-00，mock，不花额度）

用 e2e 的模拟模型各开一个会话，在发给模型的请求里找 `AMO_MCP_INSTRUCTIONS` 的原文：

- **Claude Code**：放进系统提示词的「MCP Server Instructions」一节（`## amo` 下面）。Studio 给每个 Claude 会话各建一个进程内 MCP 服务（`createSdkMcpServer`，SDK 0.3.296 支持 `instructions`），所以**每个 Claude 会话的说明可以不一样**，角色卡可以直接放在这里。
- **Codex 0.161**：作为 `mcp__amo` 这个工具组（namespace）的说明发给模型。但 Codex 建立 MCP 连接时还不知道是哪个会话（临时把调用者写进说明试过：两个会话收到的都是 `none`），所以**Codex 的说明只能是通用的**。角色卡要靠工具：通用说明里写明「开始前先调用 `amo_whoami`」，这个工具按调用者返回角色卡（工具调用带着会话身份）。

结论：通用的 AMO 用法放服务说明（两边都看得到）；角色卡 Claude 放说明里，Codex 用 `amo_whoami`；两边都能随时调 `amo_guide` 看完整用法。

## 分期

### 第一期：让 agent 懂 AMO

- 服务说明改写：AMO 是什么、实体之间的关系、工具什么时候用；提醒先看自己的角色。
- `amo_guide`（完整用法，按主题分段）和 `amo_whoami`（角色卡：我是谁、在哪个任务 / 专题 / 项目、主控是谁、相关的专题文档和文件标记、我能做什么不能做什么）。
- 任务的「主控」标记：新建任务时可勾选，任务头里能改；迁移加 `tasks.lead`。
- 专题文档：专题页里增删改（Markdown），agent 能列出和读取；可以引用文件标记。

### 第二期：主控拆任务

- 主控专用工具 `task_plan_propose`：一组任务（标题、项目、第一句话、模型、依赖）。
- 提案卡出现在专题页和画布上，用户可以改，确认时选「立刻开跑」或「放进待办」；Studio 建任务、放上画布、连依赖线。
- 只有标了主控的任务里的会话能提案；范围是它所在的专题（不在专题里时是它的项目）。

### 第三期：传话

- 主控专用工具 `relay_send`（目标任务、内容）：默认弹窗等用户确认（主窗口和 Focus 都能看到），确认后送进目标任务的主会话（正在跑就排队）。
- 任务上的开关「主控传话不用确认」。
- 传话记录在两边都看得到。
