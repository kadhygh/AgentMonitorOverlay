# 阶段 9 · 对话体验对齐 DSH

分支：`studio/stage-9-chat`（从 `studio/main` 创建）。起因：用户试用后觉得"聊天内容有点呆板，能不能完整的复刻 dsh 的体验"（2026-10-13）。

参考：DeepSeek Harness 0.2.1-alpha.2（MIT）`packages/client/ui-chat`、`ui-tool`、`ui-conversation`、`ui-theme`。对齐的是**看到的样子和交互**，不搬它的插件架构（它的对话层有十几万行，依赖它自己的 Session 事件模型）。

## 差距

| DSH | Studio 现状 |
|---|---|
| 以"轮"为单位：你的消息 → 工作过程（可折叠） → 最终回答 → 页脚 | 所有条目平铺 |
| 工作过程按类别汇总成组头："已读取文件并执行了命令"；运行中显示"正在运行命令 · npm test"并带流光 | 每个工具一张卡片 |
| 思考过程单独一行："已思考 8秒"，带首行预览，可展开 | Host 丢掉了思考内容 |
| 工具行：图标 + 标题 + 摘要（命令、路径、+12 −3），展开是终端卡片 / diff / 输入输出 | 只有名字 + 摘要 + 最后 4000 字输出 |
| 一轮结束后整轮收起，只留"已完成，用时 1分12秒"和最终回答 | 无 |
| 页脚：复制、时间、本轮用量（token 明细） | 无 |
| 运行指示：动画 + "深度求索中，用时 12秒 ···" | "生成中…" |
| 输入框：圆角卡片、圆形发送 / 停止按钮、下方统计（轮数、步数、用量、缓存命中） | 方框 + 文字按钮 |
| 回到底部按钮 | 无 |
| 设置 → 工作步骤展示：简洁 / 标准 / 详细 / 完全展开 | 无 |

## 做法

| 层 | 内容 |
|---|---|
| 协议 | 条目加 `turnId`；新增 `reasoning`（思考）和 `turn`（一轮的开始/结束、状态、用量）两种条目；`tool` 条目加 `kind`（command/read/search/list/edit/web/mcp/subagent/other）、输入参数、退出码、耗时、工作目录、文件 diff。旧数据没有这些字段时照常显示 |
| Codex | 接 `item/reasoning/*`、`item/commandExecution/outputDelta`、`thread/tokenUsage/updated`、`turn/started|completed` 的时间；`commandActions` 区分读文件 / 搜索 / 列目录；`fileChange` 带 diff |
| Claude | 接 thinking 块；`result` 的 usage 和耗时作为一轮的结束；工具输入参数、Edit/Write 的改动做成 diff |
| 界面 | `Thread` 重写为按轮分组的渲染（分组逻辑是纯函数，有单元测试）；新组件：过程组、思考行、工具行（终端 / diff / 输入输出卡片）、整轮折叠、页脚、运行指示、新输入框、回到底部 |
| 设置 | 界面 → 工作步骤展示（默认"标准"，和 DSH 桌面版一致），按本机记住 |
| 测试 | mock 模型加 `[[demo]]`：思考 → 读文件 → 改文件 → 跑命令 → 带表格的回答，用于 e2e 和截图；现有 e2e 里依赖工具卡片的用例改为先展开 |

## 不做

- DSH 的轮次导航轨道（我们已有"上一条/下一条"）、分支对话、图片附件、文件链接在侧栏打开、上下文压缩行——之后按需要再加。
- 不发布 Portable（只在发布节点出）。

## 结果（2026-10-13）

- 完成上面"做法"表里的全部内容。真实模型验证见 `spikes/RESULTS.md` s9-00：DeepSeek（经 Codex）和 GLM（经 Claude）的思考、工具行、每轮用量都能显示。
- 测试：单元 + 集成 241 个通过；端到端 44 个通过（新增 `chat-experience.spec.ts`，截图在 `screenshots/stage-9/`）。其他端到端用例默认用"完全展开"，这样能直接看到工具行和已批准的审批。
- 旧会话没有"轮"记录：按你的消息分段，折叠行只写"已完成"，没有用时和用量。
