# 带过来的小问题（阶段 8 之后）

ROADMAP 的阶段都完成后，剩下的都在等你。这里记录 loop 在等待期间看过的遗留小问题，以及结论。

| 问题 | 结论 | 处理 |
|---|---|---|
| e2e 里用 Codex 会话的用例偏慢（25 秒左右） | 查清了：不是 MCP 慢——Host 层面一次 Codex MCP 调用约 0.1 秒。慢在**测试结束关闭应用**：大约一半的运行里，Host 停止 Codex app-server 时等进程退出的 5 秒超时被用满，之后 Electron 进程退出又被拖住约 17 秒（Electron 已经发出 `quit`，Playwright 还在等进程真正结束）。另一半的运行里全程不到 1 秒 | **暂不修**：只影响测试耗时（完整 e2e 约 5–7 分钟），不影响使用——正常使用时 Host 常驻，关窗口不会停 app-server。要彻底修需要换掉 Windows 上结束进程树的方式，收益不大 |
| 交接终端里的 Claude 不带 AMO MCP | 要带上，就得把 MCP 地址和令牌写进 Claude 的 MCP 配置（命令行参数或配置文件），和"令牌不上命令行、尽量不落文件"的红线有冲突 | **先不做**：交接终端本来就是你亲自在用，需要 agent 读看板时可以收回到工作台再继续。如果你希望带上，告诉我，我按"令牌只放在数据目录的配置文件里"的方式做 |
| 测试偶尔留下临时目录 | 原因是删除时 Codex 进程还没退干净（文件被占用），删除已经带重试（最多约 10 秒）；和上面第一条是同一个根源 | **不改**：loop 每轮结束都会清理 `%TEMP%` 下的 `amo-studio-test-*`、`amo-studio-e2e-*` |
| 完整 verify 时 `server-manager` 的"崩溃后同一端口重启"偶发失败 | 单独跑总是通过；完整跑（测试文件并行、机器忙）时，被杀掉的 app-server 的端口有时超过 10 秒都没释放，重启只好换端口，后面两个用例跟着失败。等待时间试过加到 10 秒也不够，已改回 3 秒（再长会拖慢真实崩溃后的恢复） | **记录，暂不修**：不是功能错误；遇到时重跑一次 verify。要根治需要换掉 Windows 上结束进程树的方式 |
