# remote-session：在另一台 AMO 上接着用本机的任务和会话（方案，2026-10-28 晚更新，未开工）

## 起因

用户 10-28 的想法：会话在 A 机器上跑（模型调用都在 A），另一台 AMO 客户端 B 远程使用它，B 不用登录模型账号。平台的基础功能稳定后开始推进。

## 用户 10-28 晚定的

- **远程用，不是搬走**：任务和会话一直在 A 上，B 只是看和操作。
- **界面要精简**：B 上只显示远程能用的部分，分清哪些能看、哪些不能（见下面「B 能看到什么」）。
- **不整个开放给 B**：按任务（task）或会话（session）授权。
- **第一版能在 B 上查看 HTML、Markdown 和图片就够了**（会话里的文件链接、任务的附件）。
- **两种方式**：
  1. **A 主动授权**：A 在某个任务上「授权给 B」，B 就能在这个任务里工作；A 随时可以收回。
  2. **B 发起请求**：B 在自己的 Studio 里向 A 发请求（写清要做什么），A 同意时选定项目 / 专题 / 模型（A 有一份「远端允许的默认配置」，预先填好），同意后 A 上自动建立任务并开跑，任务自动授权给 B。

## B 是谁（用户 10-28 晚定）

- **B 先只是用户自己的另一台设备，但登录的是另一个 AMO 账号。**
- 所以不能靠「同一个账号」认设备，要**配对**：B 在 Studio 里填 A 的账号名发起配对 → A 上弹出「<B 的账号>（<B 的设备名>）想和这台电脑配对」→ A 点允许 → 记进 A 的「已配对的设备」（账号 + 设备编号）。之后授权和请求都只在已配对的设备之间进行，A 随时可以解除配对（同时收回所有授权）。
- 配对和授权的文字写「你自己的其他设备」，提示不要配对别人的设备：A 的 Claude / GPT 个人订阅不能给别人用（Anthropic 条款）。以后真要开放给同事，再另做（只许 API key 渠道、更严的审批）。

## 初版在 B 上的样子（用户 10-28 晚定）

- **远程任务就是 B 看板上的一张任务卡**，带「远程」标记，写明在哪台设备、哪个账号上跑（比如「远程 · 在 kangaroo 的台式机上」）。不另做精简页面。
- **打开后复用常规的任务页和对话界面**：发消息、审批、中断、开会话都照常；只是有的操作不可用（上表「不能」的那些），有的会慢一点（比如点一个 HTML，要经服务器从 A 取过来再打开）。
- **从 A 取来的文件先放进 B 本机的一个文件夹**（按远程任务分，放在 B 的 Studio 数据目录里），任务归档时一起清掉。初版 Markdown、HTML、图片够用。
- **提醒只给 B**：授权期间、B 在线时，这个任务的 Focus 提醒（审批、提问、回复完了）只在 B 上出现，A 不提醒；B 断开后，A 像常规任务一样接着提醒。

这意味着 B 的界面要能同时显示本地任务和来自别的 Host 的任务（看板、任务页、对话都要知道「这个任务从哪个 Host 来」），这是前端的主要工作量。

## 现在有的

- 登录统一在平台（`AGENTS.md` 约束第 7 条）：A、B 用平台登录的团队服务器账号认人；平台给每台电脑一个设备编号。Studio 读平台的 `account.json`，没装平台就没有远程功能。
- 团队服务器 = Mac 上的中转服务，有账号、部署流程。要加「设备之间转发」的通道。
- A 的 Host 是 HTTP + WebSocket 服务，只绑 `127.0.0.1`，host token 能用全部接口。**不对局域网开端口**：A 的 Host 主动连出到服务器，B 经服务器访问。

## 形态

```
A（任务和会话在这跑）              团队服务器                 B
Host ── 主动连出 ─────────→   按授权转发   ←─────── Studio「远程」入口
  被授权任务的事件、文件  ──→              ──→   精简的任务页、对话、审批、查看器
  发消息、审批、中断、开会话 ←──           ←──   输入框、按钮
```

- **授权表在 A 的 Host 里**：哪个任务（或会话）授权给了谁、什么时候、能做什么。A 收回授权，B 的连接立刻断开、界面显示「授权已收回」；任务和会话在 A 上照常继续。
- **远程接口是单独的一小组**，不是 Host 的全部接口：只对被授权的任务 / 会话，按授权检查每个请求。B 拿到的 token 只认这一组接口和这个授权。
- **方式 2 的请求**：B 发请求 → 经服务器到 A → A 上弹出请求卡（Focus / 看板上能看到）→ A 同意时选项目、专题、模型（默认值来自「远端允许的默认配置」：允许哪些模型、默认哪个、权限模式）→ A 建任务（标题和说明取自请求）、开会话、把请求内容作为第一条消息发出 → 自动授权给 B → B 那边出现这个任务。A 也可以拒绝，B 看到原因。

## B 能看到什么（第一版）

| 能 | 不能 |
|---|---|
| 被授权的任务：标题、说明、它的会话列表 | A 的其他任务、看板、画布、专题 |
| 会话的对话记录、发消息、中断 | A 的设置、模型渠道、凭据、维护终端 |
| 审批卡片和提问（两边都能点，先点的生效） | 重启 A 的 Host（约束第 6 条）、改 A 的设置 |
| 在任务里新开会话（只能选「远端允许」的模型） | Git Review、终端、「在资源管理器中显示」「用 VS Code 打开」 |
| 查看器：会话里链接到的 HTML、Markdown、图片（限这个任务的工作目录和附件） | 别的文件类型、任务工作目录以外的文件、写文件 |

第一版不做：B 往 A 传附件 / 截图、批注写回、代码文件的查看（以后按需加）。

## 约束和注意

- **A 必须开着**：Studio 在跑、电脑不睡眠（被远程使用时 A 阻止睡眠）。A 断开时 B 显示「A 离线」，恢复后自动重连。
- A 上能看到「哪些任务正被谁远程使用」，可以一键收回。
- 命令都在 A 的电脑上执行：远程会话的权限模式取「远端允许的默认配置」，A 可以改。

## 分步

| 步 | 内容 | 做完能干什么 |
|---|---|---|
| 1 | 服务器：设备登记、配对请求、按配对转发的通道；A 的 Host 主动连上；两边的配对界面 | 两台能配对、互相找到 |
| 2 | A：任务的「授权给…」和收回、授权表、远程接口、B 在线时 A 不提醒；B：看板上的远程任务卡，打开复用常规任务页（对话、发消息、审批、新开会话），Focus 提醒 | 方式 1 能用 |
| 3 | 查看器经通道打开 HTML / Markdown / 图片，取来的文件放进 B 的远程任务文件夹，归档时清掉 | 能看文档 |
| 4 | B 发请求、A 的请求卡和「远端允许的默认配置」、同意后自动建任务开跑 | 方式 2 能用 |
