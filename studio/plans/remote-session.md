# remote-session：在另一台 AMO 上接着用本机的任务和会话（方案，2026-10-28 晚更新，未开工）

## 起因

用户 10-28 的想法：会话在 A 机器上跑（模型调用都在 A），另一台 AMO 客户端 B 远程使用它，B 不用登录模型账号。平台的基础功能稳定后开始推进。

## 用户 10-28 晚定的

- **远程用，不是搬走**：任务和会话一直在 A 上，B 只是看和操作。
- **界面要精简**：B 上只显示远程能用的部分，分清哪些能看、哪些不能（见下面「B 能看到什么」）。
- **不整个开放给 B**：按任务（task）或会话（session）授权。
- **第一版能在 B 上查看 HTML、Markdown 和图片就够了**（会话里的文件链接、任务的附件）。
- **两种方式**：
  1. **A 主动授权**：A 在某个任务上「授权给 B」，B 就能在这个任务里工作；A 随时可以收回。
  2. **B 发起请求**：B 在自己的 Studio 里向 A 发请求（写清要做什么），A 同意时选定项目 / 专题 / 模型（A 有一份「远端允许的默认配置」，预先填好），同意后 A 上自动建立任务并开跑，任务自动授权给 B。

## B 是谁（用户 10-28 晚定）

- **B 先只是用户自己的另一台设备，但登录的是另一个 AMO 账号。**
- 所以不能靠「同一个账号」认设备，要**配对**：B 在 Studio 里填 A 的账号名发起配对 → A 上弹出「<B 的账号>（<B 的设备名>）想和这台电脑配对」→ A 点允许 → 记进 A 的「已配对的设备」（账号 + 设备编号）。之后授权和请求都只在已配对的设备之间进行，A 随时可以解除配对（同时收回所有授权）。
- 配对和授权的文字写「你自己的其他设备」，提示不要配对别人的设备：A 的 Claude / GPT 个人订阅不能给别人用（Anthropic 条款）。以后真要开放给同事，再另做（只许 API key 渠道、更严的审批）。

## 初版在 B 上的样子（用户 10-28 晚定）

- **远程任务就是 B 看板上的一张任务卡**，带「远程」标记，写明在哪台设备、哪个账号上跑（比如「远程 · 在 kangaroo 的台式机上」）。不另做精简页面。
- **打开后复用常规的任务页和对话界面**：发消息、审批、中断、开会话都照常；只是有的操作不可用（上表「不能」的那些），有的会慢一点（比如点一个 HTML，要经服务器从 A 取过来再打开）。
- **打开远程文件时显示读条**（用户 10-28）：从 A 取文件要经服务器传过来，查看器先显示「正在从 <A 的设备名> 取文件…」和进度，取到再显示，像开会话时的「正在启动」那样；取失败写清原因（A 离线、文件太大、类型不支持）。
- **从 A 取来的文件先放进 B 本机的一个文件夹**（按远程任务分，放在 B 的 Studio 数据目录里），任务归档时一起清掉。初版 Markdown、HTML、图片够用。
- **提醒只给 B**：授权期间、B 在线时，这个任务的 Focus 提醒（审批、提问、回复完了）只在 B 上出现，A 不提醒；B 断开后，A 像常规任务一样接着提醒。

这意味着 B 的界面要能同时显示本地任务和来自别的 Host 的任务（看板、任务页、对话都要知道「这个任务从哪个 Host 来」），这是前端的主要工作量。

## A 离线或收回授权时（用户 10-29 同意）

- **分清两种情况**：
  - **A 离线**（A 完全退出 Studio、关机、断网）：B 上的任务卡变灰，标「A 离线」；已同步的对话记录照样能看，不能发消息、不能审批。A 回来后自动重连、补齐这段时间的记录，卡片恢复。
  - **授权已收回**：卡片标「授权已收回」，记录还能看，不再连回。B 归档这个任务时，连同取来的文件一起清掉。
- **A 退出前提醒**：A 在托盘点「完全退出」时，如果有任务正被远程使用，确认框里写「有 N 个任务正被 <设备名> 远程使用，退出后那边会暂停」。
- **B 写到一半的消息不丢也不自动发**：A 离线时输入框内容保留，发送按钮变灰，写「A 离线，回来后再发」；断线时不自动重发（借鉴 Multica）。
- **审批卡片作废**：A 离线时 B 上没点的审批先变灰，A 回来后重新核对，以 A 的实际状态为准。
- **A 退出会中断 A 上正在跑的会话**：和平时完全退出 Studio 一样，A 重新打开后能接着聊；B 重连后看到「已中断」。

## 授权范围：会话和子会话怎么算（用户 10-29 同意）

授权范围 = 一个任务（或一个会话），加上从里面衍生出来的所有会话。B 看到的、能操作的都不超出这个范围。

- **B 自己新开会话**：授权的是整个任务时可以开，会话在 A 上跑、属于这个任务，模型只能从 A 的「远端允许」里选；只授权了一个会话时不能新开。
- **Claude 的子 agent**（会话里的 Task 工具）：本来就是会话内部的一部分（界面上「▸ N」），B 自然能看到。
- **委派会话**（agent 用 `session_start` 开的、挂在父会话下的）：在同一个任务里开的跟着父会话一起授权（授权单个会话时，它下面的子会话也算）；agent 要用「远端允许」以外的模型时自动换成默认允许的模型，并在会话里写明换过；被远程授权的任务里暂时不允许跨项目委派（真要跨，在 A 上弹确认）。
- **审批和提醒**：子会话和父会话一样，B 在线时 Focus 提醒 B，B 断开后交回 A。

## 测试（用户 10-29 同意）

- 平时在本机测：两个 Studio 测试实例代替两台设备（各自的数据目录、`AMO_HOME`、端口），本机临时起中转服务，模型用 mock；断线、刚失联 / 离线、命令去重靠关停服务人为制造。
- 部署到团队服务器后，主会话可以自己注册测试账号（比如「测试-A」「测试-B」）用两个测试实例连 Mac 实测。
- 两台真电脑之间的网络（防火墙、延迟、睡眠）和真实模型，等用户在时一起试。

## 形态

```
A（任务和会话在这跑）              团队服务器                 B
Host ── 主动连出 ─────────→   按授权转发   ←─────── Studio「远程」入口
  被授权任务的事件、文件  ──→              ──→   精简的任务页、对话、审批、查看器
  发消息、审批、中断、开会话 ←──           ←──   输入框、按钮
```

- **授权表在 A 的 Host 里**：哪个任务（或会话）授权给了谁、什么时候、能做什么。A 收回授权，B 的连接立刻断开、界面显示「授权已收回」；任务和会话在 A 上照常继续。
- **远程接口是单独的一小组**，不是 Host 的全部接口：只对被授权的任务 / 会话，按授权检查每个请求。B 拿到的 token 只认这一组接口和这个授权。
- **方式 2 的请求**：B 发请求 → 经服务器到 A → A 上弹出请求卡（Focus / 看板上能看到）→ A 同意时选项目、专题、模型（默认值来自「远端允许的默认配置」：允许哪些模型、默认哪个、权限模式）→ A 建任务（标题和说明取自请求）、开会话、把请求内容作为第一条消息发出 → 自动授权给 B → B 那边出现这个任务。A 也可以拒绝，B 看到原因。

## 前置：Studio 的托盘（用户 10-29 定，先于远程第 2 步做）

- Studio 加托盘：点窗口的 × 只关窗口，Studio 和 Host 留在托盘里，会话照常跑。
- 托盘右键「完全退出」：连 Host 一起关；有会话在跑时写清有几个、问确认（以后加上「有任务正被远程使用」）。
- 平台的 Studio 卡片显示后台状态（「后台在运行 · N 个会话进行中」）；Studio 新版装好但后台还是旧版时给「重启 Studio」，没有会话在跑才能点（约束第 6 条）。

## 约束和注意

- **A 必须开着**：Studio 在跑、电脑不睡眠（被远程使用时 A 阻止睡眠）。A 断开时 B 显示「A 离线」，恢复后自动重连。
- A 上能看到「哪些任务正被谁远程使用」，可以一键收回。
- 命令都在 A 的电脑上执行：远程会话的权限模式取「远端允许的默认配置」，A 可以改。

## 借鉴 Multica（10-28 调研，只借思路不搬代码）

Multica（https://github.com/multica-ai/multica ）是服务器存正本、各机器守护进程领任务的结构，和我们相反；审批全自动（`bypassPermissions`）、文件靠 agent 上传，这两块我们得自己做。它的许可证是 Apache 2.0 加附加条件（界面代码不能拿、借后端代码要在用户文档写「基于 Multica」、商用受限），所以**只借设计**。可以照做的：

- **A 主动连出，退避重连**：1 秒起翻倍、最多 30 秒、带抖动，连接稳定 10 秒后重置；60 秒收不到 pong 判断线。
- **每个会话的事件带递增序号**：B 记住每个远程会话收到的最后一个序号，重连后从 A 按 `since=序号` 补齐（服务器不存）。
- **重连后全部重新核对**：授权状态、待处理的审批 / 提问、会话运行状态、任务说明都重新拉一次，断线期间的变化不会留下提示。
- **命令带编号，A 按编号去重**：B 发出的发消息、审批、中断、开会话各带一个编号；已发出但没收到应答时算「结果未确认」，界面显示「重连后核对」，**不能直接重发**（会重复发消息或重复批准）。
- **离线两档**：「刚失联」（心跳 15 秒，5 分钟内）和「离线」。B 刚失联时 Focus 提醒先不切回 A，过了这段再切，避免网络抖动来回切。
- **收回前列出影响范围**：解除配对时先列出会收回哪些任务 / 会话授权，确认后再收；任务在 A 上照常继续。
- **令牌只认一次授权**；**给 B 的路径只用相对任务目录的路径**，不带用户名。
- **审批转发**（Multica 没有，自己设计）：审批请求是一种带序号的事件，A 按先到先得裁决两边的点击，结果广播给两边。
- **文件代理**：白名单检查前先解析软链接 / junction 得到真实路径，限制文件大小，只放行 HTML、Markdown、图片。授权界面照实写「远程会话的命令以 A 上你的用户身份运行」。
