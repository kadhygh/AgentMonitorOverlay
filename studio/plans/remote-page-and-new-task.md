## 1. 远程放在哪

推荐：**顶栏加一个「远程」按钮**，和书签、便签、Focus 并排，点开是主区域里的一整页（view `remote`，有返回）。

- 按钮上带状态：没配对时只显示「远程」；有配对时显示「远程 · 1 在线」；有配对请求或任务请求待处理时加一个点（和设置旁的点同一种）。设置旁的点不再管远程的事。
- 为什么不放视图标签（看板 / 画布 / 扩展包）：那几个是「看某个项目或专题的工作」，会随左边选的范围变；远程是全局的设备和授权，和范围无关。
- 为什么不做成弹窗：要放任务列表、请求、设备，内容会长，整页更好用；以后远程任务多了还能加筛选。
- 远程任务卡照旧出现在看板上；远程页里的「任务」是汇总和管理的地方。
- 设置里的「远程」页删掉，留一行「远程功能在顶栏的「远程」里」（老用户找得到）。

## 2. 远程页的排布（从上到下）

1. **一行身份信息**（小字，不显眼）：`dhy · 团队服务器 172.16.8.85 · ● 已连接 · 本机「台式机」` 和一个齿轮按钮「远程设置」。连不上时这一行变成提示条（为什么、下次重试、立即重试）。没登录平台时整页只显示「在 AMO 平台里登录」。
2. **任务**
   - 「等你处理」：别的设备请这台电脑跑的任务（同意 / 拒绝）、配对请求（允许 / 拒绝）。没有就不显示这一组。
   - 「授权给别的设备的」（这台电脑是 A）：任务名、给了谁、对方在不在线、最后操作时间，收回。
   - 「在别的设备上跑的」（这台电脑是 B）：远程任务副本，点开就是任务页。还有自己发出去、对方还没回的请求（撤回）。
3. **已配对的设备**：每台一张卡（名字、账号、在线 / 离线多久、谁允许了谁），测试连接、解除配对。右上角「+ 配对设备」打开弹窗。设备卡上不再有「请它跑一个任务…」，改成「在它上面新建任务」，直接打开新任务页的远程模式并选好这台设备。
4. **远程设置**（折叠，或齿轮打开的一块）：本机设备名（点「改名」才变输入框）、远端允许的模型、防睡眠的说明。

## 3. 配对弹窗

- 打开就列出**同一个账号下其他在线的设备**（设备名、上次上线），右上角「刷新」。选一台点「发起配对」，弹窗里显示「等对方允许」，可以撤回。
- 只列自己账号的设备：个人订阅只能自己用（远程会话方案里定的），配对本来就该是自己的设备。下面折叠一行「对方用的是别的账号？输入账号名」留给测试账号这种情况。
- 要服务器加一个接口：`GET /api/devices/online` 返回本账号在线的设备（不含自己）。中转服务端改动，部署一次。

## 4. 新任务页

### 4.1 远程创建

- 页顶「要推进什么？」旁边一个切换：`在这台电脑上 | 在别的设备上`。切到「别的设备」后第一行是**设备**（只列配对了、允许了这台电脑、在线的设备），选好以后下面的专题、项目、模型都换成那台设备上的（从它那里取，取的时候有读条；离线就说离线）。
- 下面和本地完全一样：任务名、专题、项目、第一句话、模型（只列那台允许的）、强度、权限。
- 提交以后：那台设备上建任务、授权给这台、开会话发第一句话，这台的看板上出现远程任务卡（和现在第 4 步的结果一样）。
- **要你定**：那台电脑要不要先点同意？推荐**不用**，因为配对的都是自己的设备，而且命令照样要审批；每台设备可以在「远程设置」里关掉「允许它直接建任务」，关掉以后就走现在的「请求 → 同意」流程。
- 远程模式不能发图片和附件（和远程任务里发消息一样），附件按钮灰掉并说明。
- 新增远程命令：`rt.catalog`（项目、专题含倾向项目、允许的模型）和 `rt.create`（直接建）；`rt.request` 留着给关掉直接建的情况。

### 4.2 专题在项目上面，带倾向项目

- 顺序改成：任务名 → **专题** → **项目** → 第一句话。
- 专题的「倾向项目」就用已有的「专题的项目」（`Topic.workspaceIds` 加它的任务所在的项目），编辑专题时可以加减。选了专题后，项目这一行把它的倾向项目排最前、标「专题常用」，其他的跟在后面；只有一个倾向项目时自动选上（还能改）。
- 每一行最多显示 6 个：置顶的、最近用过的、（项目行）专题常用的；后面一个「更多…」按钮，打开搜索选择框：顶部输入框边打边筛，分组（置顶 / 最近 / 全部），上下键选、回车确定，和现在顶栏的搜索同一种样子。也可以在行里直接打字过滤（焦点在这一行时）。
- 「不选」一直在第一个（不选项目 = 公共文件夹，不选专题 = 不进专题）。

### 4.3 第一句话里的 @

- @ 不再用来选项目，# 不再用来选专题（专题和项目只在上面两行选）。
- @ 和对话输入框一样：项目、任务、任务下的会话（任务展开看到它的会话）、文件（选了项目以后才有项目里的文件和书签）。选中后正文里留「@名字」，发出去的第一句话里说明它指的是哪个（和对话里一样）。
- 引用的是上下文，不改任务的项目和专题。
- 快速启动条（Ctrl N）现在也用 @ 选项目、# 选专题：**要你定**。推荐一起改成和这里一样（启动条上加两个小下拉选专题和项目），免得同一个 @ 在两个地方意思不同。

## 5. 分几步做

1. 远程单独成页（顶栏按钮、页面排布、设置里删掉远程页）、配对弹窗 + 服务器的在线设备接口。

## 6. 托盘合并（用户 10-29 定）

用平台打开工具后托盘里有平台、Studio、便签、中转 4 个图标，太多。改成：

- **平台打开的工具不放自己的托盘图标**，只留平台一个。平台启动工具时加启动参数（`--amo-tray=platform`）；工具认到它就不建托盘。单独打开（没有这个参数）照旧有自己的托盘（约束第 1 条）。
- **平台的托盘菜单不折叠**（工具不多）：按工具分区直接列出全部操作，分区之间用分隔线和灰色小标题。比如：
  - AMO Studio：打开 Studio、重启 Studio（空闲时）、完全退出 Studio（有会话在跑先问，和 Studio 自己托盘的一样）；
  - AMO 便签：显示 / 隐藏便签、退出便签；
  - AMO 中转：打开中转（有未读时写「3 条未读」）、退出中转；
  - 只列已安装的工具；没在运行的只显示「打开」。
  - 最后是平台自己：打开平台、单击图标打开（便签 / Studio，单选）、退出平台。
- **单击平台托盘图标**打开什么可以选：便签或 Studio（这两个用得最多），默认便签，设置存平台的 `platform.json`。双击或菜单里「打开平台」才打开平台窗口。
- 平台图标的提示文字和小点：有会话在等你（Studio 的 `/api/health` 里的数）或中转有未读时带点。
- 工具这边：Studio、便签、中转认 `--amo-tray=platform`；便签和中转各加一个让平台关掉它们的方式（再次启动带 `--amo-quit`，单实例把参数转给已经在跑的那个，它自己退出）；Studio 退出用现有的 `POST /api/shutdown`。便签的「显示 / 隐藏」用再次启动带 `--amo-toggle`（单实例转过去）。
