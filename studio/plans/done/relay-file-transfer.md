## 第 1 项：会话右侧的文件边栏

现状：会话页顶上有一行「附件」小条（`relay-ui/src/SessionView.tsx` 的 `.atts`），列出会话里双方上传的文件，但只有文件名和版本，看不出谁什么时候发的，文件多了挤成一团。

做法（只改 relay-ui，热更新，不用重装外壳）：

- 会话页分成左右两栏：左边是原来的标题、提示条、消息和回复区；右边是「文件」边栏，替掉原来那行附件条。
- 边栏每个文件一行：文件名、谁发的（是我就写「我」）、什么时候、大小；同名有多版时 `v2 / 共 3 版`，有批注时批注数。最新的在上面。点开用现在的查看器；另有下载。
- 「＋ 附加文件」在边栏底部，文件也可以直接拖进边栏。会话结束后不能再加（和现在一样）。
- 边栏能收起（记在本机），收起后标题栏右边一个「文件 N」按钮展开；窗口窄于 960 px 时默认收起。
- 「复制给 AI」「在 Studio 里打开」从标题栏右边挪到左边，跟在状态那一行后面。
- 任务页里嵌着的会话（`Tasks.tsx`，`embedded`）同样有边栏。
- 聊天（私聊、话题）现在没有文件功能，这次不加。

## 第 2 项：传文件（2026-11-23 用户看过：「这样就行」）

用户的话：用户可以用这条通道在自己的不同设备之间、或者和别人的不同设备之间传文件。下面「还要确认的」两条按当时写的办（并排的新标签；发给自己的其他设备也要确认）。

### 用起来是什么样

- 顶栏「待处理」旁边加一个标签「传文件」，有等你确认的传送时标数字（用户说「在待处理那个选项卡里再加一个文件传输」，按并排的新标签理解，不对再改）。
- 面板分「收到的 / 发出的」，每条显示：谁、从哪台设备、发给哪些设备、文件或文件夹、大小、进度、状态，完成后「打开文件夹」。
- **发送**：选文件或文件夹（也能拖进来）→ 选人 → 选设备（列出对方登录过中转客户端的设备，在线的标出来；可以全选）→ 发出。发给自己的其他设备也一样选。
- **接收**：收到的先出现在「等你确认」，显示文件清单和大小；点「接收」（可以临时换个文件夹）或「拒绝」。接收后发送方才开始上传。
- 存到默认接收路径（`下载\AMO 中转`，面板里能改）。同名的文件或文件夹自动改成 `名字 (1)`、`名字 (2)`。
- 只能在桌面客户端里用（浏览器打开的中转没法写本机文件，标签里说明）。

### 设备

中转客户端现在不认设备，只认账号。要加：

- 客户端连上服务时报上本机的设备号和设备名。设备号就用本机共用的 `%APPDATA%\AMO\device.json`（`packages/account/src/device.ts`，平台、Studio、便签谁先用到谁创建），设备名默认电脑名。
- 服务记下每个账号「最近 N 天用过中转客户端的设备」和在线状态，发送时列给发送方选。
- 远程会话那套设备通道（`relay/src/devices.ts`，配对、转发帧）不动，传文件不要求配对：发给谁由账号决定，设备只是选在哪台收。

### 流程（经服务器）

1. 发送方建一个传送：只发清单（相对路径、大小），不带内容。服务检查总大小 ≤ 2 GB、磁盘够。
2. 目标设备在线就立刻收到；不在线的，在 1 天内打开客户端时收到。
3. 任何一台目标设备接收后，服务通知发送方开始上传（发送方的客户端要开着；关了的话下次打开接着传）。
4. 发送方分块上传（每块 8 MB，带偏移）；服务记录每个文件收到多少，断了从断点接着传。
5. 接收方一个文件传完就开始下载（HTTP Range，断了接着下），写到 `.part` 临时文件，下完校验 sha256 再改成正式名字。
6. 所有接收的设备都收完、拒绝，或者从建立起满 1 天，服务删掉这次传送的内容（只留一条记录给双方看「已过期」）。
7. 未完成的传送，两边客户端都记在本机（中转的家目录下），重开客户端在 1 天内接着传。

### 要改哪些

| 部分 | 改什么 | 怎么发 |
|---|---|---|
| 中转服务 `packages/relay` | 设备登记；传送表、清单、分块上传、Range 下载、状态推送（/ws）；1 天清理；2 GB 和磁盘检查 | `npm run release -- relay-service`，会重启中转几秒，部署前先问 |
| 中转外壳 `packages/relay-app` | 读 device.json；选文件/文件夹、按块读文件、按块写文件、改名、打开文件夹的接口；默认接收路径存在外壳自己的设置里 | 走平台发外壳新版本；界面检查外壳版本，旧外壳上「传文件」提示更新 |
| 中转界面 `packages/relay-ui` | 「传文件」标签和面板、选人选设备、确认对话框、进度、默认路径设置 | 热更新 |

### 做的时候自己定的（2026-11-23，方案没写到、按常理定的）

- **谁来搬字节**：外壳（`relay-app/src/transfer-files.ts`、`transfer-ipc.ts`）只做本机文件的事：选文件 / 文件夹、按块读、写 `.part`、校验、改名、打开文件夹；上传下载和续传的逻辑在界面里（`relay-ui/src/transfer.ts`），这样协议有问题时热更新就能修，不用等平台发外壳。外壳只读人选过的文件（记在中转家目录 `transfers/send-<id>.json`），只写进接收时选的文件夹。
- **外壳版本号不加**：`SHELL_VERSION` 一加，新界面会要求所有旧外壳更新；照以前的做法，`relayShell.transfer` 是可选接口，界面看有没有它。旧外壳上「传文件」标签里写「在 AMO 平台的「工具」里更新 AMO 中转」，浏览器里写只能在桌面客户端用。
- **设备**：客户端连 `/ws` 时带上 `device.json` 的设备号和设备名，服务记下来；发送时列出 30 天内用过新版桌面客户端的设备，连着的标在线。从没用新版客户端登录过的人在列表里灰着，发不了。
- **同名改名**：只看最上层的名字（选的文件和文件夹）。文件夹在接收时就占好「名字 (1)」；最上层的文件在存好时才定名字。`.part` 叫 `<名字>.<传送号后 6 位>.part`，两个传送收同名文件不会撞。
- **校验**：发送方上传一个文件前先算 sha256，服务收完整个文件后核对，对不上（发的时候文件被改了、或传坏了）从头再传，三次不行停下给原因；接收方下完也核对，对不上重下。选的时候和发的时候大小不一样，直接报错，让人取消重发。
- **数量和空间**：一次最多 10000 个文件（多了先打压缩包）、最多发到 50 台设备；服务器建传送时看磁盘，要留出所有进行中的传送还没传完的量再加 5 GB。空文件夹也传过去。
- **结束**：所有目标设备都收完或拒绝、发送方取消、或者满 1 天，服务删掉内容；记录再留 7 天给双方看。接收方「停止接收」= 拒绝，已存好的文件留着，`.part` 删掉。
- **提醒**：有等这台电脑确认的传送时，「传文件」标签和托盘 / 任务栏的数字都算上它；窗口不在前面时弹系统通知，点通知打开「传文件」。
