## 一句话

- 现在的「请求」升级成**会话**：会话多一个「现在等谁处理」，处理的人有三个动作：返回给发起人、接手任务、标记完成。
- 会话上面加一层**团队任务**，任务始终在某个人手里，靠流转往下推进。
- 每个人只需要看两样东西：**我手里的任务**、**待我处理的会话**。
- 文件（Markdown/HTML）和批注挂在任务或会话上，批注可以一键带进回复，AI 也能用 MCP 拿到。

## 场景：开发一把加特林

1. 策划新建团队任务「加特林」，写 designdoc，传到任务里。
2. 策划在任务页点「复制任务提示词」，贴给自己的 AI 做初审。提示词里有团队流程、任务 id 和 MCP 用法。
3. 初审通过后，AI 用 MCP 给程序发一个会话，附上 designdoc 和要确认的问题，比如「推进方式」三选一。
4. 程序在「待处理」里看到这个会话，可以批注 designdoc，然后三选一：
   - 回复并返回给策划；
   - 接手任务：弹窗里选新状态、写原因；
   - 标记完成。
5. 策划在「待处理」里看到返回的会话，点「复制给 AI」，或者让 AI 用 sessionId 自己取，然后继续推进。做完后把任务流转给程序终审。
6. 程序终审通过，把任务标成已完成。

## 概念

| 概念 | 是什么 | 和现在的关系 |
|---|---|---|
| 团队任务 | 标题、说明（Markdown）、创建人、**持有人**（在谁手里）、状态、文件、会话、记录 | 新增 |
| 会话 | 一个人（或他的 AI）发给另一个人、需要对方处理的一件事。可以挂在任务下，也可以不挂。带「现在等谁」 | 由原来的「请求」改名升级，逐条回答和结论都保留，旧数据自动迁移 |
| 聊天 | 普通聊天 + 话题，用来闲聊 | 不变 |
| 文件 | 任务或会话的附件，按版本保存，Markdown/HTML 能直接打开看 | 新增 |
| 批注 | 选中文件里的一段文字写意见 | 新增，复用 Studio 的定位方法 |

## 会话：现在等谁

| 状态 | 等谁 | 等的人能做什么 | 列表里 |
|---|---|---|---|
| 待处理 | 收到的人 | 回复并返回 / 接手任务… / 标记完成 | 收到的人：「待我处理」，高亮；发起人：「等对方」 |
| 已返回 | 发起人 | 继续追问（回到对方手里） / 标记完成 / 复制给 AI | 发起人：「待我处理」；对方：「等对方」 |
| 已完成 | — | 任何一方都能重新打开 | 两边都在默认折叠的「已完成」里 |

- 「回复并返回」：回复表单（逐条回答、补充说明、结论）照旧，只是发出去的同时把会话交还给发起人。只写一句批注就返回也可以。
- 「接手任务…」：只有挂在任务下的会话才有这个按钮。弹窗里写新持有人（默认是自己）、新状态、原因，可以勾选「同时结束这个会话」（默认勾上）。从会话里接手时，需要回复的会话会自动回一句「我接手了…」，不需要回复的直接结束。
- 「标记完成」谁能点，后来按「需要回复」改了，见下文「界面风格和回复规则」。
- 迁移：原来 open 的请求 → 待处理；answered 的 → 已返回（等发起人确认）。

## 任务：持有人、状态、流转

- 状态见文末「用户的决定」第 1 条（4 个，可归档）。
- 流转 = 换持有人 + 选新状态 + 写原因，在弹窗里完成。流转会写进任务记录；新持有人的「待处理」里会出现一条「任务交给你」，打开（并且窗口在前台）后才算看过；自己接手不算提醒。
- 谁都能流转，全部留记录（用户的决定第 2 条）。会话里的「接手任务」就是把任务流转给自己。
- **决策**：会话收到回复时，逐条回答和结论自动汇总到任务记录里的「决策」。AI 调一次 `relay_task_get`，就能拿到说明、持有人、状态、决策列表，以及每个会话的摘要和 id。
- **推进方式**（策划在主分支开发 / 策划拉独立分支、程序合并 / 程序接手）：不做成字段，放进「流程速查」，见用户的决定第 3 条。
- 团队设置（流程、流程速查的说法、AI 提醒时间）全队共用，改了会推给所有人。

## 文件和批注

- **上传**：在客户端里把文件拖进任务或会话；AI 用 MCP 的 `relay_file_put` 传本机文件（例如 `designdoc.md`）。同一个地方再传同名文件就是新版本，旧版本保留。文件存在服务数据目录的 `files/` 下，单个文件不超过 20 MB。
- **谁能看**：放在任务里全队可见，放在会话里只有会话的两个人可见。直接打开文件链接时带 `CSP: sandbox`。
- **展示**：
  - Markdown 用现在的渲染器；文本、图片直接显示。用户 10-27 说不需要 PDF 预览，常用的是 md、html 和图片。
  - HTML 放在沙箱 iframe 里，默认**不运行脚本**，这样才能安全地选中文字批注。需要看交互时可以切到「运行脚本」，这个模式下不能批注。
- **批注**：选中文字，写一条意见。定位方式是「引文 + 前后各 24 个字」，做法参考 Studio 的 `packages/ui/src/lib/selection.ts`；高亮用 CSS Highlight API，不改动文档本身。文件出新版本后，还能找到原文的批注自动跟到新版本上，找不到的列进「原文已改」。只能删自己的批注。
- **一键带走**：
  - 「复制批注」生成一段 Markdown：引文、意见、文件名和版本。（11-05 起写法和 Reviewer 一样，带行号，「复制给 AI」也带上附件上的批注，见 `plans/done/relay-round-2026-11-05.md` 第 1 节。）
  - 回复表单里有「附上我的批注」，直接把批注带进回复；附上时复制一份，以后删了批注也不影响这条回复。
  - `relay_session_get` 返回的内容里也带批注。
- 查看器后来从模态弹窗改成拖得动的面板，批注用 Reviewer 的小窗，见 `plans/done/relay-round-2026-11-05.md` 第 2 节。

## 界面规划

原来的界面是一栏列表加对话。加上任务之后东西变多，方案是：导航、列表、详情。

- **导航**：待处理（带数字）/ 任务 / 聊天 / 成员 / 设置（团队流程、状态列表）。实际照 Studio 做成了顶栏的视图（见「界面风格」）。
- **待处理**：一个按时间排的队列，里面有三类：收到的会话、返回给我的会话、流转给我的任务。每一项显示所属任务、来自谁、等了多久，处理完就从队列里消失。
- **任务列表**：用看板卡片（见「界面风格」），已完成和已搁置可以归档。
- **任务详情**：头部是标题、状态、持有人、创建人，以及「流转…」「复制任务提示词」；内容是概要 / 会话 / 文件 / 记录。
- **会话详情**：沿用请求页的样子，增加所属任务的链接、附件条，底部是动作。
- **文件查看**：右边是批注栏；从会话里点附件打开，关掉后回到会话。
- **聊天**：普通聊天加话题，不变。

## 风险

- **数据迁移**：现有请求要转成会话。处理办法：迁移前备份数据库，迁移逻辑写单测，并用当前线上库的一份副本实测。
- **HTML 里的脚本**：designdoc 里如果有脚本，可能伸手到客户端。处理办法：默认不运行脚本；运行脚本时 iframe 不给同源权限，拿不到登录 key。
- **一次改动太大**：处理办法：按 2a 到 2d 拆开做，每一步都能单独用起来。
- **团队流程写得太死**：处理办法：流程是一段可以编辑的说明，不写进代码；推进方式也作为一个问题来问，而不是固定字段。

## AI 接力：返回给 AI 的会话怎么自动走

- 会话记下发起方是人还是 AI（`via`），以及发起人这一侧现在由谁处理（`handler`：ai / person）。AI 发起的会话，默认 `handler = ai`。
- **回复返回时**：
  - 如果发起人的 AI 正在等（`relay_session_wait` 等这个会话，或者 `relay_queue` 等队列），它马上拿到回复，服务记下「AI 已取回」和时间；
  - AI 处理完后用 MCP 收尾：`relay_session_reply` 继续追问（会话回到对方手里），或者标记完成；也可以 `relay_session_handoff` 交给人，并附一句原因。
- **没等着的 AI**：AI 的新对话开始时，MCP 说明要求先调 `relay_queue`，看有没有返回给主人、并且由 AI 处理的会话，有就接着做。（10-28 下午改成 AI 不等回复、策划手动转回，见「卡点」。）
- **人能看到的状态**（发起人的「待处理」里）：回复已到，AI 还没取回；AI 已取回，正在处理；AI 取回后 30 分钟没有动作，可能卡住了（高亮，阈值在设置里改）。（原来还有「回复到了 10 分钟没取回才高亮」，10-28 下午去掉了，见「卡点」。）
- **人随时能接手**：
  - 「复制取回指令」：一行提示词，贴给任何 agent 就会去取；
  - 「复制给 AI」：复制整段回复和批注；
  - 「我来处理」：`handler` 变成 person，之后就是普通的继续追问 / 标记完成。AI 之后再对这个会话调 MCP 时，会被告知「已由某某接手」。
- 收到会话的人（例如程序）这一侧暂时只按人处理；让程序的 AI 也帮着处理，以后再说。

## 界面风格和回复规则（2026-10-27，用户看过第一版原型后定的）

- **整体照 AMO Studio 的设计语言做**，以后并进 Studio 时更容易适应：
  - 主题变量直接用 Studio 的 `packages/ui/src/styles/base.css`，浅色是「纸感编辑部」（象牙底、墨蓝强调），深色是 Studio 的深色。两套都支持，可以选「跟随系统 / 浅色 / 深色」。
  - 组件的做法照 Studio：顶栏（`.topbar` + `.view-tabs`）、左栏（`.scope-nav` / `.nav-label` / `.nav-row`）、**任务用看板卡片**（`.board` / `.column` / `.card`）、**会话用列表**（`.srow`）、弹窗（`.modal`）、按钮（`.btn-primary` / `.btn-ghost`）、标题用衬线字体。
  - 构建时直接引用 Studio 的 `base.css`，不复制一份，免得两边改着改着不一样。
- **批注在弹窗里做**：打开附件是一个大弹窗，左边是文档，右边是批注栏。选中文字后在批注栏里写；底部有「复制批注」「完成，回到会话」。回复表单里有「附上我的批注」和「打开批注」。（11-05 改成拖得动的面板，见 `plans/done/relay-round-2026-11-05.md`。）
- **需要回复的会话，收到的人不能标记完成**：
  - AI 发来的会话一律需要回复；人发起的会话可以选择要不要回复，默认需要。
  - 收到的人只有「回复并返回」和「接手任务…」两个选项。接手时会同时回复会话，告诉发起方自己已经接手，会话回到发起方手里。（11-05 又加了「已接手，不用回复」，见 `plans/done/relay-round-2026-11-05.md` 第 4 节。）
  - 只有发起方（人或者他的 AI）能标记完成。发起方还没等到回复时，可以「撤回并标记完成」。
  - 不需要回复的会话，收到的人才有「标记完成」。
- 「新请求」改名为「新会话」，可以勾选「需要回复」。

## 收紧（2026-10-28，用户和策划重新梳理需求后定的）

**现在最急需的只有一件事**：策划正常开发，AI 卡住了，或者方案该让程序把关时，由 AI 通过 relay 给程序发会话；程序收到提醒，根据 AI 给的内容单轮或多轮回复，把方案敲定，防止 AI 按默认方向跑偏；AI 取回后继续推进。人和人之间不发这种需要确认的会话，直接聊天。

- **界面上留下的**：顶栏只有 待处理 / 聊天 / 成员；待处理（待我处理 / 等对方或 AI 处理中 / 已完成）；会话页（逐条回答、结论、附件和批注、AI 状态条、我来处理、复制给 AI）；聊天和群聊；左下角的提示条、「复制用法」、我和设置。
- **藏起来（代码和数据都留着）**：「任务」视图和看板、「＋ 新任务」「＋ 新会话」、成员页的「发起会话」、会话里的「接手任务…」和任务链接、交给我的任务（不进待处理和提示条），左下的「团队流程」「流程速查」。设置里的「团队流程」页照旧，团队流程文字仍写进给 AI 的用法（用户选的）。
- **给 AI 的用法**（`usage.ts`）：`UsageContext.tasks` 默认关，用法文件、`amo-relay prompt`、MCP 说明里都不再提团队任务；开头写明「卡住了或方案该让别人把关时发会话，不要按自己默认的方向一路做下去；没问清楚就追问，来回几轮，敲定后标记完成再继续」；文档用 `put --thread` 传进会话。MCP 的任务工具还注册着，只是说明里不提。
- **开关**：`relay-ui/src/features.ts` 的 `fullUi()`，读 localStorage `amo-relay.full = "1"`，默认关。长的 e2e 打开它，照旧覆盖任务、文件、流转等功能；另有 e2e 用收紧后的界面跑。
- 服务端和数据库不动。

## 卡点：AI 不等回复，策划手动转回（2026-10-28 下午，用户定的）

用户：常规开发里，一轮对话本来就是在卡点处结束的，卡点里也常有要策划定的细节，所以 AI 不用 `relay wait`。曾讨论过让客户端定期往 AI 对话里推送（Claude Code 后台 wait 叫醒、`claude --resume -p` 接续），用户决定先不做，回复由策划手动复制。

- **给 AI 的用法**：开头改成「遇到卡点时」四步：① 照常写进文档，包括要策划定的细节；② 同时把要程序确认的部分发成会话，文档传进会话，只问程序该答的；③ 发完就结束这一轮，报告发给了谁、threadId，不等回复、不按没确认的方向继续；④ 策划贴回回复后，没问清楚就追问，敲定了就标记完成，再改文档、继续开发。用法里去掉 `wait` / `relay_session_wait`（命令和工具本身还在）。「复制用法」复制的那段话里写明：用法文件不存在（这台电脑没装中转）就照常只写文档——策划可以把它固定放进自己的开发提示词。
- **策划这边**：会话一返回就进「待我处理」，写「回复已到 · 复制给 AI 继续」，不再等 10 分钟才提醒；会话页的提示条主按钮是「复制给 AI」，复制的内容前面带一段「程序 X 回复了你发的会话（threadId …），没问清楚就追问，敲定了就标记完成再继续」和用法文件位置，原来的对话或新对话都能贴。AI 用命令行取回后变成「AI 已取回，正在处理」。设置里去掉「多少分钟没取回」那一项（「取回后多久算卡住」保留）。
- **程序这边**：回复后列表里写「已返回给 策划X」。
- 以后再说：自动把回复送回 AI 对话（Claude Code、Codex），AMO Studio 里的会话直接接回。（Studio 里的会话 10-30 做了，见 `plans/done/relay-in-sessions.md`；Claude Code、Codex 终端里的还没做。）
