## 调查结论

- 可以落地。建议在 AMO 平台里提供独立安装的「AMO 文件快传」，工具 id 暂定 `transfer`；平台负责安装、更新、登录，文件收发在独立窗口完成。
- 建议走「发送者上传到团队服务器 → 服务器暂存 → 指定收件人下载」；支持收件人离线，发送者上传成功后可以关机。
- 现有账号、成员资料、发布安装链和美术可以复用；现有中转附件不能直接充当大文件快传，需要独立的传输协议、权限与清理机制。

## 需要解决的问题

| 问题 | 代码或实测依据 | 建议处理 |
|---|---|---|
| 现有上传只适合小附件 | `protocol.ts` 的 `MAX_FILE_BYTES` 上限为 `20 * 1024 * 1024` 字节；`server.ts` 的 `readRaw` 整包缓存；（调查时还是同步写盘，11-04 `6280aeb4` 改成不阻塞服务的写法） | 新增分块或流式落盘、校验和限并发；不要只抬高旧上限。否则同进程的中转、远程通道可能受到内存和阻塞影响 |
| 现有权限与需求不同 | `store.ts:1048` 起：任务附件对团队可见，会话附件按会话成员授权 | 新建明确的发送者、收件人集合；查询、续传、下载和通知都逐项鉴权，多人发送共用一份内容、各有领取状态 |
| 没有快传所需的续传闭环 | 当前 `/api/files` 一次上传；下载路径直接返回 200，不处理 Range | 上传会话和偏移持久化，重复分块幂等，下载可恢复；重启客户端或服务器后从已确认位置继续 |
| 暂存不能无限增长 | 本轮检查的附件表和路由没有快传的配额、过期与半成品回收机制 | 独立存储目录放在 `app/` 外；设单文件、个人和总体配额，低磁盘空间时拒绝新建传输，定时清理过期与中断上传 |
| 「发出」「收到」不能混淆 | 现有文件元数据没有逐收件人保存成功回执 | 上传完整且校验通过后显示「已上传，待领取」；收件端文件写完、校验通过再确认「已下载」，查看列表只算已查看 |
| 关闭窗口后的提醒需要专门做 | 平台目前只读取中转的 `attention.json` 来切换未读图标；通用工具托盘项只提供打开 | 明确窗口关闭后保持后台收件；退出程序后下次启动补拉。新工具未安装或后台退出时，不宣称能即时桌面提醒 |
| 网口速率不等于快传速度 | 服务器当前为 1000baseT，多位收件人各自要从服务器下载 | 一份内容上传一次、多收件人共享；上传与下载分别限并发、背压，测传输时同时验证远程会话可用性；本轮不承诺具体 MB/s |
| 文件保存需要可靠收尾 | 旧上传拒绝空文件；新工具还会遇到重名、非法文件名、源文件变化和磁盘写满 | 支持零字节文件；收件端先写临时文件并校验，再完成保存；重名不静默覆盖，不自动运行收到的文件 |
| 账号变更与换人会影响归属 | `store.ts:319` 的 `renameMember` 显式更新各表；账号是按名称关联 | 新表纳入改名迁移；缓存、续传队列按服务器和账号隔离，登出或换号后停止原账号的任务和通知 |
| 服务器能接触暂存内容 | 当前团队服务使用 HTTP，现有服务端附件存储不是端到端加密 | 首版定位为可信团队局域网暂存；如果要求管理员也不能看或需用于不可信网络，应另定加密与 HTTPS 方案 |

不建议借用远程设备的 `rt.*` 通道传大文件：它面向设备配对和远程操作，`devices-protocol.ts:24` 的帧上限为 `1024 * 1024` 字节。新工具应按人投递，收件人离线时由服务器保留内容。

## 建议的产品行为

- 平台「工具」新增卡片：AMO 文件快传；提供安装、打开、更新、卸载。程序可独立启动，联网功能读取平台登录。
- 主窗口左侧为「收件箱」「已发送」「传输中」「设置」；发送区拖入文件或点「选择文件」，搜索并多选人员，可附一句说明。
- 上传成功才生成可领取的投递；收件人不在线也能稍后领取，不要求 Studio、中转聊天或发送者电脑一直开着。
- 收件箱显示发送人、文件名、大小、时间、过期时间；保存位置可修改。已发送页显示每个人的领取状态。
- 传输中显示阶段、已传字节、总量、速度、失败原因和重试/取消；多人下载状态分别记录。
- 同一账号多台电脑共享收件记录，但「已下载」不意味着每台电脑都有本地文件，其他设备在有效期内仍可下载。
- 发送者撤回后禁止新的下载；已经保存到收件人电脑的副本无法收回。过期清理只影响服务器暂存，不删除已保存的本地文件。

## 美术约束

- 产品界面使用 AMO 原有 `base.css`，不能以本报告的 Claude 阅读版配色代替产品配色。
- 浅色沿用纸色底与墨蓝强调；深色沿用现有灰黑底与浅蓝强调；字体沿用 Noto Sans SC、Noto Serif SC、JetBrains Mono。
- 复用 AMO 的间距、字号、2/3/4 px 圆角与按钮尺寸；图标沿用现有图标方式，工具图标按 AMO 家族风格扩展。
- 浅色、深色、跟随系统都验收；对长文件名、多个收件人、错误状态、小窗口和大字体做截图检查。

## 实现阶段与验收

- 阶段一：独立工具壳、平台发布入口、账号和双主题；隔离数据目录，不影响现有工具。
- 阶段二：服务端投递表、收件权限、分块上传与下载、完整性校验、取消和幂等；临时存储与发布目录分开。
- 阶段三：断线和进程重启恢复、过期清理、配额、后台提醒、多设备状态和账号改名迁移。
- 验收：不同账号之间发单文件、多文件和多人投递；无关账号不能枚举、获取内容或订阅通知；离线后重新上线可领取。
- 验收：上传和下载中断、服务器重启、重复请求、磁盘写满、撤回/过期与下载并发、源文件变化、零字节文件和重名保存。
- 验收：实际大文件与多人并发，同时观察中转和远程会话；验收截图覆盖浅深主题、小窗口和大字体。
- 发布：本机验证后，服务端升级会重启 Relay 并短暂影响现有连接；届时单独安排部署窗口。各人的客户端通过平台自行选择更新。

产品范围和默认策略由用户决定；进入实现前据此收敛规格。
