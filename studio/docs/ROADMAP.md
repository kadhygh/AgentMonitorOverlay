# AMO Studio 路线图

这份文件只写每个阶段的目标、验收标准和关卡。详细任务在进入该阶段时，写到 `plans/stage-N.md`。后面阶段的内容可以根据前面阶段的实际结果调整；调整时，在本文件末尾的"变更记录"里写明原因。

## 关卡类型

| 类型 | 含义 |
|---|---|
| 自动 | 测试、类型检查、构建、端到端测试全部通过即可继续 |
| 请你过目 | 写入 `NEEDS_YOU.md` 后继续推进，不等待回复；用户的反馈会变成返工任务 |
| 必须等你 | 停止推进相关工作，等用户在 `NEEDS_YOU.md` 中回复。不受影响的任务可以继续 |

## 阶段 0 ✅ 方向与验证

- 协议验证：Codex app-server 共享、TUI `--remote` 接入、Claude Agent SDK 交接、DeepSeek/GLM 路由
- 设计预览：工作台、新建任务、会话、批注、画布、Focus
- 输出：`docs/protocol-session-spike-2026-10-12.md`、`docs/next-gen-vision-architecture-2026-10.md`、`design/`

## 阶段 1 · 地基：Host + Codex 会话 + 最小工作台

目标：在 Studio 里日常使用 Codex（包括 DeepSeek 路由）推进任务，需要时一键用原版终端接入同一会话。

范围：
- 补测剩余协议问题
- 工程脚手架
- 数据模型与存储：工作区、任务（工作区或跨工作区）、会话树、事件、批注、画布、待办。后几项先定义结构，界面以后再做
- Codex runtime：自持 app-server、模型路由、凭据、事件写入、记录父子关系
- Host API（HTTP + WS）
- Electron 外壳 + React 界面：
  - 看板
  - 新建任务页
  - 任务页（会话列表、会话树、归档）
  - 对话面板（流式输出、工具卡片、审批、插话、打断）
  - 在终端打开
- 测试基础：mock 模型和 fake app-server、Playwright 端到端测试

验收：
1. 端到端测试覆盖以下流程，全部通过：
   - 新建任务 → 会话 → 流式回复
   - 审批
   - 插话与打断
   - fork 和子 agent 的父子关系展示
   - 归档与恢复
   - 生成终端接入命令
2. 真实 DeepSeek 冒烟测试通过：沙盒工作区里完成两轮对话，`--remote` 终端可以连上
3. Host 重启后，会话列表与历史能恢复

关卡：
- 自动：每个任务、阶段验收
- 请你过目：界面截图、"用一天"的试用
- 必须等你：无

## 阶段 2 · 审阅

目标：不打开 Obsidian，也能完成现有的审阅闭环。

范围：
- 回复以 markdown 渲染（代码块、列表、表格）
- 选中文字后右键（添加批注、引用到输入框、复制）
- 批注栏、汇总发回、高亮被批注的原文
- 草稿区
- 快速跳转：同一会话内回复之间跳转、按批注定位

验收：端到端测试覆盖"选中 → 右键批注 → 汇总发回 → 会话收到"。

关卡：
- 自动
- 请你过目：审阅体验

## 阶段 3 · 组织层与日常切换

目标：Studio 可以替代旧 AMO 成为日常工具。

范围：
- 无限画布：平移和缩放；自由分组（新建、移动、调整大小、绑定工作区）；依赖；便签
- 画布内容按结构化数据存储，可以直接导出为大纲和 JSON
- 跨工作区任务的完整界面
- Focus 悬浮窗：透明、点击穿透、只显示需要处理的事项、就地批准
- Electron 透明窗口在 Windows 多显示器和多 DPI 下的验证

验收：端到端测试覆盖画布操作与结构导出；Focus 悬浮窗在 Windows 上实测通过。

关卡：
- 自动
- 请你过目：画布与 Focus 观感
- **必须等你**：是否把 Studio 切换为日常工具，以及何时删除旧 AMO 代码

## 阶段 4 · Claude 与只读 MCP

目标：Claude（包括 GLM 路由）会话进入同一棵会话树；agent 可以读取工作台。

范围：
- Claude Agent SDK runtime：resume、fork、子 agent 嵌套事件
- 交接到 `claude --resume` 时工作台只读，终端退出后收回；补测 `claude --bg` 和 `attach` 能否作为共享方式
- AMO MCP（只读）：看板、任务、会话树摘要、项目上下文、`canvas.read`
- 受管会话启动时自动注入 MCP

验收：端到端测试覆盖 Claude 会话、交接只读、MCP 读取。

关卡：
- 自动
- 请你过目

## 阶段 5 · 可写 MCP 与协作

目标：会话之间通过 AMO 交接信息，节奏由人掌控。

范围：
- MCP 写入：更新自己所属任务的进度和备注、提交交接摘要
- 信箱：给其他会话或任务留言，回合结束时提示
- 请求决策：在 Focus 和工作台中显示
- 画布写入接口：建组、连线、移动

验收：两个会话通过信箱完成一次交接的端到端测试。

关卡：
- 自动
- 请你过目
- **必须等你**：派发类能力（新建会话、向其他会话投递任务）是否开放、如何限权

## 阶段 6 · 项目扩展接口

目标：针对具体 project 接入专门的规范、流程和工具。

范围：
- `.amo/packs/<name>/` manifest
- 规范引用、流程模板、启动预设
- 扩展包提供的 MCP 工具（接口层）

验收：一个示例扩展包（非真实项目内容）走通加载、展示、启动预设。

关卡：
- 自动
- **必须等你**：第一个真实扩展包的内容

## 阶段 7 · 整体待办与调度 agent

目标：调度 agent 定期查看绑定了工作区的分组是否空闲，认领待办并开出会话，开工前交给人批准。

范围：
- 整体待办
- 工程空闲判定
- 调度 agent（DSH 或 SDK 运行）
- 批准流程

关卡：**必须等你**。开工前确认调度权限与频率。

## 阶段 8 · 发布与收尾

范围：
- Portable 打包（不再维护安装包）
- 首次启动时未关联数据目录则进入设置
- 删除旧 AMO 代码（已在阶段 3 获得同意的前提下）
- 文档

关卡：**必须等你**。合并到 master 由用户确认。
